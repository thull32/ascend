A large share of new code is now drafted by a model. That does not make the senior engineer less important; it moves the work. Typing gets cheap, so the scarce skills become the ones around the typing: deciding what should be built, writing a specification precise enough that an agent cannot misread it, giving the agent the right context and no secrets, and verifying a 400-line diff you did not write as rigorously as one you did. Companies hiring at the senior bar are starting to test exactly this, sometimes in interview rounds where an AI assistant is allowed and your use of it is graded.

This track is practical and tool-agnostic. The first module covers the tool landscape by category (inline completion, interactive agents, cloud agents), the plan → implement → verify loop, specs and memory files such as `CLAUDE.md` and `AGENTS.md`, context management, MCP integrations and their permission models, verification, and security policy. The second module covers how senior engineers use AI in design reviews, debugging and incidents, how to keep learning instead of atrophying, what an AI-native interview looks for (including this app's assisted mock interview), and which skills you should keep doing by hand.

It builds on [How LLMs work](/learn/ai-and-llms/how-llms-work/capabilities-and-failure-modes) and [Agents](/learn/ai-and-llms/building-with-llms/agents), which explain the model and the loop from the inside. This curriculum itself was written by parallel AI agents working from a written brief, a content contract and a validator; the lessons use those files as real examples of what worked and what broke.
