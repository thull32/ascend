The graph module in the data-structures track taught you to represent a graph and walk it with BFS and DFS. That is enough to answer "is there a path". It is not enough to answer the questions production systems actually ask: what is the *cheapest* path, which links can we cut without disconnecting anything, which parts of a dependency graph are tangled into cycles, and how do we route across a map with a hundred million nodes in a few milliseconds. Those questions have classical answers that are between fifty and seventy years old and still run every packet on the internet, every build system, every map app and every compiler's optimiser.

This module walks those algorithms in the order a senior engineer needs them. Dijkstra first, because it is the algorithm you will be asked to implement from memory and the one most people implement subtly wrong. Bellman-Ford and Floyd-Warshall next, because they answer the question Dijkstra cannot (negative edges, all pairs) and because you have to be able to explain *why* they are slower rather than just that they are. Minimum spanning trees and union-find come as a pair: Kruskal is a sort plus union-find, and union-find on its own is one of the highest value-per-line data structures in the interview canon. Tarjan's strongly connected components and the bridge-finding algorithm share one idea, the low-link value, and are how you turn a messy directed graph into a DAG you can reason about. A* closes the module as the algorithm that makes Dijkstra practical on real maps, and as a case study in what an admissible heuristic buys and costs.

Every lesson has a steppable visualisation of the algorithm on a small graph, a from-scratch implementation you write in Python or JavaScript against real tests, and a discussion of the follow-up an interviewer asks after the code compiles: what breaks with negative weights, why union by rank matters, what a condensation DAG is for, and when a heuristic is a liability. By the end you should be able to pick the right algorithm from the shape of the problem in under a minute and defend the choice.
