Mid-level engineers make code work. Senior engineers make code that keeps working when requirements shift, traffic grows, dependencies fail, attackers probe it and the original author has left. That difference is not one big idea; it is dozens of small, deliberate decisions about where boundaries go, what an error means, what a test proves, what a deploy risks, what a log line lets you answer, and who may do what.

This module walks through those decisions in the order a request meets them: the architecture and the middleware stack, the API contract and its errors, the tests that pin behaviour down, the security controls around sessions and cookies, the pipeline and deploy strategy that ship the code, the container and infrastructure definitions it runs in, the telemetry that tells you it is healthy, and the documents that explain why it is built this way. The last lesson widens the lens from this app's single login to identity across systems: OAuth 2 and PKCE traced request by request, OIDC, sessions versus JWTs with measured costs, refresh-token rotation, RBAC to relationship-based access, SAML and key rotation.

Every lesson cites real files in this repository (`crates/core`, `crates/api`, `migration`, `web`, the CI workflow, the Dockerfile, the infrastructure definition and the decision records in `docs/`) so you can open the code beside the prose, and its numbers come from measurements that say what was measured: the repository's own CI runs timed job by job and layer by layer, the cost of each test level, JWT and password-hash costs, pagination at depth. Where the codebase takes a shortcut or has a gap, the lesson says so and explains what a senior reviewer would ask for; a session lifetime with no idle timeout is one that remains open. Many review findings have since been fixed (an exact-match CSRF origin check, a request-ID filter, a 503 for handler timeouts, a race-free AI budget, integration tests that cannot pass silently in CI, a 400 for malformed JSON, a `Retry-After` computed from the limiter, a bounded password-hashing pool, cache validators that change with every build). Reviewing these lessons against the code found more, fixed in one commit: a rollback that could not boot against a newer schema, boot migrations that replicas could race, a platform drain window that defaulted to zero seconds, stale browser tabs served HTML as JavaScript, CI actions and base images referenced by movable tags with no dependency audit, migration progress hidden by a log filter, and a database password that a connect error could print. The lessons show each one as a before and after: what the code did, how the problem was found, what it does now and why that fix. Exercises turn the rules into small, testable functions: an architecture fitness check, an error-to-status mapper, a flaky-test detector, a CSRF gate, an error-budget gate and a canary promotion gate, a layer-cache simulator and a rolling-update simulator, a log parser and a `traceparent` propagator, an ADR query and a migration boot planner, a refresh-token rotation state machine and a relationship-based permission check.
