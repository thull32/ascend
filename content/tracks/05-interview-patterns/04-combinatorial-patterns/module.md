The problems in this module are the ones candidates fear: "generate all", "minimum number of", "is it possible to", "design a class that supports these operations in O(1)". They are also the ones where the pattern, once named, does the most work. A backtracking problem is a choose-explore-unchoose loop with a pruning rule. A DP problem is a state definition and a recurrence, and the six shapes of state cover nearly every interview question. A greedy problem is a one-line local rule plus a one-paragraph argument for why it is safe. Bit manipulation and math problems have a small bag of tricks each. Design problems compose two data structures you already know.

Each lesson opens with the signal that selects the pattern and a table of near misses: the statements that look like the pattern and are not, such as the "minimum" that is really Dijkstra or a greedy BFS, and the greedy rules that fail, each with the three-item input that breaks it. The template follows in Python and JavaScript with the non-obvious lines annotated, then the argument for why it is correct, then three to six problems traced state by state: the recursion tree with its pruned branches counted, the DP table filled cell by cell, the greedy choice sequence with the exchange carried out, the bits of every step, and the internal structures of an LRU, an LFU or a news feed after every operation.

The second half of each lesson is what decides the round once the code works. Under the hood covers what the runtime does, measured on CPython 3.14 and Node 24: recursion limits and memo costs, JavaScript's 32-bit bitwise operators and its 2⁵³ ceiling, the 4,300-digit `int` conversion limit, `OrderedDict`, `random.choice` and why the GIL does not make a method atomic. Failure modes are written as symptom, diagnosis and fix, and the interviewer follow-ups are the ones that change the pattern: "now return every solution", "now `n` is 10⁵", "now make it thread-safe".

The order is deliberate. Backtracking comes first because DP is what you reach for when backtracking's subproblems repeat. Greedy follows DP because the way to justify greed is to show that the DP collapses. Bit manipulation and math are specific toolkits whose traps are the number models of the two languages. Design closes the module because it draws on everything before it and is the round most often used to separate senior from mid-level: not "can you code it" but "can you name the trade-off and choose".
