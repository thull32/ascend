Knowing thirty patterns does not pass a coding interview on its own. Candidates who could solve the problem at home fail the round because they spend fourteen minutes on the approach, start testing at minute 43, freeze when the first idea does not work, or write correct code in silence and get rated "solid mid-level". Each of those is a failure of execution, not knowledge, and execution can be practised in the same deliberate way as a pattern.

This module is the playbook for the 45 minutes themselves. It starts with the clock: a time budget for each phase, checkpoints that tell you when to change course, and the sentences that move you from one phase to the next. It then goes phase by phase through the parts that decide most rounds: the clarifying questions whose answers pick the algorithm, testing your own code live so that you find the bug before the interviewer does, and getting unstuck without losing the room. It closes with the specific behaviours that separate a senior rating from a mid-level one when two candidates write the same code.

The module builds on the [problem-solving loop](/learn/foundations/problem-solving/the-problem-solving-loop) and [communicating while solving](/learn/foundations/problem-solving/communicating-while-solving) from the Foundations track. Those lessons give you the order of the steps and how to narrate them. This one adds the clock, the interviewer's scorecard, and the recovery moves. Every lesson includes scripts you can say word for word and weak-versus-strong examples of the same moment. Practise them in Ascend's mock interviews at `/interviews`, which run a timed 45-minute coding round and grade the transcript on the same dimensions a real interviewer uses.
