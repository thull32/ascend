## 1

acme-web1, at 10.1.1.10, sends a packet to acme-db1, at 10.1.2.20, through leaf1, spine1 and leaf3, treated as plain routers. On the link from leaf1 to spine1, what are the packet's destination MAC and destination IP?

A, spine1's interface MAC, and acme-db1's IP, 10.1.2.20. B, acme-db1's MAC, and acme-db1's IP. C, the anycast gateway MAC, and acme-db1's IP. D, spine1's interface MAC, and spine1's own IP, 10.254.1.0.

[think]

The answer is A: spine1's interface MAC, and acme-db1's IP.

The destination IP is the end-to-end label and never changes. The destination MAC is the per-link label: leaf1 looked up the next hop, took spine1's MAC from its neighbour table and addressed the frame to it. The next hop's IP is used only to find that MAC and never appears in the packet. The anycast gateway MAC is used only between a host and its leaf, and acme-db1's MAC only on the last link.

## 2

A traceroute shows 95 milliseconds at hop 4, then 12 milliseconds at hops 5 through 8 and at the destination. What is the most likely explanation?

A, hop 4 is a tunnel endpoint adding 83 milliseconds of encapsulation. B, hop 4's CPU answers TTL-expired probes slowly. C, hop 4 is congested and delays all traffic through it. D, the return path from hop 4 is a long-haul circuit.

[think]

The answer is B: hop 4's CPU answers TTL-expired probes slowly.

Packets through hop 4 reach the destination in 12 milliseconds, so the forwarding path through it is not slow. The reply at hop 4 is generated by the router's control plane under a rate limit, and a busy CPU answers late. Congestion at hop 4 would add delay to every later hop as well; only latency that persists to the destination is real.

## 3

Leaf1 counts rising CRC errors on its port towards spine2. Where is the fault most likely to be?

A, in spine2's routing table, which mis-forwards frames. B, in the sending host's network card, whose frames carry a bad CRC. C, on any link along the paths that cross spine2. D, on the link between leaf1 and spine2: its optics or cable.

[think]

The answer is D: on the link between leaf1 and spine2, its optics or cable.

Each router builds a new frame and recomputes the frame check sequence on every hop, so a CRC error describes corruption on the one link where the frame was received. A host's bad frame would be dropped at the first hop, and a routing error does not corrupt bits. The one caveat is cut-through switching, where a stomped CRC can be counted on the next link too, which good tooling separates out.

## 4

In the laptop-to-website walk, which statement about BGP is correct?

A, BGP is consulted at every hop to append to the AS path. B, BGP chose best paths in advance, and packets meet only the forwarding table. C, BGP runs only on the home router, which picks the ISP. D, each router queries BGP to choose a next hop for the packet.

[think]

The answer is B: BGP chose best paths in advance, and packets meet only the forwarding table.

BGP is a control-plane protocol between routers. It ran long before this packet, picked a best path per prefix and installed it in each router's forwarding table; per packet, routers do a longest-prefix match in that table. A home router has a default route and no BGP. The AS path grows in route announcements, never in packets.

## 5

A laptop joins a network and shows the address 169.254.37.12. Which step of the walk failed?

A, NAT, because the router's table was exhausted. B, DHCP, because no server answered the discover message. C, Wi-Fi association, because the passphrase was wrong. D, DNS, because the resolver was unreachable.

[think]

The answer is B: DHCP, because no server answered.

Addresses starting 169.254 are the link-local range a host assigns itself when DHCP gets no answer. A wrong passphrase fails the four-way handshake before any IP traffic exists, and DNS and NAT failures happen after the host already has a valid address.

## 6

Classic Unix traceroute, across a leaf-spine fabric with four spines, prints different addresses on the same hop line. Why?

A, the TTL is decremented by a different amount on each spine. B, a new port on every probe makes ECMP hash them onto different spines. C, the ICMP replies are load-balanced back over different return paths. D, the spines answer from random interface addresses to hide their identity.

[think]

The answer is B: a new port on every probe makes ECMP hash them onto different spines.

Classic traceroute raises the UDP destination port with every probe, so each probe is a different five-tuple and the ECMP hash can send it to a different spine. Paris traceroute keeps the five-tuple fixed to follow one path, and in a fabric you can use the same effect on purpose, varying five-tuples to cover every spine. The return path does not change which router expired the probe.
