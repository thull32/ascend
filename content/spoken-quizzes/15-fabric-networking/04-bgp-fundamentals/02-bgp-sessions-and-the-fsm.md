## 1

A BGP session on a leaf has shown Active for twenty minutes. What does that tell you?

A, the session is exchanging routes and the table is still loading. B, TCP to port 179 is not completing, so the router keeps retrying. C, OPENs were exchanged and the router is waiting for a KEEPALIVE. D, an operator shut the session down and it is waiting to be enabled.

[think]

The answer is B: TCP to port 179 is not completing, so the router keeps retrying.

Active means there is no TCP connection: the attempt failed, and the router listens and retries when the ConnectRetry timer fires. Waiting for a KEEPALIVE after the OPENs is OpenConfirm, a deliberate shutdown is Idle, marked admin, and a loading table is Established. The cause is below BGP: reachability, source address, filters, keys or TTL.

## 2

leaf1.ams proposes a hold time of 9 seconds and rr1.ams proposes 90 seconds. What does the session use?

A, 90 seconds, because the larger proposal protects against false expiry. B, neither: differing proposals are refused with NOTIFICATION code 2, subcode 6. C, 9 seconds on both ends, with keepalives about every 3 seconds. D, 9 seconds on the leaf and 90 seconds on the reflector, each its own value.

[think]

The answer is C: 9 seconds on both ends, with keepalives about every 3 seconds.

Both sides use the minimum of the two proposals, and each sends keepalives at about a third of it. Hold time belongs to the session, so the reflector's other sessions keep their own values. Code 2, subcode 6 is for unacceptable values, such as 1 or 2 seconds, or one below a configured minimum, not for a difference.

## 3

Why does BGP need a hold timer when it already runs over TCP, which retransmits lost data?

A, TCP has no way of retransmitting data on long-lived sessions. B, hold timers are needed to rate-limit how fast UPDATEs are sent. C, TCP keepalives would add too much traffic on fabric links. D, the kernel acknowledges segments even when the BGP process has hung.

[think]

The answer is D: the kernel acknowledges segments even when the BGP process has hung.

TCP acknowledgements are generated by the kernel, so a router whose BGP daemon is wedged still looks alive to TCP, and Linux's own keepalive would not probe for two hours anyway. Only the absence of BGP messages shows the process is dead. TCP retransmits fine; the timer is about liveness, not loss, and has nothing to do with pacing UPDATEs.

## 4

A session to an ISP comes up, receives a few hundred prefixes, and is reset with "hold time expired" every three minutes. The negotiated hold time is 180 seconds. What is the most likely cause?

A, an MTU mismatch that drops only full-size segments. B, a duplicate BGP identifier between the two routers. C, a TCP MD5 key mismatch between the two routers. D, a wrong peer AS number configured on one side.

[think]

The answer is A: an MTU mismatch that drops only full-size segments.

Small packets, the handshake, the OPENs and the KEEPALIVEs, pass, so the session reaches Established. The full-table UPDATEs fill maximum-size segments that a lower-MTU hop drops silently, TCP keeps retransmitting them, keepalives queue behind them, and the hold timer expires one hold time later. A key mismatch would stop TCP entirely. A wrong AS or a duplicate identifier would refuse the OPEN, so the session would never be Established.

## 5

A leaf's session to its reflector is Established and has received End-of-RIB, but the leaf has no EVPN routes from it, while IPv4 routes arrive normally. What should you check first?

A, the negotiated address families, since EVPN may be enabled on one end only. B, the hold time, because a short timer drops EVPN routes first. C, the TCP maximum segment size, because EVPN routes need larger segments to fit. D, the router IDs, because EVPN requires them to match across the pair.

[think]

The answer is A: the negotiated address families, since EVPN may be enabled on one end only.

Address families are capabilities: the session carries only those both OPENs announced, and a family missing on one side does not stop the session from coming up. Hold time and segment size affect the whole session, not one family. Router IDs must differ, not match. Compare the negotiated families with what the source of truth intends.

## 6

leaf1.ams logs that its session to rr1.ams went down with "NOTIFICATION sent, code 4, subcode 0, hold timer expired". What does that tell you?

A, leaf1.ams heard nothing from rr1.ams for a full hold time. B, an operator on leaf1.ams reset the session by hand. C, leaf1.ams refused rr1.ams's OPEN for its hold time value. D, rr1.ams heard nothing from leaf1.ams for a full hold time.

[think]

The answer is A: leaf1.ams heard nothing from rr1.ams for a full hold time.

The side whose hold timer runs out sends code 4, so leaf1.ams received no KEEPALIVE or UPDATE for the negotiated hold time: look at rr1.ams's BGP process, the path between them, or something delaying rr1.ams's sends. Had rr1.ams's timer expired, leaf1.ams would log the NOTIFICATION as received. A manual reset is Cease, code 6, subcode 4, and a refused hold time is code 2, subcode 6, which can only happen before Established.
