## 1

A social graph has 500 million users, with an average of 200 friends each. Storing it as an adjacency matrix of bits would need about how much space?

A, about 30 petabytes. B, about 12.5 gigabytes. C, about 30 terabytes. D, about 400 gigabytes.

[think]

The answer is A: about 30 petabytes.

The matrix needs V squared bits: 2.5 times 10 to the 17 bits, or about 3 times 10 to the 16 bytes, roughly 30 petabytes. Its size depends only on the number of vertices, not on the 200 friends. 400 gigabytes is the adjacency list: 100 billion directed entries at 4 bytes each. Sparse graphs make the matrix absurd.

## 2

Your breadth-first search from vertex 3, in an undirected graph, never reaches vertex 0, although the input contains an edge between 0 and 3. What is the most likely bug?

A, the queue was really a stack, so the search ran depth-first instead. B, vertex 0 has degree zero, so the search has no edge by which to reach it. C, each edge was added to only one endpoint's adjacency list. D, breadth-first search treats edges as one-way, so it cannot cross undirected edges.

[think]

The answer is C: each edge was added to only one endpoint's adjacency list.

Appending 3 to vertex 0's list makes the edge usable from 0, but not from 3. Undirected edges must go into both endpoints' lists; the search simply follows whatever lists it is given. A stack instead of a queue would change the visiting order, not which vertices are reachable.

## 4

In CPython, an adjacency list of 10 million directed edges over a million vertices, built as a list of lists, takes about 450 megabytes, while a compressed sparse row layout with 32-bit integers takes 44. Where do most of the extra bytes go?

A, the outer list stores a 64-byte header for every vertex. B, each list is over-allocated to twice its length on every append. C, each neighbour is a pointer to a separate 28-byte integer object. D, Python stores every integer as 8 bytes, instead of the 4 in the compact layout.

[think]

The answer is C: each neighbour is a pointer to a separate 28-byte integer object.

A list slot is an 8-byte pointer, and integers above 256 are heap objects of 28 bytes each, so a neighbour costs about 36 bytes before growth slack. The header of each vertex's list is 56 bytes, but spread over ten edges it is only about 6 bytes per edge. And over-allocation is about 12.5 percent plus a small constant, not double.

## 5

In JavaScript, you track visited grid cells with a Set of row and column arrays, and the breadth-first search never terminates. Why?

A, arrays compare by reference, so a newly built row and column array never matches a stored one. B, arrays are hashed by their first element only, so whole rows collide. C, sets silently drop array values, so every add leaves the set empty. D, the search needs a map from cell to distance; a set cannot record visits.

[think]

The answer is A: arrays compare by reference, so a newly built row and column array never matches a stored one.

Two arrays with the same contents are different objects, so asking the set whether it holds a freshly built array is always false, even though it holds a lookalike. Use a string key made of the row, a comma and the column; a numeric key, the row times the column count plus the column; or a two-dimensional boolean array.

## 6

A puzzle has about a trillion possible states, but the solution is 20 moves from the start, and each state has 4 moves. Which representation should you use?

A, an adjacency matrix over all the states, giving constant-time move checks. B, an implicit graph, with neighbours generated by applying moves on demand. C, an adjacency list of every state, built once up front before searching. D, an edge list of all legal moves, sorted and scanned at each step.

[think]

The answer is B: an implicit graph, with neighbours generated by applying moves on demand.

Only states within 20 moves are ever touched, at most 4 to the 20 in the worst case, and far fewer with a visited set of the states actually reached. Building the full adjacency list is impossible at a trillion states, and a matrix is far worse. The neighbour function is the graph.
