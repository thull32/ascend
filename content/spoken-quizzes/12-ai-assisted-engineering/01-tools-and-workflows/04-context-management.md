## 1

Two hours into a session, the agent re-reads files it already read, and contradicts a design decision from the start of the session. What is the most effective response?

A, have it write a handoff note, then start a fresh session from that note. B, switch to a model with a larger context window, and carry on in this session. C, paste the full transcript into a new session, so nothing is lost. D, restate the original decision more forcefully in the same session.

[think]

The answer is A: have it write a handoff note, then start a fresh session from that note.

Those are symptoms of context rot: dilution, stale file contents, and failed attempts in the window. A handoff note, covering state, dead ends, constraints and next steps, keeps the useful state and drops the noise. A bigger window delays the problem without removing the noise, and pasting the transcript recreates it.

## 2

An eight-iteration agent session ends with a transcript of about 44,000 tokens. Roughly how many input tokens did the model process over the whole session, and why?

A, about 200,000, because the growing transcript is resent on every iteration. B, about 44,000, because the transcript is only sent once, at the end. C, about 88,000, because each iteration sends the transcript and its own output. D, about 8,000, because caching means only new tokens are ever processed.

[think]

The answer is A: about 200,000, because the growing transcript is resent on every iteration.

Every call resends everything so far, so the total is the sum of the transcript sizes over the iterations, which grows roughly with the square of the iteration count. In the traced example, it was 199,900 for a final transcript of 44,300. Caching changes what is billed and how fast prefill runs, not how many tokens the model attends over.

## 3

At the time of writing, which action leaves the prompt cache intact in a Claude Code session?

A, adding an MCP server whose tools load eagerly. B, editing source files in the repository. C, switching to a different model with the model command. D, compacting the conversation with the compact command.

[think]

The answer is B: editing source files in the repository.

The cache keys on a byte-identical prefix of the request. Editing files changes nothing in the prompt until a tool reads them, which appends to the tail. A model switch uses a different cache, compaction rewrites the conversation, and an eagerly loaded server changes the tool definitions near the front of the prompt, so everything after them misses.

## 4

You need to find where the codebase handles expired sessions, but you do not know any function or file names. Which context mechanism is most likely to help first?

A, agentic grep for the word session, then read every file it matches. B, a semantic index query, then reading the files it returns to confirm. C, pasting the whole repository into the context, so nothing is missed. D, asking the model, since it has seen similar session code in training.

[think]

The answer is B: a semantic index query, then reading the files it returns to confirm.

Semantic, embedding-based retrieval finds concepts without exact identifiers. It can be stale, and it can mis-rank, so you confirm by reading the returned files. Grepping for session in a large codebase returns hundreds of hits, and the model's training data knows nothing about your repository.

## 5

You are about to compact the conversation in the middle of a debugging session. What is the best way to do it?

A, give it instructions naming the changed files, failing tests and live constraints. B, run it as is; the summary is generated by the model, and keeps what matters. C, skip compaction and switch models instead, which frees context without losing history. D, paste the memory file into the chat first, so the summary includes it.

[think]

The answer is A: give it instructions naming the changed files, failing tests and live constraints.

The summariser keeps what it judges important, which can drop the one detail you needed. Instructions make the summary follow your priorities, and compacting right after a green step leaves little to lose. A model switch does not shrink the context, and the memory file survives compaction without being pasted.

## 6

A subagent reads 40 files and returns a 400-token summary to the main session. What is the main benefit?

A, the summary is more accurate than the files, since noise is removed. B, the main context grows by the summary, not by all the tokens of reading. C, the subagent has edit permissions on files the main agent cannot touch. D, the subagent uses a cheaper model, so all that reading costs less overall.

[think]

The answer is B: the main context grows by the summary, not by all the tokens of reading.

Delegation isolates exploration. The main context grows by 400 tokens, rather than the tens of thousands the subagent read, so it keeps its constraints and plan in a small window. The trade-off is that the summary is lossy, not more accurate, so you delegate surveys and questions, not the decision itself.
