## Introduction

Twelve questions from the graphs module. Answer out loud before the answer comes.

They run through the module in order, two from each lesson: representations, breadth-first search, depth-first search, connectivity and cycles, topological sort, and modelling real problems as graphs. Each has four options, A to D, then a few seconds for you to commit to one.

## Question 1

Your breadth-first search from vertex 3, in an undirected graph, never reaches vertex 0, although the input contains an edge between 0 and 3. What is the most likely bug?

A, the queue was really a stack, so the search ran depth-first instead. B, vertex 0 has degree zero, so the search has no edge by which to reach it. C, each edge was added to only one endpoint's adjacency list. D, breadth-first search treats edges as one-way, so it cannot cross undirected edges.

[think]

The answer is C: each edge went into only one endpoint's list.

Appending 3 to vertex 0's list makes the edge usable from 0 but not from 3. Undirected edges must go into both endpoints' lists; the search simply follows whatever lists it is given. A stack instead of a queue would change the visiting order, not which vertices are reachable.

## Question 2

A puzzle has about a trillion possible states, but the solution is 20 moves from the start, and each state has 4 moves. Which representation should you use?

A, an adjacency matrix over all the states, giving constant-time move checks. B, an implicit graph, with neighbours generated by applying moves on demand. C, an adjacency list of every state, built once up front before searching. D, an edge list of all legal moves, sorted and scanned at each step.

[think]

The answer is B: an implicit graph.

Only states within 20 moves are ever touched, at most 4 to the power 20 in the worst case, and far fewer with a visited set of the states actually reached. Building the full adjacency list is impossible at a trillion states, and a matrix is far worse. The neighbour function is the graph.

## Question 3

A breadth-first search marks vertices visited when they are dequeued, instead of when they are enqueued. On a complete graph with V vertices, what happens?

A, nothing changes, because each vertex is still processed only once. B, the search never terminates, because vertices keep re-entering the queue forever. C, distances come out wrong, because a later duplicate overwrites the vertex's first label. D, each vertex can be enqueued up to V minus 1 times, so the queue fills with duplicates.

[think]

The answer is D: the queue fills with duplicates.

The source enqueues every other vertex, and each of those, when popped, enqueues all the still-unmarked ones again, for one plus V times V minus 1 over two enqueues in total. Distances stay correct, because the first dequeue wins and later duplicates are skipped, and the search still ends, because each vertex is marked once it is dequeued. Only the work multiplies. Mark on enqueue.

## Question 4

On a grid, every move costs 1, except moving through mud, which costs 3. Which algorithm finds the cheapest route?

A, Dijkstra with a priority queue, because the edge costs are unequal. B, zero-one BFS, because a deque handles two distinct edge costs. C, plain breadth-first search, because every move on a grid is still a single step. D, depth-first search with pruning, because it can abandon any branch that is already costlier.

[think]

The answer is A: Dijkstra.

Breadth-first search's rule that the first discovery is the shortest relies on uniform costs. With costs of 1 and 3, a route with more steps can be cheaper. Zero-one BFS handles two costs only when they are exactly 0 and 1, because its deque then holds two consecutive distances in order, and costs of 1 and 3 break that ordering.

## Question 5

During a depth-first search on a directed graph, you examine the edge from u to v, and v has already been visited and finished. What can you conclude?

A, v is an ancestor of u, so the edge is a back edge to the current path. B, the search is incorrect, since a finished vertex is never examined again. C, it is a forward or cross edge, which alone does not signal a cycle. D, the graph has a cycle, because v is being reached a second time.

[think]

The answer is C: a forward or cross edge, not a cycle.

A cycle is signalled by an edge to a vertex that is discovered but not finished, grey, still on the current path. A finished vertex cannot be an ancestor of u, because an ancestor is still open while u is being explored, so the edge points forward or across. Treating any visited vertex as a cycle is the classic false positive.

## Question 6

You convert a recursive depth-first search to an explicit stack by pushing all of a vertex's neighbours and marking visited on pop. Compared with the recursive version, what changes?

A, nothing changes, since the stack is exactly what recursion used anyway. B, some reachable vertices are missed, since a vertex pushed twice is skipped. C, running time grows to V squared, since each pop rescans the whole visited set. D, the stack can grow to the size of the edge count from repeated pushes, and the finish order is lost.

[think]

The answer is D: duplicate pushes, and no finish order.

Pushing in reverse keeps the discovery order the same as recursion, and every reachable vertex is still visited; a duplicate is skipped only because it was already marked. But duplicates can pile up on the stack, and the moment a vertex finishes is never observable. A stack of vertex and next-neighbour pairs fixes both, with a stack no larger than V and the same pre- and post-order as recursion.

## Question 7

An undirected graph has 10 vertices and 9 edges. It is a tree if and only if:

A, every vertex has degree at least 1. B, it is connected, or equivalently, acyclic. C, no vertex has a degree greater than 2. D, it has exactly two vertices of degree one.

[think]

The answer is B: it is connected, or equivalently acyclic.

With n minus 1 edges, connected implies acyclic and acyclic implies connected, so either check is enough. An acyclic graph with 10 vertices and 9 edges has 10 minus 9, one, component. Degree conditions are not enough: a square plus a separate path of six vertices has 10 vertices, 9 edges and no isolated vertex, yet it is not a tree.

## Question 8

A two-colouring by breadth-first search finds an edge whose endpoints have the same colour. What does that prove?

A, the graph contains an odd-length cycle, so it is not bipartite. B, the graph has a self-loop, the only same-colour edge possible. C, the graph contains an even-length cycle, so it is not bipartite. D, the search started at the wrong vertex and should be retried from another.

[think]

The answer is A: there is an odd cycle, so the graph is not bipartite.

Colours alternate along the search tree's paths, so two same-coloured vertices joined by an edge close a cycle of odd length through their common ancestor. Even cycles colour consistently; a square is bipartite. And bipartiteness does not depend on where you start.

## Question 9

A DAG has the topological orders 0, 1, 2, 3 and also 1, 0, 2, 3. What does this imply?

A, neither 0 nor 1 reaches the other, so they could be processed in parallel. B, Kahn's algorithm is non-deterministic, so it can emit either order. C, the graph has a cycle through 0 and 1, so no single order is forced. D, the graph has only two edges, so most pairs of vertices are left unordered.

[think]

The answer is A: 0 and 1 are independent.

Two valid orders that differ only by swapping two neighbours mean neither depends on the other. A unique topological order requires a path through every vertex in order. A cycle would make no order valid at all, and the orders say nothing about the edge count: 0 to 2, 1 to 2, and 2 to 3 fits, and so do other edge sets.

## Question 10

Why is longest path easy on a DAG, but NP-hard in general?

A, DAG edges are unweighted, so longest path reduces to a breadth-first depth. B, DAGs have at most V minus 1 edges, so the number of paths to search stays linear. C, general graphs have no topological order, so they have no longest path. D, in topological order, each predecessor's value is final before it is used.

[think]

The answer is D: in topological order, each predecessor's value is already final.

The recurrence, longest to v is the best predecessor's longest plus the edge weight, is well-founded only when the dependencies are acyclic, so one pass of relaxation in topological order is enough. With cycles, the simple-path constraint makes the problem combinatorial. General graphs still have longest simple paths; they are just hard to find. And DAGs can have weighted edges and on the order of V squared of them.

## Question 11

You have 200 thousand accounts, each with a few email addresses, and must group the accounts that belong to the same person, meaning they share an address. What is the efficient model?

A, compare every pair of accounts for a shared address, about n squared comparisons. B, hash each account's full set of emails and group equal hashes, linear in the total emails. C, sort accounts by their first email and merge neighbours that match, n log n. D, an account and email graph with components or union-find, linear in the total emails.

[think]

The answer is D: a graph through the email vertices, with components or union-find.

Shared addresses link accounts through the address itself. Visiting each account's emails and joining it with the first account that owns each email touches every email once, and components capture the chains of merges. Pairwise comparison is 20 billion operations. Hashing whole sets or sorting by first email only groups accounts whose entire set or first address coincide, and misses accounts that share just one address.

## Question 12

A "friends of friends" endpoint has a median latency of 5 milliseconds and a 99th percentile of 800, and the slow requests come from users connected to the same few accounts. What is the most likely cause?

A, the adjacency list is sharded, so each hop is a network round trip. B, a supernode with millions of edges sits inside the two-hop expansion. C, the graph is stored undirected, so every edge is expanded twice. D, the search marks visited on dequeue, so the queue holds duplicate entries.

[think]

The answer is B: a supernode inside the two-hop expansion.

Two-hop cost is the sum of the neighbours' degrees, so one celebrity among a user's friends multiplies the work by their degree, which is why the slow requests cluster around particular accounts. Duplicate queue entries, undirected storage and per-hop round trips would slow every request roughly equally. The fix is a cap per neighbour, sampling, or precomputed candidates for high-degree vertices.

## Recap

Three ideas kept coming back. The representation and the state decide everything: both directions for undirected edges, a vertex that holds everything the answer depends on, and neighbours generated on demand when the space is huge. Every traversal has one invariant to protect: mark on enqueue for breadth-first search, grey versus black for cycles in depth-first search, the count check in Kahn's algorithm. And costs hide in the shape of the data, in duplicate queue entries, unequal weights and supernodes, not in the average case.
