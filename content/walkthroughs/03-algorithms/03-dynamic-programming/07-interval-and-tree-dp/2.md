@0
The diameter of a tree is the longest path between any two nodes, counted in edges. In tree DP the table is the recursion's return values. Each call returns its subtree's height, the number of nodes on its longest downward path. On the way, it checks the longest path that bends through it, left height plus right height, against a global best. This tree has nine nodes, 1 to 9, and it is a single chain: every node has only a right child.

@1-9
The recursion enters 1, then 2, then 3, all the way down to 9. No node can do anything yet, because it needs the heights of both children first. That is post-order: children finish before their parent reads them.

@10
Node 9 is a leaf. Both children are empty, height 0, so the path through it is 0 edges and the best stays 0. It returns height 1.

@11
Node 8 has an empty left side and a right height of 1. The path through it is 0 plus 1, one edge, which beats the best, so the best becomes 1. It returns height 2.

@12-17
The same step repeats up the chain. At each node the left side is empty and the right height is one more than at the node below, so the path through it grows by one edge and becomes the new best: 2 at node 7, then 3, 4, 5, 6, and 7 at node 2. The returned heights climb from 3 to 8.

@18
At the root, node 1, the path through it is 0 plus 8, eight edges, the new best. It returns height 9.

@19
The diameter is 8 edges, the whole chain, highlighted. One post-order pass touches each node once, so it is linear. The naive version, which recomputes the height at every node, is quadratic on exactly this kind of chain. The same shape solves maximum path sum and house robber on a tree: return a small tuple from each child, combine at the parent.
