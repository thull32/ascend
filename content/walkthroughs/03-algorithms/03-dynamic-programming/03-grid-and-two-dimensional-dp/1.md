@0
A grid of 3 rows and 4 columns, and you may only move right or down. Each cell will hold the number of distinct paths from the top-left corner to it. The last move into any cell came either from the cell above or from the cell to its left, and no path does both, so a cell is the sum of those two. The fill goes row by row, left to right, so both neighbours are always ready.

@1
Base case: the start cell, row 0 column 0, is 1. There is exactly one way to be at the start.

@2-5
The edge cells have only one neighbour. Along the top row, columns 1, 2 and 3 can only be reached from the left, so each is 1: the all-right path. Then the first cell of row 1 can only be reached from above, so it is 1 as well.

@6
The first interior cell, row 1 column 1. Above it is 1, to its left is 1, so it is 2: right then down, or down then right.

@7-8
The rest of row 1 follows the same rule. Column 2 is 1 above plus 2 on the left, which is 3. Column 3 is 1 plus 3, which is 4.

@9-11
Row 2 starts with another edge cell, 1, reachable only from above. Then column 1 is 2 above plus 1 on the left, which is 3, and column 2 is 3 plus 3, which is 6.

@12
The answer cell, bottom-right, row 2 column 3. Above it is 4, to its left is 6, so it holds 10.

@13
Ten unique paths. Without obstacles this matches a closed form: every path is 5 moves of which 2 are downs, and there are 10 ways to choose which 2. The table is Pascal's triangle tilted. The DP still wins once obstacles or costs appear, because the recurrence barely changes. The cost is rows times columns, and since each row only reads the row above, one rolling row is enough memory.
