@0
Five nodes, A to E, and two of the edges are negative: B to E costs minus 4, and C to B costs minus 2. Dijkstra would be wrong here. Bellman-Ford gives up on choosing an order and simply relaxes every edge, in a fixed order, round after round. With five nodes, a shortest path has at most four edges, so four rounds are enough.

@1-2
Round one starts at A. A to B has weight 6, so B becomes 6. A to D has weight 7, so D becomes 7.

@3-4
B to C gives 6 plus 5, so C becomes 11. B to E has weight minus 4, so E becomes 2.

@5
Then D to C, with weight minus 3: 7 minus 3 is 4, better than 11. Notice what happened. Relaxation is in place, so this edge used the value of D set moments earlier in the same round, and C reached 4 after a single round even though its path, A, D, C, has two edges.

@6
Round two finds one improvement. C to B costs minus 2, and 4 minus 2 is 2, better than the 6 that A gave B directly. So B, A's own neighbour, gets its final distance only after C, which got its own only after D. Dijkstra would have settled B at 6 and discovered too late that the long way round is cheaper.

@7
Round three: B has dropped to 2, so B to E now gives 2 minus 4, which is minus 2. E improves from 2 to minus 2, by the path A, D, C, B, E.

@8
Round four changes nothing. If a full round changes nothing, no later round can either, because every round sees the same distances, so the algorithm exits early.

@9
The final distances are A 0, B 2, C 4, D 7 and E minus 2, and there is no negative cycle. One more pass over every edge is the check: if any edge still improved, some shortest path would need five or more edges, which means it repeats a node, which means a negative cycle. The cost is V times E, slower than Dijkstra, but correct where Dijkstra is wrong. Edge order is invisible in that bound and dominant in practice: here three rounds did the work, while edges stored in reverse along a path would need all four.
