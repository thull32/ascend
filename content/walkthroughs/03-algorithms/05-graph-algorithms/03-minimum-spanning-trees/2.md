@0
The same six nodes and the same weights, but a different schedule. Kruskal sorts every edge by weight and walks the list, adding an edge only if its two ends are in different components. Union-find answers that question, are these in the same tree, in near-constant time.

@1-2
The lightest edge is A to C, at 2. A and C are in different components, so the edge is added, and the tree weighs 2.

@3-4
Next is C to E, at 3. E is on its own, so this joins it to A and C. The tree weighs 5.

@5-6
Then A to B, at 4. B is on its own, so it joins as well. Three edges taken, weight 9.

@7-8
B to C, at 5, is the first rejection. B and C are already connected, through A, so this edge would close a cycle. It is also the heaviest edge on the cycle A, B, C, and by the cycle property no minimum spanning tree contains it.

@9-10
D to E, at 6, joins D to the big component. Four edges, weight 15.

@11-12
D to F, at 7, brings in F, the last node. Five edges for six nodes means every node is connected, so the algorithm can stop. The heavier edges never need to be examined.

@13
The tree weighs 22, the same tree Prim found, because with distinct weights the minimum spanning tree is unique. Here the sort dominates, so Kruskal costs order of E log E. It also has a property Prim lacks: on a disconnected graph it builds one tree per component, a spanning forest, without any change.
