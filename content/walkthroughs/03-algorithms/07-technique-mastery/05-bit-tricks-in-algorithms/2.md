@0
One trick drives this whole picture: x AND x minus 1 clears the lowest set bit of x. Repeat it until x reaches 0, and the number of steps is the number of set bits. It is also, step for step, the path a Fenwick tree query takes.

@1
Start with 13, which is 1101 in binary. The count is 0.

@2-3
Subtracting 1 flips the lowest set bit, bit 0, to 0, and there are no bits below it to borrow through, so x minus 1 is 12, 1100. AND keeps only the bits set in both rows, so exactly that lowest bit disappears. The result is 12, and the count is 1.

@4-5
Now x is 12, 1100, whose lowest set bit is bit 2. Subtracting 1 borrows through the two trailing zeros: bit 2 flips to 0 and both bits below it flip to 1, giving 11, 1011. The higher bit is untouched. The AND clears bit 2 and leaves 8, 1000. The count is 2.

@6-7
x is 8, 1000. Subtracting 1 borrows all the way down: 7, 0111. The AND has nothing in common, so the result is 0, and the count is 3.

@8
x reached 0 after 3 steps, so 13 has 3 set bits. The cost is the number of set bits, not the width of the word.

@9
Now read the values it passed through: 13, 12, 8. A Fenwick tree query for the prefix ending at 13 visits exactly those nodes. Node 13 covers just position 13, node 12 covers 9 to 12, and node 8 covers 1 to 8. Three ranges that tile 1 to 13, one per set bit, and never more than log of n. Subtracting the lowest set bit and clearing it with x AND x minus 1 are the same operation.
