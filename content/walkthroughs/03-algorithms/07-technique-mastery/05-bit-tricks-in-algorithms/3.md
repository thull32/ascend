@0
The Gray code orders binary values so that neighbours differ in exactly one bit, and the code at position i is i XOR i shifted right by one. Here i is 6. In four bits, 6 is 0110, and shifted right by one it becomes 3, 0011. Those are the two rows on screen. Every bitwise operator works on each column independently, so we will combine them three ways.

@1-6
First AND: a result bit is 1 only when both bits are 1. Working from the right, only bit 1 has a 1 in both rows. So 6 AND 3 is 0010, which is 2. AND is a mask: it keeps only the bits set in both.

@7-12
Then OR: a result bit is 1 when either bit is 1. Bits 0, 1 and 2 each have a 1 somewhere, and bit 3 has none. So 6 OR 3 is 0111, which is 7. OR turns bits on without disturbing the others.

@13-17
Now XOR, the one the Gray code needs: a result bit is 1 when the two bits differ. Bit 0 differs, 0 and 1, so it is 1. Bit 1 matches, both 1, so it is 0. Bit 2 differs, so it is 1. Bit 3 matches, both 0.

@18
6 XOR 3 is 0101, which is 5. So the Gray code at position 6 is 101 in three bits, the seventh code in the sequence. XOR toggles: applying the same mask twice restores the original.

@19
Each of these is a single constant-time instruction, because the hardware evaluates every column in parallel. Compare with the code before it: position 5 gives 111. From 111 to 101, exactly one bit changed, bit 1, which is the position of the lowest set bit of 6. That one-bit property is what lets you walk all subsets while adding or removing a single element per step, so a running sum costs one addition or subtraction per subset instead of n.
