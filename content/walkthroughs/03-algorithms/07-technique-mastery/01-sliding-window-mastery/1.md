@0
Ten values: 3, 1, 4, 1, 5, 9, 2, 6, 5, 3. We want the longest run with no repeated value. The right end, R, advances one step at a time, and when a duplicate enters, the left end, L, jumps past the previous copy. Hold onto one fact, because it is the whole algorithm: for this property, the best left end never moves backwards.

@1-3
The first three values, 3, 1 and 4, are all new. The window grows from position 0 to position 2, with three distinct values, and the best so far is 3.

@4
Position 3 holds 1, and 1 already sits at position 1. The window cannot contain both, so L jumps to position 2, one past the old copy. The window is now 4 and 1, two values, and the best stays at 3. Any window ending here or later that started further left would hold both copies of 1, which is why L never needs to come back.

@5-8
Then a long run of new values: 5, 9, 2 and 6. The window stretches from position 2 to position 7, holding 4, 1, 5, 9, 2 and 6, six distinct values, and the best becomes 6.

@9
Position 8 holds 5, which already sits at position 4. L jumps to position 5. The window is 9, 2, 6 and 5, four values, and the best stays at 6.

@10
Position 9 holds 3. The earlier 3, at position 0, was left behind long ago, so it is new to this window. Five distinct values, and the best is still 6.

@11
The longest run of distinct values has length 6. The code is a while loop inside a for loop, but it is not quadratic: L and R each move at most n times and never backwards, so the total work is at most two n steps. That only holds because the property is closed under shrinking: every sub-window of a window with no repeats has no repeats either. Ask that question first, and you know whether a window is the right tool.
