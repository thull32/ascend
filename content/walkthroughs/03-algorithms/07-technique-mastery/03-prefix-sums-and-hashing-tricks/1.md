@0
Six values: 4, 5, 0, minus 2, minus 3, 1, and the question from the start of the lesson: how many subarrays have a sum divisible by 5? Below the values sit two rows. The first holds prefix sums, starting from P of 0, which is 0, the sum of nothing. The second holds each prefix's remainder when divided by 5. Here is the whole trick: a subarray's sum is the difference of two prefixes, and that difference is divisible by 5 exactly when the two prefixes leave the same remainder. So every pair of equal remainders is one subarray. A counter per remainder starts with remainder 0 seen once, for the empty prefix.

@1
Adding 4 gives the prefix 4, remainder 4. No earlier prefix has remainder 4, so nothing is counted yet.

@2
Adding 5 gives 9, again remainder 4. One earlier prefix shares it, so one subarray ending here is divisible by 5: the 5 on its own. The total is 1.

@3
Adding 0 leaves 9, remainder 4 once more. Now two earlier prefixes share it, so two more subarrays end here: 5 and 0, and the 0 on its own. The total is 3.

@4
Adding minus 2 gives 7, remainder 2, a bucket nobody else is in. Nothing is counted. Negative values are no problem here, which is exactly where a sliding window gave up.

@5
Adding minus 3 brings the prefix back to 4, remainder 4, and three earlier prefixes already sit in that bucket. Three more subarrays: 5 through minus 3, 0 through minus 3, and minus 2 with minus 3. The total is 6.

@6
Adding the final 1 gives 5, remainder 0, which matches the empty prefix at the start. That pair is the whole array, whose sum is 5. The total is 7.

@7
Seven subarrays, found in one pass with five counters. Each new prefix adds the number of earlier prefixes with the same remainder, which builds the pair count one term at a time. The same six lines answer sum equals k, sum divisible by k, and XOR equals t; only the key changes. It works because the operation can be undone. Maximum, minimum and gcd have no inverse, and need a different structure.
