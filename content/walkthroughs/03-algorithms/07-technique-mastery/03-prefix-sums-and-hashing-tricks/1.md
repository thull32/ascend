@0
Six values: 4, 5, 0, minus 2, minus 3, 1. Below them sits an empty row of prefix sums. Each prefix will hold the sum of every value up to and including its position. Build the row once, in a single pass, and any range sum becomes one subtraction, because the shared beginning cancels out.

@1-2
The first prefix is just 4. The next adds 5, giving 9. Each new prefix is the previous prefix plus one value, so each costs a single addition.

@3-4
Adding 0 leaves 9. Adding minus 2 gives 7. Negative values are no problem here, which is exactly where a sliding window gave up.

@5-6
Adding minus 3 gives 4, and adding the final 1 gives 5. The full row reads 4, 9, 9, 7, 4, 5.

@7
Now a query: the sum of positions 1 to 4, that is 5, 0, minus 2 and minus 3. Take the prefix at position 4, which is 4, and subtract the prefix just before the range, at position 0, which is also 4. The answer is 0, in one subtraction, whatever the length of the range. And look at those two prefixes again: both are 4, so they have the same remainder when divided by 5, and that is exactly why the range between them is divisible by 5. Counting such ranges means counting pairs of prefixes with equal remainders, which one pass with five counters does. The trick works whenever the operation can be undone: sums, sums modulo k, and XOR. Maximum, minimum and gcd have no inverse, and need a different structure.
