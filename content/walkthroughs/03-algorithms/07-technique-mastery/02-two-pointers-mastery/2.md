@0
Eight values, each a 0, a 1 or a 2, to be sorted in one pass. Three pointers, lo, mid and hi, split the array into four regions: 0s before lo, 1s from lo up to mid, the unknown region from mid to hi, and 2s after hi. Each step looks at the value under mid, and every step shrinks the unknown region by one.

@1
Mid finds a 2. It is swapped with the value at hi, the last position, which happens to be another 2, and hi moves left. Mid stays put, because whatever arrived from hi has not been examined yet.

@2
And here is why that rule matters. Mid still holds a 2, so it is swapped again, this time with the 1 at hi. The 2 lands at position 6, the 1 arrives at position 0, and hi moves left again.

@3
Mid now examines that 1. It already belongs in the middle region, so mid just advances.

@4
At position 1, mid finds a 0. It is swapped with the value at lo, the 1 at position 0. The 0 goes to the front, and lo and mid both advance. Mid can move on safely here, because anything arriving from lo has already been examined.

@5
At position 2, mid finds a 2. It swaps with the 0 at hi, position 5, and hi moves left. Again mid stays, to examine the 0 that just arrived.

@6
That 0 is swapped with the 1 at lo. Now the array reads 0, 0, 1, 1, 1, 2, 2, 2, and lo and mid advance together.

@7-8
The last two unknowns are both 1s, so mid advances twice and passes hi. The unknown region is empty.

@9
Sorted in one pass, with constant extra space. The asymmetry between the two swaps is the whole bug surface: a swap with lo brings in a value already seen, so mid advances; a swap with hi brings in a stranger, so mid waits. The potential, hi minus mid plus 1, drops on every branch, which is the proof the loop is linear. Forget to move either pointer after a swap, and the loop spins forever on an input as small as 2, 2.
