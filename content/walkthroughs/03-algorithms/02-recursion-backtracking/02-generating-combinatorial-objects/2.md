@0
Permutations of 1, 2 and 3. At each depth, the search chooses one element that is not yet used, and a full path of length 3 is one permutation. The first level has three choices, the next has two, the last has one: 3 times 2 times 1, so expect 6 leaves.

@1-4
At depth 0 all three elements are unused, and the search picks 1. At depth 1 the unused set is 2 and 3; it picks 2. At depth 2 only 3 is left. The path is full, so 1, 2, 3 is recorded as permutation number 1.

@5-6
Now the step that makes it backtracking. Back at the path 1, 2, the search un-chooses 3, so that a later branch may use it. Then, back at the path holding just 1, it un-chooses 2. Every choice is undone exactly, in reverse order.

@7-10
With 1 still in place, the next option at depth 1 is 3. That leaves only 2, so the path 1, 3, 2 is recorded as permutation number 2. Then the search unwinds again, un-choosing 2 and then 3.

@11
Back at the empty path, 1 itself is un-chosen. Every permutation that starts with 1 has been produced: two of them.

@12-21
The same pattern runs with 2 in front. The unused set at depth 1 is 1 and 3. Choosing 1 then 3 records 2, 1, 3 as permutation number 3. Unwinding and choosing 3 then 1 records 2, 3, 1 as number 4. Then everything is un-chosen back to the empty path.

@22-31
And once more with 3 in front: 3, 1, 2 is permutation number 5, and 3, 2, 1 is number 6. The search unwinds all the way to the root, and the used set is empty again, exactly as it started.

@32
6 permutations from 16 calls: the root, 3 nodes on the first level, 6 on the second, and 6 leaves. The leaves alone number n factorial, and each one is copied out at length n, so the total is n times n factorial. No algorithm that outputs every permutation can do less. Notice the symmetry that keeps it correct: one choose before each call, one un-choose after it.
