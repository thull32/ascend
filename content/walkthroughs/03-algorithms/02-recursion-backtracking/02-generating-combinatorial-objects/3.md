@0
Choose 2 of the four numbers 1, 2, 3 and 4. Two rules make this work. Pick in increasing index order, so each combination appears once and never in a second order. And prune any branch that can no longer reach 2 items.

@1-2
The root needs 2 more items, and its candidates are all four. It picks 1. That child needs 1 more, and its candidates start after 1: only 2, 3 and 4. The start index is the whole trick: once 1 is chosen, nothing before it can follow.

@3-6
Each of those candidates completes a pair, so the records come quickly: 1, 2, then 1, 3, then 1, 4, combinations number 1 to 3. All candidates for the path holding 1 are tried, and it returns.

@7-10
The root picks 2 next. Its child's candidates start at 3, so it records 2, 3 and 2, 4. There is no 2, 1: that pair was already produced as 1, 2, and the start index makes sure it can never appear again.

@11-13
The root picks 3. Only 4 is left after it, giving 3, 4, combination number 6.

@14
Finally the root would pick 4, but there is nothing after 4, and 1 more item is still needed. This branch can never fill up, so it is pruned on the spot and never gets a subtree.

@15-16
6 combinations, which is 4 choose 2. Recording only at depth k, starting each level after the last choice, and cutting branches that cannot reach k is what makes this cheaper than enumerating all 16 subsets and filtering by size. On bigger inputs that pruning matters: for 20 choose 10 it removes about 60 percent of the internal nodes.
