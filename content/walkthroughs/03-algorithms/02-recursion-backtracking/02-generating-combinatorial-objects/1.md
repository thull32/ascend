@0
Every subset of 1, 2 and 3 is a sequence of three yes-or-no decisions: is 1 in, is 2 in, is 3 in. Each level of this tree makes one of those decisions, so the tree is binary, and it has 2 to the 3, which is 8 leaves. Each leaf is one subset.

@1-4
The search always takes the include branch first. Include 1, include 2, include 3. All three decisions are made, so the path is complete, and the subset 1, 2, 3 is recorded as subset number 1.

@5-7
Now backtrack one level. Back at the partial subset 1, 2, the search takes the other branch: exclude 3. That is also a leaf, so 1, 2 is recorded as subset number 2. Both choices for 3 have been explored under this node, so it returns to its parent.

@8-13
Back at the partial subset holding just 1, the search now excludes 2. Below that, it includes 3 and records 1, 3 as subset number 3, then excludes 3 and records 1 alone as subset number 4. Both of those subtrees are finished, so the search climbs back up to the root. Everything containing 1 has been listed: four subsets, exactly half.

@14-21
At the root, the search finally takes the exclude branch for 1. The whole pattern repeats one level down: include 2, include 3, record 2, 3 as subset number 5. Exclude 3, record 2 alone as subset number 6. Return.

@22-26
Still without 1, now exclude 2. Include 3 records the subset holding only 3, number 7. Exclude 3 records the empty set, number 8. The empty set is a leaf like any other: three decisions, all of them no.

@27-29
Every remaining call has explored both its branches, so the recursion unwinds to the root and returns.

@30
8 subsets from 15 calls: 1 plus 2 plus 4 plus 8 nodes. The number of leaves is 2 to the n, so the running time is exponential no matter what, but the recursion is only n levels deep, so the stack stays tiny. Remember that the output itself is the lower bound here: any algorithm that writes out every subset does at least that much work.
