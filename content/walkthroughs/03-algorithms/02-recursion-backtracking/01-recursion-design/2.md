@0
Ten sorted values, from 2 up to 91, and we are looking for 23. Each call looks at the middle of its range and makes exactly one recursive call, on the half that can still contain the target. That is the same recurrence as power: one call on half the input, plus constant work. So instead of a branching tree, watch for a chain.

@1
The first call covers positions 0 to 9. The middle is position 4, which holds 16. Sixteen is less than 23, so the target can only be to the right, and the call recurses on positions 5 to 9.

@2
The second call covers 5 to 9. Its middle, position 7, holds 56, which is bigger than 23, so it recurses on the left part of its range: positions 5 and 6.

@3
The third call's middle is position 5, which holds 23. Found: this call returns 5, without recursing any further. Three calls, one per level, and half the range was discarded each time.

@4-5
Now the chain unwinds. The call on 5 to 9 returns the 5 it was handed, unchanged, and so does the first call. The recursive call was the last thing each one did, so there is nothing to combine on the way up.

@6
Found at index 5, after 3 calls and a depth of 3. One branch per level gives log n time and a log n deep stack, which is safe for any input you can store. And because the call is in tail position, a compiler that eliminates tail calls could run it in constant space; the lesson explains why Python and JavaScript will not.
