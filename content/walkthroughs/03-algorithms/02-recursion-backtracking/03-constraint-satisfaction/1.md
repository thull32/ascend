@0
Four queens on a four by four board, one queen per row, so each level of the search is a row and the only choice is the column. A cell is safe if no earlier queen shares its column, its diagonal, or its anti-diagonal. The diagonal is identified by row minus column, the anti-diagonal by row plus column, and two queens on the same diagonal share that number. Three quick checks per cell.

@1-2
Row 0 has no queens above it, so its first column is safe. A queen goes in row 0, column 0, and the search recurses to row 1.

@3-6
Row 1, column 0 shares a column with that queen: skip. Column 1 shares its diagonal: skip. Column 2 is safe, so a queen goes there and the search moves on to row 2. Each rejected cell is rejected the moment it is proposed, and it never gets a subtree.

@7-12
Row 2 is a dead end. Column 0 is under the first queen. Column 1 shares an anti-diagonal with the queen in row 1. Column 2 is under the second queen, and column 3 is on that queen's diagonal. No column works, so this call returns false to row 1.

@13-14
Backtrack: remove the queen at row 1, column 2, and try the next column. Row 1, column 3 is safe, so the queen moves there.

@15-17
Row 2 again, with a different board above it. Column 0 is still under the first queen, but column 1 is now safe. A third queen goes in, and the search reaches row 3.

@18-23
Row 3 fails on every column. Column 0 is under the first queen, column 1 under the queen in row 2, and column 3 under the queen in row 1, while column 2 is on the diagonal of the queen in row 2. Dead end, return false.

@24-29
The queen in row 2 is removed, and row 2's remaining columns fail too: column 2 is on the first queen's diagonal, column 3 is under the queen in row 1. So row 2 is dead, the queen in row 1 is removed, and row 1 has no columns left either. Everything below a queen in the corner has failed.

@30-31
So the very first choice was wrong. The queen at row 0, column 0 is removed, and the next column, 1, is tried. It is safe.

@32-36
Row 1: column 0 shares the new queen's anti-diagonal, column 1 its column, column 2 its diagonal. Column 3 is safe, and a queen goes there.

@37-38
Row 2, column 0 is safe at the first try. A third queen goes in.

@39-42
Row 3: column 0 is under the queen in row 2, column 1 is under the queen in row 0, and column 2 is safe. The fourth queen goes in.

@43
Row 4 is reached, which means all four queens are placed with no conflict. Solution found, and the search unwinds returning true.

@44
The first solution has its queens in columns 1, 3, 0 and 2, after 8 placements. Brute force would look at 4 to the 4, which is 256 boards. Nothing changed the worst case; what changed is that every conflict was caught the moment the conflicting queen was proposed, never deeper. On eight queens, checking only at the leaf visits about 19 million nodes; checking at each placement, the same search visits 2,057.
