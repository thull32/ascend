@0
A four by four grid of land and water, and the task is to count the islands. The grid is a graph nobody builds: each cell's neighbours are the cells above, below, left and right. The scan visits cells in order, and every unvisited land cell starts a depth-first flood fill that marks its whole island. The mark is what matters. A marked cell is never entered again, so the search can never loop.

@1-4
The first land cell is at row 0, column 0, and it has not been visited, so it starts island 1. The flood marks it, then spreads right to row 0, column 1, then down to row 1, column 1. Every neighbour of those three cells is water, already marked, or off the grid, so island 1 is complete at three cells.

@5-9
The scan moves on, skipping the marked cells, until it finds unvisited land at row 1, column 3: island 2. The flood runs down to row 2, column 3, then to row 3, column 3, then left to row 3, column 2. Four cells, all marked.

@10-11
The scan reaches row 3, column 0. It is land and unmarked, so it starts island 3, a single cell with water all around it.

@12
Three islands. The cell at row 3, column 2 never starts a fourth, because island 2's flood had already marked it. Each cell is visited once, so the whole count is proportional to rows times columns. Word search uses exactly this trick: overwrite the cell while it is on the current path, restore it on the way back, and the visited set costs no extra memory.
