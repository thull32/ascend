@0
These eleven boxes are not data. They are the possible answers: candidate eating speeds from 1 to 11. For each speed we can ask one yes-no question, is this speed fast enough to finish in time? Here the answer is no for speeds 1 to 3 and yes from 4 onwards. The question is monotone: once a speed works, every faster speed works too. So the answers run false, then true, and we want the first true, with exactly the template from plain binary search.

@1
The search range covers all eleven candidates. The middle is speed 6. We run the feasibility check at speed 6, and it passes. Speed 6 might be the answer, so it stays in range: high moves down to it.

@2
Now the middle is speed 3. The check fails. By monotonicity, every slower speed fails too, so low jumps past it, to speed 4.

@3
Between speeds 4 and 6, the middle is 5. It passes, so high moves down to 5.

@4
The only candidate left to test is speed 4. It passes, so high moves down to 4.

@5
Low and high meet at speed 4: the smallest speed that works, found with four checks instead of eleven. Notice that no probe compared anything against a stored element. Each probe ran the predicate, which in a real problem is usually a linear greedy simulation, so the total cost is the cost of that check times the logarithm of the answer range. With answers up to a billion, that is about 30 checks. The skill is the reframing: write the question as is this answer good enough, and say out loud why a larger answer only makes it easier.
