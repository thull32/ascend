@0
Seven numbers: 4, 2, 2, 8, 3, 3 and 1. Every one is a small whole number, no larger than 8. That one fact changes the game: instead of comparing elements, we can use each value as an index into an array of counts, one slot for every possible key from 0 to 8. All nine counts start at zero. The plan has three passes: count, turn the counts into starting positions, then place each element.

@1-4
Walk the input once. The first value is 4, so the count in slot 4 goes up to one. Then 2, and slot 2 goes to one; the next 2 bumps it to two. Then 8, and slot 8 becomes one.

@5-7
3 twice, so slot 3 reaches two, and finally 1 sets slot 1 to one. The histogram now reads: one 1, two 2s, two 3s, one 4, one 8. Not a single comparison so far.

@8-12
The second pass turns counts into starting positions with a running total. The start of each key is the number of elements with a smaller key. Key 0 never occurs and starts at 0. Key 1 also starts at 0, and the total becomes 1. So key 2 starts at 1, and its two copies bring the total to 3. Key 3 starts at 3, and the total reaches 5. Key 4 starts at 5.

@13-16
Keys 5, 6 and 7 do not occur, so each starts at 6 and the total stays 6. Key 8 starts at 6 as well, and the total ends at 7, the length of the input. The row now reads 0, 0, 1, 3, 5, 6, 6, 6, 6: exactly the starting positions from the lesson's trace.

@17-19
The third pass walks the input in its original order and drops each element into its slot. The 4 goes to position 5, and the start for key 4 moves on to 6. The first 2 goes to position 1, and the start for key 2 moves to 2, so the second 2 lands right after it, in position 2.

@20-23
The 8 goes to position 6. The two 3s go to positions 3 and 4, in the order they arrived. Finally the 1 goes to position 0.

@24
Sorted: 1, 2, 2, 3, 3, 4, 8, with no comparisons at all. Because the placement pass runs forwards, equal keys land in input order, so the sort is stable, and that is what lets radix sort build on it. Run that pass backwards and it still sorts, but stability is gone. The cost is the length of the input plus the number of possible keys, here nine, which is why counting sort escapes the n log n lower bound: that bound only applies to algorithms that learn about the input by comparing. The trap is the key range. Counting sort wants it to be about the size of the input; for 32-bit integers the counts array alone would be 16 gigabytes, which is the problem radix sort solves.
