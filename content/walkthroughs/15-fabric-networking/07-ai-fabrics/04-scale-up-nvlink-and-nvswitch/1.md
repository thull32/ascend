@0
On screen are two servers from Meridian's San Jose cluster, srv001 and srv002. Inside srv001, GPU0 and GPU1 meet at the NVSwitch. GPU0 also sits under a PCIe switch next to its own 400 gigabit per second ConnectX-7 network card, which is cabled to the rail 1 leaf, rail1-leaf1. srv002 is built the same way. Hold onto one idea, because it is the whole picture: inside the server, GPUs share memory over a link nine times faster than the network, and that speed stops at the edge of the server.

@1
Scale-up first. GPU0 copies 1 gibibyte into GPU1's memory. NVLink carries the GPUs' own memory reads and writes as small hardware packets, so this is simply a memory copy through the NVSwitch. There is no network card, no IP or transport header, and no protocol stack on the path.

@2
An H100-class GPU has 18 NVLink 4 links, 900 gigabytes per second counting both directions, or 450 each way. So the gibibyte lands in GPU1 in about 2.4 milliseconds, and the table fills in its first column. Through the NVSwitch, every one of the server's eight GPUs can reach every other at that same rate.

@3
Now scale-out: the same gibibyte to GPU0 of srv002. With GPUDirect RDMA, the network card reads straight from GPU memory through the PCIe switch the two share, with no copy into the CPU's memory. A PCIe generation 5 slot, sixteen lanes wide, carries about 63 gigabytes per second each way, more than the card needs.

@4
The card cuts the data into RoCE version 2 packets with 4,096 bytes of payload each, 262,144 of them for the gibibyte. It sends them at 400 gigabits per second, which is 50 gigabytes per second: one ninth of NVLink's 450.

@5
On the wire, each frame of about 4,158 bytes takes 83 nanoseconds to serialise at 400 gigabits, and light crosses the few metres of cable at about 5 nanoseconds per metre. The rail 1 leaf forwards each packet on its destination IP address. It has no idea a GPU sits behind the card.

@6
The leaf adds its own forwarding delay, from a few hundred nanoseconds to about a microsecond depending on the switch chip, and far more if a queue has built up. srv002's card then checks each packet's sequence number, and the remote memory key carried in the first packet of each message: the transport work the RDMA from zero lesson traces.

@7
srv002's card writes the payload through its own PCIe switch straight into GPU0's memory, GPUDirect RDMA again. The second column fills in: 50 gigabytes per second, and 21.5 milliseconds for the whole gibibyte, nine times NVLink's 2.4.

@8
Now the table sets them side by side. NVLink gives each GPU nine times the bandwidth, and a small-message latency of about a microsecond, against a few microseconds on an idle network and more when queues build. But NVLink reaches only the eight GPUs in its server. The card and the fabric reach all 1,024 GPUs in the cluster, at a ninth of the rate, through five devices instead of one: a PCIe switch, a card, the leaf, a card and another PCIe switch. Every extra switch tier adds latency.

@9
The chart asks how fast a transfer really goes, by message size. It uses the alpha-beta model: a fixed start-up cost per transfer, plus the size divided by the bandwidth. With an assumed 1 microsecond per NVLink transfer and 3 per network transfer, a 1 mebibyte message reaches 315 gigabytes per second on NVLink and 44 on the network. Messages of a few kibibytes are bound by latency on both. And the faster link needs the bigger message to fill it: the network gets within a few percent of its peak from about 4 mebibytes, NVLink only from about 16.

@10
Now the path this run avoided. Without GPUDirect RDMA, the data would first be copied from GPU memory into the CPU's memory, and the card would read it from there: an extra copy and an extra PCIe crossing at each end. A card under the wrong PCIe switch or the wrong CPU socket has much the same effect, a classic reason a fresh cluster misses line rate, which the tuning lesson takes apart.

@11
Last, the scale-up domain keeps growing. An NVL72 rack joins 72 GPUs with NVLink 5, at 1.8 terabytes per second per GPU in total, so tensor and expert parallelism can span 72 GPUs instead of 8. The network then carries only what crosses racks, mostly data and pipeline parallelism. But each GPU's network link is still a ninth of its NVLink or less, so placement keeps mattering. That is the pattern to keep: put the chattiest traffic on the fastest, shortest fabric, and size the network for whatever has to leave it.
