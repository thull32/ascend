@0
On screen is Meridian's Amsterdam fabric with all four spines, and a probe agent behind three leaves: 10.250.11.10 behind leaf1, and 10.250.13.10 behind leaf3. Acme says some requests from its web servers behind leaf1 to its databases behind leaf3 are slow, now and then, while others are fine. Hold onto one idea, because the whole method follows from it: a probe measures only the path it took, so in a leaf-spine fabric you have to choose those paths on purpose, and label every result with the path it took.

@1
First, ping. 100 sent, 100 received, 0 percent loss, an average round trip of 52 microseconds. All true, and nearly useless. ICMP has no ports, so to the hash every echo between these two addresses looks the same. leaf1 sends all of them up one spine, here spine1, and ping has tested one path out of four.

@2
So the agent runs TWAMP Light: 16 UDP streams to the reflector's port 862, 10 packets a second each, identical except for the source port, 50001 to 50016. The reflector behind leaf3 timestamps each packet and returns it with its own sequence number, so loss can be split by direction. A different source port is a different 5-tuple, so leaf1's hash spreads the streams across the spines. The spine column is still a question mark.

@3
To fill it in, the agent sends one packet with each stream's exact 5-tuple but a TTL of 2. It expires at the spine, and the ICMP time exceeded comes back from that spine's address on the link, 10.254.3.0 for spine3. The hash ignores the TTL, so this packet takes exactly the stream's path. The map: 4 streams on spine1, 5 on spine2, 3 on spine3, 4 on spine4.

@4
After five minutes, 3,000 packets per stream. Three streams lost about 4 percent from leaf1 to leaf3: 3.9, 4.1 and 3.8 percent. Every other stream is clean, apart from one lost packet of noise, and the 99th percentile round trip is 61 microseconds on all of them, the bad ones included. Averaged over all 16 streams the loss is 0.7 percent, which is why a single fabric-wide number hides a path that is badly broken.

@5
Now group by spine. spine3 carries the three bad streams and loses 3.93 percent; no stream through any other spine is degraded. Acme's own connections hash the same way, so about a quarter of them cross spine3 and suffer retransmissions. That is why the complaint is sometimes slow, rather than down.

@6
But is it spine3 itself, or one of its links? Add the agent behind leaf2 and you get two more pairs. leaf2 to leaf3 through spine3: 5 streams, about 4 percent loss. leaf1 to leaf2 through spine3: 5 streams, nothing lost. The only element every bad path shares and the good path lacks is the link from spine3 down to leaf3. That set arithmetic is boolean network tomography, and it needs the good path as much as the bad ones.

@7
The counters at both ends agree. spine3 sent 3.000 billion frames on that link in five minutes; leaf3 received 2.883 billion intact and discarded 117 million, 3.9 percent, that failed the frame check, and its uncorrectable FEC codewords are rising. One receive lane of leaf3's optic reads minus 8.6 dBm against about minus 2 on the other three, too weak for forward error correction to repair every error. Yet both ends say the link is up, so ECMP keeps sending it a quarter of the traffic bound for leaf3.

@8
Meridian costs out that one link, raising its IS-IS metric at both ends so no shortest path uses it. A metric only governs traffic leaving its own end, and the damaged direction is spine3 to leaf3. leaf1's next hops for leaf3's prefixes drop to three: spine1, spine2 and spine4. The same 16 streams rehash, modulo 3 now, and none of them loses a packet, which confirms the diagnosis while the optic replacement is scheduled.

@9
Two things made this work: enough distinct 5-tuples to cover every path, and grouping results by the path each probe took. Even 16 random source ports leave each spine a 1.0 percent chance of getting no stream at all, so real probing systems map their paths and fill the gaps deliberately, at least two streams per spine. The same pattern scales to a pingmesh matrix across every pair of leaves. And ping, with its single 5-tuple, would have kept saying 0 percent loss.
