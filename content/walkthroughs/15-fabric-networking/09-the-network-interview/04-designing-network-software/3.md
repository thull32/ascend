@0
Meridian's intent loop for one switch, leaf1.ams, a small example with two of its uplinks shown. The source of truth holds what the network should be. The automation server at 172.16.0.20 renders that into configuration and compares it with what leaf1 is really running, which it reads over the out-of-band management network at 172.16.1.11. The idea to hold: a push says what to set, and only some ways of pushing say what to remove.

@1
The source of truth stores data, not configuration text. leaf1 is a leaf in Amsterdam with loopback 10.255.1.11, two fabric links at an MTU of 9,216, and two Acme segments: VLAN 100 as VNI 10100 on port swp1, and a staging segment, VLAN 300 as VNI 10102 on port swp5.

@2
A template turns that data into eight lines of configuration, shown here in a vendor-neutral form. Rendering is a pure function, so the same data always produces the same text. It can be unit tested, and rerun at any time without touching a device.

@3
On an ordinary night the automation reads leaf1's running configuration through its API and compares it with the render, line by line. They match, so the diff is empty: the device runs exactly what the source of truth says.

@4
Then the break-glass case. During an incident yesterday, an engineer fighting errors on swp52's optic raised its IS-IS metric to 1000 by hand, so that leaf1 would stop sending traffic over that link. Tonight's diff finds a value on the device that differs from the render. That is drift.

@5
Drift has two possible fixes: put the device back to the intent, or change the intent to match the device, and a person decides which. The optic on swp52 was replaced this morning, so the override is stale, and its owner approves reverting it.

@6
Now a change of intent. Acme retires its staging segment, so the VLAN 300 record is deleted from the source of truth, and the template renders six lines instead of eight. The two staging lines are simply absent, because a template can only describe what exists, never what used to.

@7
The diff from running to intended has three entries: change swp52's metric from 1000 back to 10, and remove the VLAN 300 line and the swp5 line. Two of the three are deletions, and deletions are exactly what the rendered text cannot express.

@8
The automation pushes the six rendered lines in merge mode, which is NETCONF's default edit operation, a gNMI update, or an NVUE patch. The device adds or overwrites every setting the payload names, and leaves everything else alone.

@9
The push reports success, and swp52's metric is back to 10. But VLAN 300 and swp5 are still configured, because nothing in the payload mentioned them. leaf1 keeps advertising an EVPN type 3 route for VNI 10102 with route target 65000 colon 10102, and if that VNI is ever reused for another tenant, port swp5 joins that tenant's segment. Success reported, intent not met: this is the silent failure the pipeline's verify step exists for, because its post-push diff would not be empty.

@10
There are two ways out. Send each deletion explicitly, as a NETCONF delete operation, a gNMI delete path or an NVUE unset. Or push in replace mode, as a NETCONF replace, a gNMI replace or an NVUE config replace, where the payload is the complete configuration and the device deletes anything it does not contain. The automation sends the same six lines as a replace.

@11
leaf1 computed the two deletions itself. VLAN 300 and swp5 are gone, its type 3 route for VNI 10102 is withdrawn, and the diff is empty. Replace is only safe on the parts of the configuration the source of truth fully models, so tools scope it to those sections and merge where another team owns the rest.

@12
An hour later the loop runs again: same data, same render, an empty diff, so nothing is pushed. That idempotency is what lets the loop run continuously, because a non-empty diff is always drift or a pending change, never noise. Now take it to the fleet. Replace faithfully deletes whatever the payload lacks, so an empty source of truth read, rendered and pushed as replace, would be an outage. That is why the pipeline adds a circuit breaker on diff size, refusing any push that deletes more than a threshold until a person approves. The signals to surface: a non-empty post-push diff, a growing drift count, and a change deleting far more than its kind usually does.
