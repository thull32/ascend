@0
On screen is leaf1 in Amsterdam, treated here as a plain IP router, with two spines above it and the two border gateways, gw1 and gw2, above those. acme-web1 has just sent it a packet for 198.51.100.25, a server of the content network, AS 64511. leaf1's routing table holds nine routes: connected subnets, IS-IS routes to the gateways' loopbacks, and BGP routes the gateways advertise. Hold onto one rule, because it is the whole lookup: among every route whose prefix contains the destination, use the one with the longest prefix.

@1
First the destination goes into binary: 11000110, 00110011, 01100100, and 00011001 for the last octet, 25. A slash n route matches when the destination's first n bits equal the prefix's first n bits.

@2
The default route, 0.0.0.0 slash 0, has no bits to compare, so it matches everything. It is a candidate, with length zero: the route of last resort.

@3
Next is 10.1.1.0 slash 24, acme-web1's own subnet. Its first octet is 10 and the destination's is 198, so it fails on the very first bit.

@4
198.51.100.0 slash 24. The destination's first 24 bits are exactly 198.51.100, so it matches with length 24, the best so far, pointing at gw1's loopback, 10.255.1.201.

@5
198.51.100.128 slash 25 is longer, but longer only helps if it matches. Bit 25 is the first bit of the last octet: a 1 in the prefix, because 128 starts with a 1, and a 0 in the destination, because 25 does not. No match.

@6
198.51.100.0 slash 27 covers the 32 addresses ending in 0 to 31, and AS 64511 announces it only over its direct peering with gw2. Its 27 bits are the slash 24 plus three zero bits, and the destination's last octet starts with three zeros too. It matches with length 27 and replaces the slash 24 as the best.

@7
The last four routes all start with 10, so none of them match. The winner is the slash 27, via 10.255.1.202. A slash 27 names 32 addresses, the slash 24 names 256, and the default names all of them, so the longest match is the most precise statement anyone made about where this destination lives.

@8
But the router cannot send anything to 10.255.1.202 yet. That is gw2's loopback, two hops away, on none of leaf1's links, so leaf1 cannot ARP for it. So it looks up the next hop itself, in the same table. The longest match is 10.255.1.202 slash 32, an IS-IS route with two equal-cost next hops: 10.254.1.0 and 10.254.2.0.

@9
Look those up in turn. 10.254.1.0 sits inside the connected slash 31 to spine1, and 10.254.2.0 inside the connected slash 31 to spine2. A connected route ends the recursion, because a neighbour on a directly attached link can be reached with ARP. Four lookups, from a BGP route through an IS-IS route to two ports.

@10
That chain is worked out in the RIB, where routes are chosen, and only when a route changes. The FIB, the table the forwarding chip reads, receives the finished answer: the slash 27 with an ECMP pair, the port to spine1 and the port to spine2. Every packet then costs one hardware lookup; the chip never walks the chain. And because every BGP prefix via gw2 can point at one shared next-hop group, a hierarchical FIB lets an IS-IS change towards gw2 rewrite that one group instead of every prefix.

@11
The flow's hash picks spine1, and the packet heads towards gw2 and on to AS 64511. Notice what the table does under failure: withdraw the slash 27 and the very same lookup falls back to the slash 24 via gw1, and without that to the default. That is the pattern to carry away. Longest-prefix match runs before any idea of best path, so a stray more-specific silently takes traffic from a healthy covering route. And a BGP route is only as good as the IS-IS route under its next hop: if gw2's loopback vanished from IS-IS, the slash 27 would become unusable and traffic would quietly change exit.
