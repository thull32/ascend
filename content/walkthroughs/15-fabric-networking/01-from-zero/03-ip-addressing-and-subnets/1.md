@0
On screen is a corner of Meridian's Amsterdam fabric: spine1, leaf1 below it, and acme-web1, Acme's web server, attached to leaf1. Three addresses, three prefix lengths. acme-web1 is 10.1.1.10, slash 24. Hold onto one idea, because it is the whole of subnet math: an IPv4 address is a 32-bit number, the prefix length says how many of its leading bits name the network, and one AND with the mask separates the two parts. Here the first 24 bits name the network and the last 8 name a host on it.

@1
Write the address in binary, one octet at a time, each at 8 bits. 10 is eight plus two, so zero zero zero zero, one zero one zero. 1 is seven zeros and a one. So 10.1.1.10 is the octets for 10, 1, 1 and 10 again, and the bar on screen marks where the 24 network bits end, between the third octet and the fourth.

@2
Slash 24 as a mask is 24 one-bits followed by 8 zero-bits, which is 255.255.255.0. Wherever the mask has a one, the bit above it belongs to the network part; wherever it has a zero, it belongs to the host part.

@3
Now AND each address bit with the mask bit below it. One AND one is one, and anything AND zero is zero. So the network bits pass straight through, the host bits are cleared, and the result is the network address, 10.1.1.0.

@4
Set every host bit to one instead, and you get the broadcast address, 10.1.1.255. A packet sent there reaches every host on the subnet at once.

@5
Every address in between can go to a host: 10.1.1.1 to 10.1.1.254. That is two to the eighth, minus two, which is 254, because the all-zeros host value names the network and the all-ones value is the broadcast. In Acme's subnet the first host, 10.1.1.1, is the gateway, by convention, and acme-web1 is 10.1.1.10.

@6
The same AND answers the question a host asks for every packet it sends: is the destination on my subnet? 10.1.1.11, ANDed with 255.255.255.0, gives 10.1.1.0, the same network, so acme-web1 delivers it directly. 10.1.2.20 gives 10.1.2.0, a different network, so that packet goes to the default gateway. The lesson on ARP and the default gateway traces that decision.

@7
Now the other end of the picture: leaf1's end of its link to spine1, 10.254.1.1, slash 31. This boundary does not fall between octets. 31 network bits leave a single host bit, the very last one, so the mask is 255.255.255.254: thirty-one ones and then a zero.

@8
The AND clears only that last bit, so the network is 10.254.1.0, slash 31. spine1's address, 10.254.1.0, differs from the leaf's only in that last bit, so its AND gives the same 10.254.1.0. Both ends are on one subnet.

@9
One host bit means only two addresses, 10.254.1.0 and 10.254.1.1. The usual rule, first address for the network and last for the broadcast, would leave none for hosts. But a point-to-point link has exactly two ends and needs neither, so RFC 3021 lets both be used: spine1 takes the even address, 10.254.1.0, and leaf1 the odd one, 10.254.1.1.

@10
The older habit was a slash 30 per link: four addresses, two of them spent on a network and a broadcast that a two-ended link never uses. Amsterdam has 64 fabric links, 4 spines times 16 leaves. As slash 31s they take 128 addresses instead of 256, and every leaf to spine link in Meridian's fabric is numbered this way.

@11
Last, leaf1's loopback, 10.255.1.11, slash 32. All 32 bits are network bits, so the subnet is a single address. It belongs to the router itself rather than to any link, so it stays reachable while any one of leaf1's links is up, which is why Meridian uses loopbacks as router IDs and tunnel endpoints. The table on screen is the pattern to keep. A slash 24 holds 256 addresses and 254 hosts. A slash 30 holds 4, with 2 usable. A slash 31 holds 2, and both are usable on a point-to-point link. A slash 32 holds exactly one: the router. Every row is the same operation, an AND with the mask. The trap is applying the minus-two rule everywhere: right for a server VLAN, wrong for a slash 31, where the common wrong answer is zero usable hosts.
