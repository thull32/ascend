@0
acme-web1, at 10.1.1.10, uploads a backup over HTTPS to acme-cloud1, at 10.200.1.50, in Acme's cloud region. Meridian's fabric links carry 9,216-byte packets and both servers use 1,500. But gw1 reaches the cloud through a VXLAN tunnel across the internet, where packets are limited to 1,500 bytes and the tunnel's own headers take 50, so the tunnel's MTU is 1,450. Here is the weak point to hold onto: the only thing that will ever tell the sender to send smaller packets is one ICMP message from a router it has never heard of, and that message has to survive every filter on the way back.

@1
acme-web1 opens the connection. Its SYN advertises a maximum segment size of 1,460: its 1,500-byte MTU minus 20 bytes of IP header and 20 of TCP. The SYN itself is only 60 bytes, so it crosses the tunnel without trouble.

@2
acme-cloud1 answers with a SYN-ACK that also says 1,460, since its own MTU is 1,500 too, and the final ACK completes the handshake. Neither end knows the tunnel exists, so both now believe 1,460-byte segments are safe.

@3
The upload starts with full-size segments: 1,460 bytes of data in a 1,500-byte packet with the Don't Fragment bit set, which Linux sets on every TCP packet so it can discover the path's MTU. The 9,216-byte fabric links carry it easily, as far as gw1.

@4
gw1 must send it into the 1,450-byte tunnel. The packet is 50 bytes too big and the Don't Fragment bit forbids splitting it, so gw1 drops it and sends acme-web1 an ICMP "fragmentation needed" message, type 3, code 4, naming the next-hop MTU: 1,450. Its counter of those messages sent goes to one.

@5
The message travels back from gw1's loopback and reaches acme-web1, whose host firewall, as hardening, drops every inbound ICMP type except the echo replies that keep ping working. The one message that would have told TCP to shrink its segments to 1,410 bytes is discarded. The firewall's ICMP drop counter goes to one.

@6
With no acknowledgement, TCP resends the same 1,500-byte segment each time its retransmission timeout expires, doubling the timeout each time: 200, 400, 800 and 1,600 milliseconds, so retransmissions leave at 0.2, 0.6, 1.4 and 3 seconds, and the next wait is 3.2 seconds. Every copy dies at gw1, every ICMP it triggers dies at acme-web1, and the two counters climb together to five. Bytes acknowledged: zero.

@7
The connection is established and small packets still pass, but no full-size segment ever arrives, so the upload hangs. Linux keeps retrying for about 15 minutes before giving up, which is the timeout in the logs. To the user it looks like a slow server. The signals are elsewhere: retransmissions on acme-web1, a rising "fragmentation needed" counter on gw1, and the firewall's ICMP drop counter.

@8
The operator turns on MSS clamping on gw1's tunnel. Every TCP SYN and SYN-ACK passing through has its maximum segment size rewritten down to 1,410, the tunnel MTU minus 40 bytes of headers, and its checksum fixed to match. A new connection's SYN leaves acme-web1 saying 1,460 and enters the tunnel saying 1,410.

@9
acme-cloud1's SYN-ACK says 1,460 as well, and gw1 rewrites it to 1,410 on its way back. Each end has now been told the other accepts at most 1,410 bytes per segment, and the clamped counter reads two.

@10
acme-web1's segments are now 1,410 bytes of data plus 40 of headers, 1,450 bytes, exactly the tunnel's MTU. They cross without fragmenting, acknowledgements come back, and the upload runs. No ICMP was needed at all.

@11
Clamping is cheap and lives on the one box that created the problem, but it repairs only TCP, because only TCP carries a segment size, and only connections whose handshake crossed that box. Large UDP packets, such as big DNS answers or another tunnel's traffic, still depend on the ICMP message and still vanish into this hole; QUIC avoids it by probing the path itself. The other fixes are to stop filtering ICMP type 3 code 4, and ICMP version 6 Packet Too Big, since IPv6 routers never fragment, or to let the sender probe the path without trusting ICMP, which on Linux is the TCP MTU probing setting. Remember the signature: connects, then hangs on the first large transfer. A default ping is 84 bytes and proves nothing; ping at full size with Don't Fragment set, 1,472 bytes of data, and the hole shows itself.
