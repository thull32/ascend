@0
On screen is Meridian's Amsterdam fabric with its four spines and two of its sixteen leaves: leaf1, with Acme servers on 10.1.1.0 slash 24 behind it, and leaf3, with 10.1.2.0 slash 24. For now, picture leaf1 routing this traffic as plain IP; the VXLAN tunnels Meridian really uses come later, so every packet towards leaf3 has four equally good uplinks, one per spine. Hold onto one sentence, because it is the whole mechanism: read fields that every packet of a connection shares, hash them, and let the number pick the uplink.

@1
The forwarding table entry for 10.1.2.0 slash 24 points not at one next hop but at an ECMP group of four members, numbered 0 to 3, one per spine. For every packet the forwarding chip must pick one member, and it must pick the same one for every packet of a flow, so that TCP never sees its segments overtake each other on different paths.

@2
Flow A arrives: a PostgreSQL connection from acme-web1, 10.1.1.10 with source port 51517, to acme-db1, 10.1.2.20 on port 5432. The header stack highlights five fields: the source and destination addresses, the protocol, 6 for TCP, and the two ports. That is the 5-tuple, and every packet of this connection carries exactly the same five values.

@3
The chip feeds those five fields through a hash function and gets a 32-bit number, written in hex as B 6 A F 1 3 1 B. Real switch chips use their vendor's own hash, often CRC-based, mixed with a configurable seed; this one stands in for them. What matters is shared by all of them: the same five values always give the same number, and changing any of them gives a different one.

@4
Now the pick. With four members, the hash modulo 4 is simply its lowest two bits. This number ends in hex 1 B, whose lowest two bits are 1 and 1, which is 3, so flow A goes up member 3, the uplink to spine4. Every later packet of flow A hashes the same way and follows it, and spine4 has a single route down to leaf3.

@5
Flow B is a second connection between the same two servers, and only one field differs: source port 51518 instead of 51517. Its hash, 1 5 1 F D D C 6, bears no resemblance to A's. Modulo 4 it gives 2, so B takes spine3. Change one port by one, and a flow lands on an effectively random uplink.

@6
Three more flows: C, a TLS connection; D, another database client; and E, a DNS query over UDP, protocol 17. They hash to members 0, 3 and 1. Five flows now sit on four uplinks as one, one, one and two, with spine4 carrying two. The hash spreads flows evenly only on average, and it never looks at how many bytes a flow carries or how busy an uplink already is.

@7
Now the same connections, A and B, as Meridian really sends them, across the VXLAN overlay. leaf1, the tunnel endpoint at 10.255.1.11, routes each packet into Acme's VNI 50001, decrementing the inner TTL to 63, and wraps it in outer headers addressed to leaf3's endpoint, 10.255.1.13. The uplink is now chosen by the underlay route to that loopback, and the hash reads only the outer headers.

@8
Suppose leaf1 used one fixed outer source port, 4789, for everything. Then every tunnelled flow to leaf3 has the same outer 5-tuple: 10.255.1.11 to 10.255.1.13, UDP, port 4789 to port 4789. Same hash, ending in hex C B, same member 3, and both A and B pile onto spine4: all of the tunnel's traffic on one link of four. Tunnels with no ports at all, such as plain GRE, have exactly this problem unless the chip can hash on the inner headers.

@9
What tunnel endpoints actually do, as RFC 7348 recommends: hash the inner headers and write the result into the outer UDP source port, kept within the dynamic range 49152 to 65535. Flow A's inner hash, the very number we computed at the start, gives port 54043, and flow B's gives 56774. The destination port stays 4789, which is how leaf3 still recognises the packet as VXLAN.

@10
The two outer 5-tuples now differ in one field, so their hashes differ, and the two connections take spine1 and spine4. Every packet of flow A still gets source port 54043, so the tunnel keeps each flow on one path and in order.

@11
So the pattern. ECMP hashing needs no coordination and no per-flow state, and it keeps every flow in order. But it balances flows, not bytes, it is blind to load, and a tunnel must copy the inner flow's entropy into its outer headers or all its traffic collapses onto one path. RoCEv2, on UDP port 4791, uses its source port the same way, which is why AI fabrics care how the network card chooses it.
