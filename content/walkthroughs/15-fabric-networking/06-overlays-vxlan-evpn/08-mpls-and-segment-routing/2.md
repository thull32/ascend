@0
The same backbone and the same Acme packet, from acme-web2 in Singapore to acme-db1 in Amsterdam, but this time the transport label comes from segment routing instead of LDP. The idea to hold: the IGP itself advertises one small number for the far PE, and every router turns it into the same label, so there is no label protocol to run or to keep in step with the IGP.

@1
The Amsterdam PE advertises its loopback, 10.255.1.241 slash 32, in IS-IS with a prefix SID index of 241. Every router reserves the same label range, the segment routing global block, from 16000 to 23999, and adds the index to the base: 16000 plus 241 is 16241. So all four routers agree that label 16241 means towards the Amsterdam PE. That PE left the SID's No-PHP flag clear, which asks the router before it to pop the label: penultimate-hop popping, the job label 3 did with LDP.

@2-3
The tenant layer does not change at all. The Amsterdam PE advertises the VPNv4 route for 10.1.2.0 slash 24 with VPN label 92001 and route target 65000 colon 50001, and the Singapore PE imports it into VRF ACME. It resolves the next hop, 10.255.1.241, to the segment-routed path: push 92001, and above it 16241, towards the Singapore P router.

@4-5
acme-web2's SYN arrives with a time to live of 64. The Singapore PE looks it up in VRF ACME, decrements the time to live to 63, and pushes the same two-label stack as before, except that the transport label is now 16241. Still 8 bytes, still EtherType 8847.

@6-7
At the Singapore P router comes the visible difference. It reads the top label, 16241, and swaps it for 16241, the same value, decrementing the label's time to live to 62. The outgoing label is the next router's block base plus 241, and with matching blocks that is 16241 again. A label that means the same thing on every router is the point of segment routing: IS-IS carries it, so no separate protocol has to agree it hop by hop.

@8
Across the long-haul circuit: about 10,500 kilometres and roughly 52.5 milliseconds one way, carrying 16241 over 92001.

@9-10
The Amsterdam P router is the penultimate hop. Because the No-PHP flag was clear, it pops 16241 and copies its time to live, 61, into the VPN label now on top. Only 92001 crosses the last link, with its bottom-of-stack bit set, so IP follows.

@11-12
The Amsterdam PE maps 92001 to VRF ACME and routes the packet to the connected subnet. acme-db1 receives an ordinary IPv4 packet with a time to live of 60, exactly as with LDP.

@13
Same outcome, one fewer protocol. The comparison table now says the core needs MPLS and IS-IS with segment routing, and no LDP. The index is global across the whole IGP domain, but the label is global only if every router uses the same block, which is why operators standardise it. With a mismatched block the path still works, because each router computes its neighbour's label from the block that neighbour advertised; the labels on the wire just stop matching from hop to hop. Against VXLAN the cost is unchanged: 8 bytes here against 50, and a core that must run MPLS rather than plain IP.
