@0
HTTP/1.1 keeps connections open by default, and this picture shows what that saves. A fresh HTTPS connection pays the TCP handshake, one round trip, and then this: a TLS 1.3 handshake, another round trip, all before the first request byte. Keep-alive pays both once per connection instead of once per request.

@1
The client sends its ClientHello: the cipher suites it supports, its key share, and the server name it wants.

@2
The server replies with its own key share, and from here everything is encrypted: the certificate chain, a signature proving it holds the private key, and its Finished message.

@3
The client verifies the certificate chain, the name and the validity dates, sends its Finished, and can send its HTTP request in the same flight.

@4
The encrypted response comes back. TLS cost one round trip before data could flow.

@5
So a new connection costs two round trips of setup before the request even leaves, one for TCP and one for TLS. The lesson measured it with curl against example dot com: the first request took 212 milliseconds, including 66 for TCP and 54 for TLS. The second request, on the reused connection, took 67 milliseconds. Reuse removed 145 of the 212. The catch is idle timeouts: if the server closes an idle connection just as the client reuses it, you get a 502, so the client's idle timeout must be shorter than the server's.
