@0
Clients, a load balancer, and three servers. Round robin is the simplest policy there is: each request goes to the next backend in the rotation, whatever state that backend is in. Watch the rotation, and notice what the balancer never looks at.

@1-2
Request 1 arrives, and goes to server 1.

@3-6
Request 2 goes to server 2, and request 3 to server 3.

@7-10
Then the rotation wraps around: request 4 goes back to server 1, and request 5 to server 2. At no point did the balancer ask how busy any server was, or how long its last request took.

@11
That is both its strength and its flaw. It is simple and stateless, and health checks take failed backends out of the rotation, while weights handle backends of different sizes. But a server that has slowed down still gets exactly its share. The lesson's numbers: 20 backends share 1,000 requests a second at 20 milliseconds each, and one degrades to 100 milliseconds. Round robin still sends it 50 requests a second, so 5 percent of all requests are slow, and one sick machine sets the service's 95th percentile. Least connections fixes that, and it is the next picture.
