@0
A user in Tokyo, an edge point of presence in Tokyo, and the origin server in Virginia, on the other side of the Pacific. A CDN is a distributed cache with a routing layer in front. The first request for an object pays the long trip once; everyone nearby after that is served locally.

@1
User A asks for a video segment, seg42. DNS or anycast routing has already sent them to the nearest point of presence.

@2
The edge does not have it: a cache miss. It fetches the segment from the origin, across a round trip of about 150 milliseconds.

@3
The origin answers, and its Cache-Control header says the edge may keep the object for a day, a max age of 86,400 seconds. Whether a CDN helps at all is decided by headers like this one.

@4
User A gets the bytes in about 160 milliseconds, marked as a miss. The edge now holds a copy.

@5
User B, also in Tokyo, asks for the same segment.

@6
This time it is a hit, served from the edge in about 5 milliseconds, and the origin never sees the request.

@7
Three things decide how well this works. The hit ratio is what you optimise, and miss ratios multiply down the tiers, so 90 percent at the edge with a shield behind it can leave the origin only 2 percent of requests. The cache key, the URL plus any headers the response varies on, decides whether two requests share an entry. And invalidation is done by purging or, better, by versioned URLs that never need purging. Netflix's Open Connect goes further than pulling on a miss: its appliances sit inside ISPs and are filled with the catalogue ahead of time, during off-peak hours.
