@0
Four layers, stacked: application, transport, network and link. The rule that ties them together is encapsulation. Each layer takes whatever the layer above handed it, treats it as an opaque payload, and puts its own header in front. Going down the stack on the sender, the packet grows. Going up on the receiver, each layer strips exactly its own header and hands the rest up.

@1
It starts with the application's bytes: an HTTP request, get slash index dot html. So far there is one header, and nothing is on the wire yet.

@2
TCP wraps it. Its header carries the ports, source port 51000 and destination port 443, which say which process on each host owns the bytes. It also carries sequence and acknowledgement numbers for ordering and reliability, and the flags. The unit is now called a segment.

@3
IP wraps the segment. Its header holds the addresses routers use to move it across networks, source 10.0.0.5 and destination 93.184.216.34, plus a time to live, and a protocol field saying the payload is TCP. That protocol field is how the receiver knows which layer gets the rest. The unit is now a packet.

@4
Ethernet wraps the packet in a frame. Its header holds MAC addresses for the next hop only, here the gateway, and a type field saying IPv4 follows. A checksum trails the frame. The whole thing must fit in an MTU of 1,500 bytes, and now it goes out as bits over copper, fibre or radio.

@5
Four headers, nested like envelopes, each with one field that says who gets the payload: the Ethernet type, the IP protocol, the port. Each device works at one layer. A router works at the network layer, rewriting the link header on every hop and leaving IP mostly alone. A switch works at the link layer. A load balancer works at transport or application. And on the receiving host the process runs in reverse: read one field, strip one header, hand the rest up, until the bytes land in the right socket.
