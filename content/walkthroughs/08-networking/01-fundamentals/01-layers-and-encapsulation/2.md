@0
IP routing has picked the next hop's IP address, but the Ethernet header needs a MAC address, and nothing on the screen knows it yet. Host A, at 10.0.0.5, wants to talk to host B at 10.0.0.9 on the same link, through a switch, with host C at 10.0.0.7 listening too. ARP is the protocol that turns a local IP address into a MAC, and it must run before the first IP packet to that neighbour can leave.

@1
A broadcasts a question to the all-ones MAC address, every f: who has 10.0.0.9? Tell 10.0.0.5.

@2
A broadcast reaches every host on the segment. Host C receives it, sees that 10.0.0.9 is not its address, and ignores it.

@3
Host B receives the same broadcast and recognises its own IP.

@4
B replies directly to A, not as a broadcast: 10.0.0.9 is at this MAC address, the one ending in 11, 00, 09. A caches the answer and can finally put B's MAC in the Ethernet header and send the IP packet.

@5
That cache is why only the first packet to a new neighbour pays for the lookup. Two more things to know. A host can send an unsolicited, gratuitous ARP to announce that an address has moved, which is how failover between routers takes over a shared address. And ARP has no authentication, so anyone on the segment can answer for an address that is not theirs. That is ARP spoofing, and it is why an untrusted network needs encryption at the layers above.
