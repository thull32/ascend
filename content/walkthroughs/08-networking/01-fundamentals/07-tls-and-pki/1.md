@0
A client and a server, with a TCP connection already open between them. TLS 1.3 needs one round trip before encrypted application data can flow; TLS 1.2 needed two. The trick that saves the round trip: the client guesses which key exchange the server will accept, and sends its half of it in the very first message.

@1
The ClientHello goes out in plaintext. It lists the cipher suites the client supports, carries its ephemeral Diffie-Hellman key share, and names the server it wants, the SNI, so a server hosting many names can pick the right certificate.

@2
The ServerHello picks a suite and returns the server's own key share. Now both sides can compute the same secret, so everything after the ServerHello is already encrypted: the certificate chain, a signature over the whole handshake made with the certificate's private key, and the Finished message. That signature is the proof that the server holds the key, not merely a copy of a public certificate.

@3
The client checks the chain from the leaf through the intermediate up to a root it trusts, checks that the name matches and that the dates are valid, then sends its own Finished, and in the same flight its HTTP request. The key exchange is ephemeral, which gives forward secrecy: stealing the certificate's private key later does not decrypt traffic recorded today.

@4
The encrypted response comes back. Total cost: one round trip before data. A resumed session can even send data in the first flight, zero round trips, but that early data can be replayed, so it is only safe for requests that are harmless to repeat.

@5
Add it up for HTTPS over TCP: one round trip for the TCP handshake and one for TLS before the request can even leave, so at a 100 millisecond round trip the first response byte arrives after about 300 milliseconds. QUIC folds the transport and crypto handshakes into one round trip, and a reused connection skips both, which is why reuse beats any handshake optimisation. And remember where TLS incidents actually come from: rarely the cryptography, almost always chains, names, clocks and round trips.
