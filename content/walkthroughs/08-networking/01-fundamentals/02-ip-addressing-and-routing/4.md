@0
There are about 4.3 billion IPv4 addresses and far more devices, so most hosts share one public address through network address translation. On screen: a laptop at 192.168.1.20, a NAT router whose public address is 203.0.113.1, and a web server at 93.184.216.34. The router's job is to rewrite source addresses and ports on the way out, remember each rewrite, and reverse it on the way back.

@1
The laptop sends from 192.168.1.20, port 51000, to the server on port 443. That is a private address, and no router on the internet will carry a reply to it.

@2
So the NAT router rewrites the source to its own public address and a fresh port: 203.0.113.1, port 40001. It records the pair in its table, laptop port 51000 on one side, public port 40001 on the other. And because the TCP checksum covers both addresses, it recomputes that too, which is why a box that is supposed to work at the IP layer has to parse TCP.

@3
The server sees only the public address. It replies to 203.0.113.1, port 40001.

@4
The router looks up port 40001 in its table, finds the laptop's entry, and rewrites the destination back to 192.168.1.20, port 51000. The laptop never knows any of this happened.

@5
Every consequence of NAT follows from that table. Nothing outside can start a connection inward, because only an outbound packet creates a row, so inbound connections need port forwarding or hole punching, the way WebRTC does it. Idle rows expire, so long-lived idle connections need keepalives. And IPv6, with enough addresses for every device, removes the need for translation entirely.
