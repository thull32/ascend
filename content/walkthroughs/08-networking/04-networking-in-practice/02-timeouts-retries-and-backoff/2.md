@0
A gRPC channel, its retry budget, and a server that is about to be hard down. The budget is a token bucket that outcomes fill instead of the clock. It starts full, at 10 tokens. Every failed attempt removes 1, every success adds a tenth, and a retry may be sent only while the bucket holds more than half, more than 5. Hold onto that last rule, because it is what makes retries switch themselves off.

@1
Call 1, attempt 1: the server answers UNAVAILABLE. The failure costs a token, leaving 9, still above 5, so a retry is allowed.

@2
Attempt 2 fails too. 8 tokens left, still above 5, so the channel may retry again.

@3
Attempt 3 fails, leaving 7. The budget would allow another retry, but the policy's maximum of 3 attempts is reached, so call 1 fails.

@4
Call 2, attempt 1 fails: 6 tokens left, still above 5, so one retry is allowed.

@5
The retry fails and the bucket falls to 5. Five is not above 5, so there are no more retries, and call 2 fails after 2 attempts.

@6
Call 3 makes one attempt, fails, and leaves 4 tokens. The budget is below the threshold, so it is not retried at all. Retries have switched themselves off after just 3 of them.

@7
Every later call makes exactly one attempt, and the bucket falls to 0 and stays there. The outage now adds no extra load: amplification tends to exactly one times, where a fixed three attempts per call would have tripled the traffic on a server that is already down.

@8
Now the server heals. Each success adds only a tenth of a token, so it takes 51 successes to lift the bucket from 0 to 5.1, just above 5, before retries resume. The budget hands retries back only after the dependency has proved itself.

@9
In a partial outage, where a fraction f of attempts fail, the tokens drift by a tenth of one minus f, minus f, per attempt. That is negative once f exceeds about 9 percent. So retries switch themselves off exactly in the regime where they stop helping and start adding load.

@10
A per-call attempt count multiplies load by the attempt count in an outage. A budget bounds retries as a fraction of traffic, costs one number per server, and lets a healthy system retry freely. Finagle, Linkerd and Envoy budget the same way, as a percentage of requests with a small floor, so that a low-traffic client can still retry at all.
