@0
Two bytes. The top row, a, is the byte that was sent: 1 0 1 1 0 0 1 0, which is 178. The bottom row, b, is what arrived: 1 0 0 1 0 1 1 0, which is 150. Something on the way flipped some bits. The visualisation will combine the two bytes three ways, column by column, and the third way is the one this lesson is built on.

@1-10
First, AND: a result bit is 1 only when both bits are 1. Working from the rightmost column to the left, only the columns where both bytes hold a 1 survive. The result is 1 0 0 1 0 0 1 0, which is 146. AND is a mask: it keeps only the bits set in both.

@11-20
Next, OR: a result bit is 1 when either bit is 1. Column by column again, and the result is 1 0 1 1 0 1 1 0, which is 182. OR turns bits on without disturbing the others.

@21
Now XOR: a result bit is 1 exactly when the two bits differ. For a sent byte and a received byte, that is the question that matters: which bits changed?

@22-23
Bits 0 and 1 are the same in both bytes, so XOR gives 0 for each.

@24
Bit 2 differs: a has 0, b has 1. That bit flipped in transit.

@25-26
Bits 3 and 4 agree. Zero, zero.

@27
Bit 5 differs: a has 1, b has 0. The second flip.

@28-29
Bits 6 and 7 agree.

@30
So a XOR b is 0 0 1 0 0 1 0 0, which is 36. This is the error pattern: a 1 exactly where a bit flipped, two flips here. And here is the catch for parity. Both bytes have four 1s, so an even-parity check passes, and the corruption goes undetected. Parity catches every odd number of flips and no even number.

@31
The three results: 146, 182 and 36, each computed for all eight columns in parallel by the hardware. Think in error patterns from here on. A check detects an error exactly when it treats the error pattern as different from zero. Parity is blind to any pattern with an even number of 1s, and every stronger scheme in this lesson, the Internet checksum and CRCs, is built on the same XOR arithmetic.
