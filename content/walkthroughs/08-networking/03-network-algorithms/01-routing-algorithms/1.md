@0
Five routers, A to E, and six links with costs: A to B costs 1, A to C 4, B to C 2, B to D 5, C to D 1, and D to E 3. Every OSPF router holds this same map and runs Dijkstra from itself. This is A's run. The rule to hold: always settle the closest unsettled router, because with non-negative costs its distance can never improve.

@1
A is settled at distance 0.

@2-3
A relaxes its links. B becomes 1, and C becomes 4. Both go into the heap.

@4
The closest is B, at 1, so B is settled.

@5
From B, C costs 1 plus 2, which is 3, better than the 4 A offered directly. C drops to 3, now reached through B. The old entry, C at 4, stays in the heap as a stale entry that will be skipped later.

@6
From B, D costs 1 plus 5, which is 6.

@7
The closest is now C, at 3, so C is settled.

@8
From C, D costs 3 plus 1, which is 4, better than 6. That is the second improvement, and both times the route with fewer hops was not the cheapest.

@9
The stale entry C at 4 surfaces first; C is already settled, so it is discarded. Then D is settled at 4.

@10
From D, E costs 4 plus 3, which is 7.

@11
The stale D at 6 is discarded the same way, and E is settled at 7. Everything is settled.

@12
The shortest-path tree is highlighted: A to B, B to C, C to D, D to E. A's forwarding table needs only the first hop of each path, and every destination goes via B. Because every router runs the same algorithm on the same database, the trees agree, so when A hands a packet for E to B, B's own tree sends it on towards C. That agreement is what makes forwarding loop-free once everyone has converged. And the algorithm is cheap: with a binary heap it is order of V plus E, times log V.
