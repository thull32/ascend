@0
Between autonomous systems, nobody will flood their topology to a competitor, and there is no common metric. BGP keeps distance-vector's structure and fixes its loop problem with one change: each advertisement carries the list of autonomous systems it has passed through. On screen, an origin network at AS 64500, a transit provider, an intermediate ISP, and your ISP.

@1
The origin announces its prefix, 198.51.100.0 slash 24, with an AS path containing only itself: 64500.

@2
The transit provider, AS 3356, prepends its own number, so the path reads 3356, 64500, and re-announces it only where its export policy allows. Routes learned from peers and providers go only to paying customers.

@3
AS 7018 prepends itself in turn, and your ISP receives the route with a three-AS path. If it also heard the prefix over a direct peering with 64500, it would compare the two, and policy decides first: local preference, then path length.

@4
Here is why the path fixes count to infinity: an AS that sees its own number in an incoming path discards the route, so the path itself proves where the route has been. The decision order is local preference, then AS path length, then origin, then the multi-exit discriminator, and so on. Large content networks peer directly with ISPs so the path is a single hop, cheaper and faster. And since BGP believes what it is told, route leaks and hijacks spread the same way, which RPKI exists to mitigate.
