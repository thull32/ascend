@0
MongoDB indexes are B-trees, with the same rules as Postgres indexes. The index maps a field value to the document's record id; without it, a find reads every document in the collection. On screen: a root page with separators 20 and 40, and three leaves holding 5, 10 and 15; 20, 25 and 30; and 40, 45 and 50. Every leaf sits at the same depth.

@1
Look up 45. Read the root: 45 is at least 40, so follow the pointer to child 3. One page read.

@2
Read leaf 3 and binary-search it: 45 is found. Two page reads, and the root is always cached, so one disk read. With a fan-out of around 300, a tree four levels deep indexes billions of entries.

@3
A range scan from 25 to 45 descends once, to leaf 2, then follows the sibling pointer to leaf 3. Linked leaves are why sorted and range queries read sequentially, and why an index can hand back documents already in sort order.

@4
Insert 42. It routes to leaf 3, which now holds 40, 42, 45 and 50: four keys, its capacity. Nothing else changes.

@5
Insert 47. Leaf 3 would hold 5 keys, one over capacity, so the page must split.

@6
Half the keys move to a new leaf 4, which holds 47 and 50, and its smallest key, 47, is promoted into the root as a separator. If the root overflowed, it would split too and the tree would grow one level, from the top.

@7
Insert 12. It routes to leaf 1, which has room, and becomes 5, 10, 12 and 15.

@8
The failure modes. A split writes several pages, so a crash in the middle needs the write-ahead log to keep the tree consistent. Random inserts leave pages around 70 percent full. And a hot rightmost leaf serialises inserts on one page latch.

@9
Fast reads and in-order scans, paid for with a whole page rewritten per change. For compound indexes, MongoDB's field-order rule is ESR: equality fields first, then the sort field, then the range. Put the range before the sort, and the index can no longer return documents in sort order, so the server sorts in memory instead. It is a heuristic, though: when the range is very selective, putting it before the sort field can win. Check with explain on production-shaped data.
