@0
Write shape is where storage engines genuinely differ. A B-tree updates pages in place: cheap, predictable reads, and a page write plus a log record for every random write. A log-structured merge tree turns every write into a sequential append, and pays later, in compaction and in reads that check several files. Here is that second engine at work.

@1-2
Puts arrive: a equals 1, b equals 2, c equals 3, then a equals 4. Each is appended to the log and inserted into the memtable, a sorted structure in memory. The overwrite of a just replaces it in memory. No disk seeks.

@3-4
Put d equals 5 fills the memtable, and it is flushed as one immutable sorted file, SST-1, in a single sequential write. A fresh memtable takes new writes.

@5-6
Put b equals 9 and delete c. The delete is a tombstone, another write. A read for c finds the tombstone in the memtable first, so c is not found, even though SST-1 still holds c equals 3.

@7
A read for a misses the memtable, passes SST-1's Bloom filter, and costs one disk read: a equals 4.

@8
Two more puts, and a second flush, SST-2. The two files overlap, so a read for b must check both, newest first. Every flush adds read amplification.

@9-10
Compaction merges them into one level 1 file in the background: b is 9, and c and its tombstone are gone. Now a read for b touches one file. Write cost now, cheaper reads later.

@11
The failure modes. Compaction competes with foreground input and output and can fall behind, and then writes stall. Tombstones must survive long enough or deleted keys come back. And repeated writes to one key waste space until compaction.

@12
So if the dominant operation is a high-rate write to a known key, this picture is the argument for Cassandra or DynamoDB: sustained write throughput far above a B-tree's. If writes are modest and queries are varied, it is an argument against. Start from the default, one Postgres, and let a checkable sentence about the access pattern, like a known-key write at 40,000 a second with no reads except by key, choose the store for you.
