@0
A load balancer, nine stable instances, one canary, and a metrics panel that compares them. A canary release sends a small slice of real traffic to the new version, compares its metrics against the stable version serving the rest, and only then widens the slice. For a schema migration, the new version is the read new flag: read from the new columns instead of the old one.

@1
Version 2 is deployed to the canary instance. It gets no traffic yet. The stable instances run at a 0.1 percent error rate.

@2
Stage one: 10 percent of traffic goes to the canary. If version 2 is broken, at most one user in ten sees it, and only briefly.

@3
The analysis compares both versions over the same window: error rate, the 99th percentile latency, saturation. The canary is within tolerance, so the gate passes and the share widens.

@4
Stage two: 50 percent. Now the canary sees enough traffic to hit a code path that 10 percent never exercised, and its errors and latency jump.

@5
The gate fails: the canary's error rate is far above stable's 0.1 percent over the same window. Because stable is serving the other half at the same moment, the comparison isolates the release from ambient noise.

@6
Automatic rollback: the canary's weight goes to zero, and the load balancer sends everything to stable. The bad release reached a fraction of users for one window, not everyone until a human noticed.

@7-8
Version 2.1 starts again at 10 percent, then 50, and passes both times. Every promotion repeats the gate. And because it compares like with like, a traffic spike that slows both versions does not fail the canary.

@9
Promotion: all ten instances run version 2.1, which becomes the stable version.

@10
The pitfalls. With only 5 canary requests in a window there may be too few samples to see a 1 percent error rate, so the gate needs a minimum count, not just a rate. A canary that only gets easy traffic passes and then fails at 100 percent. And stateful sessions need sticky routing.

@11
The trade: a small blast radius, and problems only real traffic reveals, caught early, at the cost of slower rollouts and two versions live for hours, so the schema must stay compatible with both. For data, flags make the read switch instant and reversible. Each one is temporary, with an owner and a removal date.
