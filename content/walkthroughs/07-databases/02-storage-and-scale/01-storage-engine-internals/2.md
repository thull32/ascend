@0
A log-structured merge tree inverts the B-tree. Writes go to a sorted table in memory, the memtable, which is flushed as an immutable sorted file and later merged with others. Every disk write is sequential. The price is that a read may have to look in several places. On screen: the log, a memtable that holds 4 keys, level 0 files, and a merged level 1.

@1
Put a equals 1, put b equals 2. Each is appended to the log for crash safety, and inserted into the memtable, a sorted structure like a skip list. Under a millisecond, no disk seeks.

@2
Put c equals 3, then a equals 4. Overwriting a in the memtable just replaces the value in memory, while the log still has both records.

@3
Put d equals 5, and the memtable is full.

@4
Flush. The memtable is written as one sorted, immutable file, SST-1, with a sparse index and a Bloom filter, in a single sequential write. The log segment can be dropped, and a fresh memtable takes new writes.

@5
Put b equals 9, and delete c. SST-1 is never touched: it is immutable. The delete is a new write too, a tombstone for c. The real removal happens at compaction.

@6
Read c. The memtable is checked first and holds the tombstone, so the answer is not found, even though SST-1 still contains c equals 3. The newest level wins.

@7
Read a. It is not in the memtable. SST-1's Bloom filter says maybe, the index points to the right block, and one disk read returns a equals 4. Bloom filters let a read skip files that cannot hold the key.

@8
Two more puts fill the memtable, and it flushes as SST-2. Level 0 files overlap in key range: both hold b and c. So a read for b must check SST-2 before SST-1. Read amplification grows with every flush.

@9
Compaction: a background merge sort of the two files into one non-overlapping level 1 file. Newer values win, so b is 9. And the tombstone removes both c equals 3 and itself, since nothing older remains.

@10
Read b now: the memtable is empty, level 0 is empty, and one level 1 file answers b equals 9. Compaction pays a write cost now to make every later read cheaper.

@11
The failure modes. Compaction competes with foreground input and output, and if it falls behind, level 0 piles up and writes stall. Tombstones must survive until they reach the bottom level, or deleted keys come back. And a burst of writes to one key wastes space until compaction.

@12
To change 100 bytes, a B-tree rewrites an 8 kibibyte page in place. An LSM tree writes the 100 bytes to its log, then rewrites them sequentially each time compaction merges them down a level. LSM trees win on sustained writes and SSD endurance; B-trees win on point reads and range scans that must be fast the first time. RocksDB, LevelDB, Cassandra and HBase are all log-structured.
