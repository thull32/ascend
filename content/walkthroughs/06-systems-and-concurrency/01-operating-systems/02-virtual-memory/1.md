@0
The process sees 8 virtual pages, but the machine has only 3 physical frames. The page table on screen maps each virtual page number to a physical frame number, or marks it not present. The process is about to touch pages in this order: 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5. When a frame is needed and none is free, the rule is first in, first out: evict the page that was loaded earliest.

@1-2
Access page 1. Its entry is not present, so the memory management unit raises a page fault and the operating system takes over. It loads page 1 into frame 0, marks the entry present, and retries the instruction, which now succeeds.

@3-6
Pages 2 and 3 fault the same way and land in frames 1 and 2. All three frames are now full, after three faults.

@7-9
Page 4 faults, and there is no free frame. First in, first out picks page 1, the earliest loaded, evicts it from frame 0, writing it back first if it was modified, and marks its entry not present. Page 4 moves into frame 0.

@10-15
And now the cost of that choice. The next access is page 1, which was just thrown out, so it faults and evicts page 2. Then page 2 is needed, faults, and evicts page 3. Each eviction removes the page that is about to be wanted.

@16-18
Page 5 faults too, and the oldest load is now page 4, which leaves frame 0 for page 5.

@19-20
Finally, two hits: pages 1 and 2 are present, in frames 1 and 2, so the hardware translates the addresses without involving the operating system at all.

@21-26
Page 3 faults and evicts page 1, the oldest load, even though it was used two steps ago. Page 4 faults and evicts page 2.

@27
Page 5 is still in frame 0. A hit.

@28
Twelve accesses: 3 hits, 9 faults, 6 evictions. A hit is a table lookup the hardware does for you; a fault means the operating system reads from disk, which is thousands of times slower. Notice what first in, first out kept doing: throwing out the page loaded longest ago, regardless of whether it was just used.
