@0
On the left are the stacks, one per thread; on the right, the process's heap. The rule to hold onto: a stack frame belongs to the thread that pushed it, while everything on the heap is shared by every thread in the process. For now there is one thread. main has just started on thread 1, and its locals, n equal to 3 and list, which is still null, live in main's frame.

@1
main calls build with n. A new frame goes on top of thread 1's stack, with its own n, its own head and a loop counter i.

@2-4
The loop runs three times. Each iteration allocates a node on the heap, first at address 1000 in hex holding 4, then at 1020 holding 8, then at 1040 holding 15, and head moves to the newest one. None of these nodes belongs to build's frame.

@5
build returns head. Its frame is popped and its locals vanish, but all three nodes survive, because heap memory is released by an explicit free, not by leaving a scope. main's list now holds address 1040.

@6
Now main starts a second thread, running a worker function with the list. Thread 2 gets a stack of its own, a separate region with its own frames, and its first frame holds p: a copy of the pointer, 1040, the same node main's list points at. Copying a pointer copies the address, not the object.

@7
On thread 2, the worker calls sum, which walks all three nodes through the shared heap and gets a total of 27. sum's locals live on thread 2's stack, where thread 1 cannot see them.

@8
Meanwhile thread 1 calls print with the list. Both threads now have a frame with a local named p, and they never collide, because each lives on its own thread's stack. Both point at the same node.

@9
Thread 2 writes through its pointer, and the node at 1040 now holds 16 instead of 15. There is only one heap, so thread 1's print sees the new value or the old one, depending on timing. With no lock between them, this read and this write are a data race.

@10
sum returns on thread 2 and print returns on thread 1. Each return pops a frame from its own thread's stack only, and the heap is untouched.

@11
The worker returns and thread 2 exits. Its whole stack is released at once, but the nodes it pointed at stay, because they belong to the heap, not to the thread.

@12-14
main joins thread 2, so nothing else can still be reading the list, and then frees the nodes one at a time: 1040, then 1020, then 1000, advancing list before each free so it never loses its path to the rest.

@15
main returns. Two threads, two private stacks, one shared heap. That shared heap is what makes threads cheap to communicate through, since passing a pointer is enough, and it is exactly what makes races possible.
