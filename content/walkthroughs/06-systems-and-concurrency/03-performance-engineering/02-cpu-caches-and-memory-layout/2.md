@0
The same 8 by 8 matrix, stored row by row, with the same 4 line cache. The only change is the order: now we walk down the columns. Element 0, then 8, then 16, and so on to 56, and then back up to the top of the next column. Forty accesses again. Before it plays, how many hits do you expect?

@1-4
Element 0 is a miss, which brings in line 0. Element 8 is in line 1, another miss. Then 16 in line 2, and 24 in line 3. Four misses, and the cache is full, but we have used only one element from each line.

@5-12
Element 32 is in line 4. No room, so line 0 is evicted, the least recently used. Then 40 evicts line 1, 48 evicts line 2, and 56 evicts line 3. One column, eight lines touched, and a cache that holds four.

@13-20
Now the second column starts with element 1. It lives in line 0, which we fetched at the very start and then evicted four steps ago. A miss. So is element 9 in line 1, 17 in line 2, and 25 in line 3. Each line was thrown out just before it would have been reused.

@21-44
And so it goes, column after column. Every access is a miss, every miss evicts the line the traversal will need again shortly.

@45-76
The fourth and fifth columns are the same story: fetch a line, read one element, evict it.

@77
Forty accesses: zero hits, forty misses. Each column touches eight lines, the cache holds four, and least recently used evicts each line just before it would be reused. Same data, same number of elements, and every line fetched five times instead of once. Locality, not element count, sets the cost. On the lesson's machine a cache hit is about 0.9 nanoseconds and a trip to memory about 100, so access order alone can make a loop many times slower.
