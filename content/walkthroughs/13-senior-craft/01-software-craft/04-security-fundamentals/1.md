@0
Two hosts, a client and a server, and a session cookie that must never cross the wire in the clear. TLS 1.3 gets there in one round trip and then encrypts everything that follows. TLS 1.2 needed two.

@1
The client opens with a ClientHello. It lists the cipher suites it supports, includes its own share of a fresh key exchange, and names the server it wants, so the server can pick the right certificate.

@2
The server answers with a ServerHello: it picks the suite and sends its own key share. Both sides can now derive a handshake secret, so everything after the ServerHello is already encrypted: the certificate chain, a signature proving the server holds the private key, and its Finished message.

@3
The client verifies the chain from a trusted root, through an intermediate, to the leaf certificate, and checks the name and the validity dates. Then it sends its own Finished and, in the same flight, its HTTP request. That request, Cookie header included, is encrypted. The key exchange gives forward secrecy, so a key stolen later cannot decrypt this session.

@4
The encrypted response comes back. Total cost: one round trip before any data. A resumed session can send data with zero round trips, with replay caveats.

@5
Counting the TCP handshake as well, HTTPS costs two round trips before the first byte, and QUIC folds them into one. The encryption is only half the story: Ascend marks its cookies Secure in production and sends HSTS, so the browser never tries plain HTTP first, and the cookie never travels without this handshake in front of it.
