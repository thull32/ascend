@0
One login, followed through Ascend. On screen: the browser, the platform edge, the middleware stack, the route handler in the api crate, AuthService in the core crate, and Postgres. Below is the middleware list, outermost first, as app.rs assembles it. Hold onto one idea: each hop is a boundary with its own vocabulary. HTTP at the edge and in the middleware, typed requests in the handler, domain types in the core crate, SQL behind it.

@1
The browser posts to the login route. The platform edge terminates TLS and forwards the request to Ascend, a single binary.

@2
The outermost layers run first, rows 1 to 3. A client-supplied request ID survives only if it is a UUID, one is set if none survived, and it is copied onto the response.

@3
Rows 4 to 6. The tracing span opens next; it reads the request ID, so it has to come after. Then the metrics timer, which sits outside the timeout, so a request cut off at 240 seconds is still recorded as a 503. Then the timeout itself.

@4
Rows 7 to 12. Compression and security headers wrap everything, error pages included. Then the router sends API requests through the body limit, the per-IP rate limit and the CSRF check, with the rate limit first, so a flood of forged requests still spends its budget.

@5
Row 13: the route matches, and stamp route records its template for the metrics layer. The handler's extractor parses the JSON body into a typed request. This is where HTTP vocabulary stops.

@6
The handler calls the core crate in domain terms: AuthService login, with an email and a password. The core crate has no HTTP types at all. It validates the input, normalises the email and verifies the password.

@7
Postgres sits behind the core crate. The service creates a session row.

@8
The service returns the user and a new session, a token with an expiry. It does not know what a cookie is.

@9
The adapter decides that: the token travels in an HttpOnly, SameSite Lax cookie, and any error would be mapped to a status code in one place, the api crate's error module. On the way out, the response passes back through every layer: headers added, body compressed, status recorded.

@10
So each boundary translates. The edge speaks TLS, the middleware speaks HTTP, the handler speaks requests and cookies, and the core speaks users and sessions. Move a layer, and behaviour changes, which is why their order is a design decision and not an accident of the code.
