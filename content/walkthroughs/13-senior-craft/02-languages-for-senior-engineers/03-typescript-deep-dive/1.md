@0
Three lanes: the one JavaScript thread, and two host threads, one for timers and one for the network. Below them, three queues: the call stack, the microtask queue and the macrotask queue. The program logs A, sets a zero-millisecond timer, starts a fetch, attaches a callback to an already-resolved promise, and logs B. Hold onto one fact: the host can wait on timers and sockets in parallel, but every callback runs on the one JavaScript thread.

@1
The script starts, and logging A runs synchronously.

@2
Setting the timer hands it to the host and returns immediately. The callback is not queued yet: the timer has to expire first, and even zero milliseconds means "after the current script".

@3
The fetch starts a request on the host's network thread and returns a pending promise. The JavaScript thread never blocks waiting for the socket.

@4
The promise is already settled, so its callback, m, goes straight into the microtask queue.

@5
Logging B runs. By now the timer has expired and its callback sits in the macrotask queue, but nothing queued has run, because the script is still on the stack.

@6
The script finishes and the stack is empty. Now the event loop looks at its queues, and it always takes microtasks first.

@7
It drains the microtask queue: m runs and logs C. Any microtasks m queued would run now too, before any macrotask.

@8
Then it takes one macrotask: the timer callback runs and logs D. After every macrotask, the loop drains microtasks again.

@9-10
The response arrives on the network thread, and its handler is queued. The JavaScript thread was idle, not blocked. The handler runs and logs E.

@11
Output: A, B, C, D, E. The rule is the current script, then all microtasks, then one macrotask, then repeat. And because one thread runs every callback, a 200 millisecond synchronous loop delays every timer, click and response by 200 milliseconds. Await gives you interleaving, not parallelism. Move processor-heavy work to a Worker, which is why Ascend runs learner code in Web Workers and stops a runaway loop by terminating the worker from the main thread.
