@0
A sorted list: 1, 3, 3, 3, 7, 9. We want the first index whose value is at least 3, which is exactly what bisect left returns. Ask the question "is this value at least 3?" at every position, and the answers run false, then true, true, true, true, true. The answer flips exactly once, so we can binary search for the flip. The search keeps a half-open range, low included and high excluded, around that boundary: it starts as 0 to 6.

@1
The middle is index 3, which holds 3. True, so the answer is at index 3 or to its left: high moves to 3.

@2
Between 0 and 3 the middle is index 1, which also holds 3. True again, so high moves to 1.

@3
Now the middle is index 0, which holds 1. False, so the answer is to its right: low moves to 1.

@4
Low equals high, at 1: the first index holding a value of at least 3. Bisect right is the same search with "greater than" in place of "at least", and returns 4. Subtract the two and you have the number of 3s: three. Counting values in a range, or finding the largest value below a bound, all fall out of these two calls.
