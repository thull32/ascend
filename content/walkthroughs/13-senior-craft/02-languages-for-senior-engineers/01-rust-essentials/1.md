@0
On the left is the stack frame for main; on the right, the heap. A String called s has just been created from the word hello. On the stack, s holds a pointer, a length of 5 and a capacity; on the heap sits the buffer with the five bytes. Watch the arrows: a solid arrow is ownership, a dashed one is a borrow. The rule to hold onto is that exactly one variable owns the buffer at any moment, and that owner is the one that frees it.

@1-2
r1 borrows s, with a shared reference. It can read the buffer but cannot free or change it, and s is still the owner. Then r2 borrows it too. Any number of shared borrows can coexist, because readers cannot invalidate each other.

@3
r1 and r2 go out of use, and both borrows end. Nothing happens on the heap: borrows never own, so they never free.

@4
Now mr takes an exclusive, mutable borrow. While it is live, no other borrow of s may exist, shared or mutable, so a write can never race with a read. Many readers, or one writer.

@5
Through mr, an exclamation mark is pushed onto the string. The buffer was full, length 5 and capacity 5, so the push reallocates. A new buffer with capacity 10 appears at 1020 in hex, holding hello with an exclamation mark, the old buffer at 1000 is freed, and s's pointer moves to the new one. That is why no other borrow may exist while mr is live: a reference into the old buffer would now dangle.

@6
mr is never used again, so the exclusive borrow ends and s is usable once more.

@7
Then t equals s: a move. The pointer, length and capacity are copied into t, and s is marked as moved. The heap is untouched. Using s again is a compile error, so the buffer still has exactly one owner, now t.

@8-9
A function that measures the length borrows t rather than taking it. A new frame appears with a dashed arrow into the buffer. It returns 6, its frame disappears, its borrow ends with it, and t is still the owner.

@10
End of scope. t, the owner, is dropped, and the buffer is freed exactly once. No double free, because s was moved from; no leak, because someone always owned it.

@11
That is the whole model: freeing at a predictable point with no garbage collector, and borrowing that lends access under one rule, many readers or one writer, checked at compile time. The only run-time trace it leaves is a hidden drop flag when a value is moved on some paths but not others.
