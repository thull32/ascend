@0
Rc and Arc are reference counts: a number stored with the allocation, raised on every clone and lowered on every drop. The picture uses language-neutral steps rather than Rust syntax, but the mechanism is the same. One object, X, has just been allocated; a holds the only reference, so its count is 1.

@1-2
b becomes a second reference to X, and the count is 2. Then X is passed into a function as a parameter, p, and the count is 3 for as long as that function runs. Every copy is counted the moment it is made.

@3
Inside the function, a new object Y is created whose parent field points at X. Y starts at 1, and X rises to 4, because a reference stored in a heap field counts too.

@4-5
The function returns. p and y go out of scope, so X drops to 3 and Y drops to 0. Zero means nobody can reach Y, so it is freed right now, and freeing Y releases everything Y referenced: its parent pointer goes, and X falls to 2. Frees cascade through the object graph.

@6-8
b is cleared, and X is at 1; a still holds it. Then a is cleared, the count hits 0, and X is freed immediately, with no separate collection phase. That is the strength of reference counting: destruction happens at a predictable point.

@9-10
Now the weakness. Two fresh objects, P and Q, one reference each. Then P's next field points at Q and Q's previous field points back at P. Each now holds a reference to the other, so both counts are 2.

@11
Clear both stack variables. The stack can no longer reach P or Q, yet each still has a count of 1, held by the other. Neither will ever reach zero.

@12
When main returns, P and Q are leaked. Reference counting cannot collect cycles. The fixes are weak references, which do not count, and which is why Rust gives you Weak, or a backup tracing collector. The ongoing cost is an increment or decrement on every copy, and in Rust that cost differs sharply: an Rc clone and drop measured half a nanosecond, an Arc clone 7 nanoseconds on one thread, and 88 nanoseconds each with eight threads cloning the same Arc, because the count's cache line bounces between cores.
