@0
Two hosts, a browser and a server, and one HTTP/1.1 request over a connection that is already open and kept alive. In Ascend, the server side of this picture is really Railway's edge, which terminates TLS and forwards plain HTTP to the binary.

@1
The browser sends a request line and its headers: a GET for the lessons. Host is mandatory, and Accept, the session cookie, and If-None-Match ride along.

@2
The server answers with a status line, 200 OK, then headers, including the content type, an entity tag and Cache-Control, then the body.

@3
Later, the browser comes back for the same resource and sends the entity tag it already holds, in If-None-Match. It is asking: has this changed since the version I have?

@4
It has not, so the answer is 304 Not Modified, with no body. The cached copy is still valid, and the revisit is cheap for both sides. Ascend's lesson and curriculum endpoints derive that tag from the content version and the build, so a new deploy changes the tag and the next revisit downloads fresh content.

@5
One limit of HTTP/1.1: a connection carries one response at a time, so browsers open about six connections per origin to work around it. HTTP/2 multiplexes many requests over one connection instead.
