@0
A client and a server, and a TLS 1.3 handshake: one round trip, then everything is encrypted. In Ascend's case the server on this picture is Railway's edge, not the application. The handshake ends there, and the edge forwards plain HTTP to the container. Ascend never holds a certificate.

@1
The browser sends a ClientHello: the cipher suites it supports, its share of a fresh key exchange, and the name of the site it wants, so the edge can pick the right certificate.

@2
The edge replies with a ServerHello, choosing the suite and sending its own key share. From here on, everything is encrypted: the certificate chain, a signature proving the edge holds the private key, and its Finished message.

@3
The browser checks the chain up to a trusted root, the name and the validity dates, sends its own Finished, and in the same flight its first HTTP request, session cookie included. The key exchange gives forward secrecy.

@4
The encrypted response comes back. One round trip before any data; a resumed session can send data immediately, with replay caveats.

@5
With the TCP handshake in front, that is two round trips before the first byte, and QUIC folds them into one. Because the encryption is the edge's job, the application's job is to make plain HTTP useless to a browser. HSTS tells it never to try HTTP for a year, the Secure flag keeps the session cookie off HTTP, and production refuses to boot without Secure cookies, so it is an invariant rather than a setting someone can forget.
