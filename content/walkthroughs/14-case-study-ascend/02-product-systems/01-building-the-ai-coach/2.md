@0
Today the coach makes one model call per turn and has no tools. Give it tools and every turn becomes an agent: a model in a loop that reads the task and the history, decides on a tool call or a final answer, lets the harness run the tool, appends the result, and goes round again. Here it has two tools, one that fetches the learner's last submission and one that fetches a test result. The learner asks: why does my two sum submission fail the hidden test?

@1
Iteration 1. The harness sends the persona, the tool definitions and the question, about 1,900 input tokens, and the model decides it needs the learner's code first: get last submission, for two sum.

@2-3
The harness, not the model, runs it: a read-only tool. The learner's Python solution comes back and is appended to the transcript, along with the fact that it fails hidden test 7.

@4
Iteration 2. The whole transcript is resent, about 2,450 tokens now, and 4,350 across the two calls so far. The model needs to know what test 7 checks, and asks for its result.

@5-6
That runs too, and the failing case is appended: numbers 3 and 3, target 6; expected indices 0 and 1, got 0 and 0.

@7
Iteration 3, about 2,700 tokens. The failing case points straight at the bug, so the model answers without a tool call and the loop ends, with a hint rather than a solution: with 3 and 3, your loop pairs the first 3 with itself; what should happen when the complement you look up is the element you are standing on?

@8
Three model calls and two tool calls, about 7,050 input tokens across the turn, although the last call sent only 2,700: the transcript is resent every time, so cost grows roughly with the square of the loop's length. And each model call takes a request slot and a budget hold, so this one turn costs three of each where today's tool-less coach spends one. That is why a per-request budget undercounts an agent: you budget per iteration, and you cap iterations, here at 6.
