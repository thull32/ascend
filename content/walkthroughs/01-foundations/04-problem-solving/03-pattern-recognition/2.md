@0
Nine numbers, some negative: minus 2, 1, minus 3, 4, minus 1, 2, 1, minus 5, and 4. We want the contiguous subarray with the largest sum. A sliding window is tempting and wrong, because with negatives the sum is not monotone as the window grows. Kadane asks a different question at every index: what is the best subarray ending right here? It is either this element alone, or this element added to the best one ending at the previous index.

@1
At position 0 there is only minus 2, so the running sum is minus 2 and so is the best.

@2
Position 1 holds 1. Extending gives minus 2 plus 1, which is minus 1, worse than 1 alone. The running sum was a burden, so we start fresh here. The running sum and the best are both 1.

@3
Position 2 holds minus 3. Extending gives minus 2, which still beats minus 3 alone, so we extend. The best stays 1.

@4
Position 3 holds 4. Extending would give minus 2 plus 4, which is 2, less than 4 alone. Restart at position 3. The running sum is 4, and the best is 4.

@5-7
Now the run builds. Minus 1 takes the running sum to 3. Then 2 takes it to 5, and 1 takes it to 6. The best climbs to 5, then 6.

@8-9
Minus 5 drops the running sum to 1, but 1 is still positive, so it is worth keeping. The final 4 lifts it to 5. Neither beats 6.

@10
The maximum subarray sum is 6, from position 3 to position 6: 4, minus 1, 2 and 1. One pass, linear time, constant space. One phrase in the statement would change the pattern: had it said "of length exactly k", the fixed-size window would win instead.
