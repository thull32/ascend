@0
This is the optimised answer to the longest substring without repeats, run on six values: 1, 2, 3, 1, 2, 4. Two pointers mark a window. The right pointer always advances by one. When a value enters that is already inside the window, the left pointer jumps just past that value's previous position. Hold onto why that jump is safe: any window starting at or before the earlier copy would contain both copies, so none of those starts can ever win.

@1-3
The right pointer takes 1, then 2, then 3. Each value is new to the window, so the window simply grows. It now covers positions 0 to 2, three distinct values, and the best length so far is 3.

@4
The right pointer reaches position 3, which holds 1. But 1 is already in the window, at position 0. The brute force would throw everything away and restart. Instead, the left pointer jumps to position 1, just past the old 1. The window is positions 1 to 3, holding 2, 3 and 1: still three distinct values, and the best stays 3.

@5
Position 4 holds 2, which last appeared at position 1. The left pointer jumps to position 2. The window holds 3, 1 and 2, length 3 again.

@6
Position 5 holds 4, which is new. The window grows to cover positions 2 to 5: 3, 1, 2 and 4. Four distinct values, and the best becomes 4.

@7
The longest run of distinct values has length 4. Both pointers only ever move right, and each moves at most n times, so the whole scan is linear: down from the cubic brute force and the quadratic version that restarted from every start. The question that got us here is the optimisation step's whole method: what work is the brute force repeating?
