@0
Binary search for the first true is about a monotone predicate: false, false, false, then true from some point onward. Here the predicate asks whether a value is at least 4. The array is 0, 0, 0, 1, 1, 1, so you can already see that no value qualifies. This run shows the edge case: what the search returns when there is no true at all. The invariant: every index below low is false, and every index at or above high is true. The unknown region runs from low up to, but not including, high: here 0 to 6. High starts at 6, one past the end, because before we look at anything, the only index known to be true is the imaginary one past the end.

@1
The middle of 0 to 6 is position 3, which holds 1. One is not at least 4, so the predicate is false. Everything up to position 3 is false, so low moves to 4, one past the middle. A false probe excludes the middle, because it is definitely not the answer.

@2
The unknown region is now 4 to 6, and its middle is position 5. Also false. Low moves to 6.

@3
Low equals high, so the unknown region is empty and the loop stops. The answer is low, which is 6: the length of the array, the insertion point. Nothing in the code handled "no true at all" specially. Starting high at the length instead of the length minus 1 made that case fall out for free, and that is the payoff of choosing the half-open range.
