@0
On the left is the stack, on the right the heap. main has just started, and its two locals, n, which is 3, and list, which is still null, live in main's stack frame. That frame is freed automatically when main returns. The rule to hold onto: a stack value dies when its function returns, and anything that must outlive the call has to live on the heap.

@1
main calls build with n. That pushes a new frame on top of main's, with build's own locals: its copy of n, a head pointer, and a loop counter. They are separate from main's, even where the names match.

@2-4
Each time round the loop, build allocates a Node on the heap and points head at it. The node holding 3 goes at address 1000 in hex, then the node holding 2 at 1020, linked to the first, then the node holding 1 at 1040, linked to the second. None of these nodes belong to any frame.

@5
build returns head. Its frame is popped and every one of its locals vanishes, but all three nodes survive, because heap memory is released by explicit free, or by a garbage collector, not by scope. main's list now points at the node at 1040.

@6
main calls print with the list. Now two frames hold the same address into the same nodes. Copying a pointer copies the address, not the objects.

@7
print returns, its frame is discarded, and the heap is exactly as it was.

@8-10
Now main frees the nodes one at a time: 1040, then 1020, then 1000. Before each free it moves list on to the next node. Free first, and the address of the rest of the list would be gone, and those nodes leaked.

@11
main returns. The stack is empty and every heap block has been freed. Stack memory is last in, first out, and automatic: allocating a frame is one instruction. Heap memory outlives frames and costs tens of nanoseconds or more per allocation, and someone has to release it, either you or a garbage collector.
