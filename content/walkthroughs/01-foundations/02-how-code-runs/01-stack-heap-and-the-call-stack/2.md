@0
main calls fact of 3, the same function as the hand trace, whose base case is n less than or equal to 1. Every call needs its own frame, holding the argument, the return address, which says where to resume in the caller, and any locals. The stack pointer marks the top, and it is the only bookkeeping the machine needs.

@1-2
fact of 3 cannot finish yet, because it needs fact of 2 first. So it pushes another frame and waits, with its own n of 3 parked in its frame. fact of 2 does the same for fact of 1. Each frame's return address points back into the call above it.

@3
fact of 1 is the base case: it makes no further call and will return 1. This is the deepest the stack gets, four frames: main plus three fact frames, the three live frames of the hand trace. Recursion depth is live memory.

@4
Now the returns. fact of 1 returns 1 and its frame is popped. The value lands in fact of 2, which resumes right after the call and multiplies by its own n: 2 times 1.

@5
fact of 2 returns 2 to fact of 3, which computes 3 times 2. Each return pops exactly one frame, in the reverse of the order they were pushed.

@6
fact of 3 returns 6, its frame is popped, and main's result slot receives 6. The stack is back where it started.

@7
fact of 3 is 6. Three fact frames went on and came off, last in, first out, and the multiply happened on the way back up, which is why no frame could be discarded early. The peak grows with n, so the cost to check before recursing over user-sized input is frame size times depth, against the stack limit.
