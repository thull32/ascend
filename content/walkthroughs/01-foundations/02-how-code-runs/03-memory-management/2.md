@0
Seven objects on the heap, A to G. Only two variables on the stack, a and d, are roots. E and F point at each other, but nothing on the stack reaches them, and G has no references at all. A tracing collector ignores counts entirely. The test is reachability: is there a path from a root to this object?

@1
The mark phase starts a work list with every object a root points at: A and D. Marking is a graph traversal from the roots.

@2-3
Mark A as live, and push what it points at, B, onto the work list. Then mark D, which points at nothing, so nothing is added.

@4-5
Mark B and push C. Mark C, which points at nothing. The work list is empty.

@6
Marking is done: A, B, C and D are reachable. Now the sweep phase walks the whole heap in address order and frees everything without a mark.

@7-10
A, B, C and D are marked, so each is kept, and its mark bit is cleared, ready for the next collection.

@11-12
E is unmarked, so it is garbage and its memory goes back to the free list, even though F still points at it. F goes the same way, even though E pointed at it. This is the cycle that reference counting could never free, and here it costs nothing special.

@13
G is unmarked too, and it is freed.

@14
Four objects live, three reclaimed. The mark phase costs time in proportion to the live objects, and the sweep in proportion to the whole heap, so garbage is free to find and only costs in the sweep. Assignments are plain pointer writes, so your program runs faster between collections. The price is the collection itself, and the naive version stops every thread while it runs.
