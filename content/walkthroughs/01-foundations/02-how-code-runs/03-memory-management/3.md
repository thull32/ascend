@0
Rust, with no garbage collector and no counts. s is a String holding hello, and s is the unique owner of its heap buffer. Ownership means exactly one variable is responsible for freeing it. Keep one rule in mind for the borrows that follow: many readers, or one writer, never both.

@1-2
r1 borrows s, shared. It can read the buffer but cannot free it or change it, and s is still the owner. Then r2 takes a second shared borrow. Any number of these can coexist, because readers cannot invalidate each other.

@3
r1 and r2 are no longer used, so their borrows end. Nothing happens to the heap: borrows never own.

@4
mr takes a mutable borrow, which is exclusive. While it is live, no other borrow of s, shared or mutable, may exist, so a write can never race with a read.

@5
Through mr, an exclamation mark is pushed onto the string, and here the buffer is reallocated. s sees the change, because it is the same heap block. And no one could be left holding a pointer into the old buffer, because the exclusive borrow ruled that out.

@6
mr's last use is behind us, so the exclusive borrow ends and s is usable again.

@7
t equals s is a move. The pointer, length and capacity are copied into t, and s is marked invalid: using s again is a compile error. The buffer still has exactly one owner.

@8-9
A length function borrows t rather than taking ownership, so t is still the owner after the call. It returns 6, and its borrow ends with its frame.

@10
End of scope. t, the owner, is dropped, and the buffer is freed exactly once. No double free, because s was moved from, and no leak, because someone always owns it.

@11
Ownership gives you deterministic freeing with no collector, at exactly the cost of a manual free, placed by the compiler. Borrowing lends access under the rule many readers or one writer, checked at compile time. What you give up is having two owners, and that is where reference counting comes back, as Rc and Arc.
