@0
This is Brian Kernighan's trick for counting set bits. x AND x minus 1 clears the lowest set bit of x, so the number of times you can do it before x reaches zero is exactly the number of set bits, the popcount.

@1
Start with 13, which is 1 1 0 1. The count is 0.

@2-3
Subtract 1. The lowest set bit is bit 0, the rightmost, and it flips to 0, giving 1 1 0 0. AND that with 13, and exactly the lowest set bit disappears: x becomes 12. The count is 1.

@4-5
Subtract 1 from 12. Now the lowest set bit is bit 2. The borrow runs through the two trailing zeros: bit 2 flips to 0, the bits below it flip to 1, giving 1 0 1 1, which is 11. The higher bit is untouched. AND with 12 leaves 1 0 0 0, which is 8. The count is 2.

@6-7
Subtract 1 from 8 to get 0 1 1 1. Bit 3, the last set bit, flips to 0 and everything below it flips to 1. AND them and nothing survives: x is 0. The count is 3.

@8
x reached zero after 3 steps, so 13 has 3 set bits. The cost is the number of set bits, not the width of the word: three iterations even for a 64-bit word with three bits set. That wins on sparse words and loses on dense ones.

@9
Popcount underpins Hamming distance, bitset sizes and the iteration order of subset dynamic programming. Many CPUs expose it as a single instruction, and in practice the fastest popcount is whichever library call reaches that instruction.
