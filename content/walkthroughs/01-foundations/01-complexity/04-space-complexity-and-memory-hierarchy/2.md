@0
An array of 32 elements in main memory, and a cache with 4 slots. Memory never moves one element at a time. It moves in cache lines, here 8 elements, which is 64 bytes. Touch one element and its 7 neighbours come along with it. That one fact is the rule behind this whole picture.

@1
The first read is element 0. Its line is not cached, so it is a miss: all of line 0, elements 0 to 7, is fetched from main memory into slot 0. A miss to memory costs roughly a hundred times as much as a hit.

@2-8
Elements 1 to 7 are already sitting in slot 0, so each read is a hit, served in a few cycles. Seven reads for free, paid for by the one miss.

@9-16
Element 8 starts line 1, so there is a second miss and line 1 lands in slot 1. Then elements 9 to 15 are hits again. Sixteen sequential reads have cost just two trips to memory, and every element of both fetched lines was used.

@17-18
Now the access pattern jumps, eight elements at a time. Element 0 and element 8 are still cached from the scan, so both are hits.

@19-20
Element 16 is in line 2, which has never been fetched: a miss, and a whole line of 8 comes in to serve a single element. Element 24 does the same with line 3. When you stride across memory, each new line costs a full fetch and you use one element of it.

@21-24
The same four strided reads again. The array is small enough that all four lines fit in the four slots, so this time every one is a hit.

@25
Twenty-four accesses: 20 hits and 4 misses. Sequential access used every element of each line it paid for. Strided access paid for whole lines to use one element each. Locality, not the element count, sets the cost, and that is why a linear scan through an array rarely waits for memory at all.
