@0
An array of 64 elements in main memory, eight cache lines of 8 elements, and a cache with only 4 slots. Memory never moves one element at a time. It moves in cache lines, here 8 elements, which is 64 bytes. Touch one element and its 7 neighbours come along with it. That one fact is the rule behind this whole picture.

@1
The first read is element 0. Its line is not cached, so it is a miss: all of line 0, elements 0 to 7, is fetched from main memory into slot 0. A miss to memory costs roughly a hundred times as much as a hit.

@2-8
Elements 1 to 7 are already sitting in slot 0, so each read is a hit, served in a few cycles. Seven reads for free, paid for by the one miss.

@9-16
Element 8 starts line 1, so there is a second miss and line 1 lands in slot 1. Then elements 9 to 15 are hits again. Sixteen sequential reads have cost just two trips to memory, and every element of both fetched lines was used.

@17-18
Now the access pattern jumps, eight elements at a time: one element per line. Element 16 is in line 2, which has never been fetched: a miss, and a whole line of 8 comes in to serve a single element. Element 24 does the same with line 3. The cache is now full.

@19-20
Element 32 is in line 4. Another miss, and with every slot taken, the least recently used line, line 0, is evicted to make room.

@21-26
The same again for elements 40, 48 and 56: each one is a miss, each evicts the oldest line, and each fetches 8 elements to use 1. The array has more lines than the cache has slots, so nothing the stride touches is ever reused.

@27
Twenty-two accesses: 14 hits and 8 misses. The sixteen sequential reads cost two misses and used every element they paid for. The six strided reads cost six misses, a whole line each, to use one element of each. Locality, not the element count, sets the cost, and that is why a linear scan through an array rarely waits for memory at all.
