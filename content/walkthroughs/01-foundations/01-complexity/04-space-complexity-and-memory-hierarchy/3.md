@0
A linked list of six nodes: 12, 7, 33, 4, 19 and 26. A pointer called current starts at the head. A list has no index, so to reach the node at position k you must follow k next pointers, one after another.

@1-3
Visit 12: read its value, then read its next pointer to find 7. Visit 7, then follow its pointer to 33. Visit 33, then on to 4. The thing to notice is the order of the work. You cannot even know where the next node lives until you have read the current one, so each load depends on the one before it.

@4-6
Visit 4, then 19, then 26. The next pointer of 26 is null, and the list ends.

@7
Current is null, so the loop stops. Six nodes, one pointer load each: order n time and constant extra space, exactly like scanning an array. But the hardware sees a very different picture. An array scan reads contiguous memory, and the prefetcher runs ahead of it. Here the nodes are wherever the allocator put them, the prefetcher cannot guess the next address, and on a cold cache every hop can be a miss of about 100 nanoseconds. Same complexity, very different speed.
