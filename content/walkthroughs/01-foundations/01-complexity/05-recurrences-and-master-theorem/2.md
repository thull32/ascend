@0
Recursive binary search for 23 in ten sorted values, from 4 up to 90. Each call looks at the middle of its range and makes exactly one recursive call, on the half that can still contain the target. So instead of a tree, you are about to see a chain.

@1
The first call covers positions 0 to 9. The middle, position 4, holds 31, which is bigger than 23, so it recurses on the left half, 0 to 3.

@2-4
Position 1 holds 9, too small, so the next call takes 2 to 3. Position 2 holds 15, too small, so the next takes just position 3. Position 3 holds 22, still too small, so the last call gets a range from 4 to 3.

@5
Low is now greater than high: the range is empty, so 23 is not in the array, and this call returns minus 1.

@6-9
Now the chain unwinds. Each call returns the minus 1 it was handed, unchanged, because the recursive call was its last action and there is nothing to combine on the way up.

@10
Five calls, five deep, one per level, each doing a constant amount of work. That is the recurrence T of n equals T of n over 2, plus 1: one node per level and log n levels, so log n time. The stack is also log n deep, and it can drop to constant space if the compiler eliminates the tail call.
