@0
Eight labelled points: four of class 0 in the lower left, four of class 1 in the upper right. A decision tree carves this space with yes-or-no questions about one feature at a time, so every cut is a straight line parallel to an axis. It grows greedily: at each node, try every threshold on every feature, and keep the split whose two children are purest. Purity is measured by Gini impurity, which is 0 for a node holding one class and 0.5 for a fifty-fifty mix. The root, four and four, sits at 0.5.

@1
First candidate: the best threshold on the first feature. Cut at 4, between the class 0 points, which reach 3, and the class 1 points, which start at 5. The left side gets four points, all class 0, and the right side gets four, all class 1. Both children are pure, so the weighted impurity is 0.

@2
Second candidate: the best threshold on the second feature. A cut at 3.5 also separates the classes perfectly, four and four, weighted impurity 0. The two candidates tie.

@3
The tree takes the cut on the first feature at 4, the first one it scored. Impurity drops from 0.5 to 0, a gain of 0.5, the most any split can achieve here. Now it recurses into each side.

@4
The left side holds four points, all class 0, with impurity 0. Nothing is left to split, so it becomes a leaf that predicts class 0.

@5
The right side holds four points, all class 1. Another pure leaf, predicting class 1.

@6
One question, two leaves, and every training point classified correctly. The algorithm is greedy and top-down, with no backtracking, and each node costs a scan over every threshold of every feature. On real data the tree keeps splitting, and depth is the dial: a deep tree can give every example its own leaf and memorise the noise. That variance is why production systems ship ensembles, random forests and gradient boosting, rather than a single deep tree.
