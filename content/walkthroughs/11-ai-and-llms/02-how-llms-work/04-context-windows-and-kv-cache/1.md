@0
The prompt is three tokens: The cat sat. Prefill runs one parallel forward pass over all three, and in every layer it computes each token's key and value vectors and stores them: three key and value pairs in the cache. Here is the fact the whole cache rests on. Because of the causal mask, a token's keys and values never change once computed, since they depend only on the tokens at or before it. So compute them once, and keep them.

@1
Decode step 1. Only the new token, on, runs through the layers. It computes one new key and value pair, appends it to the cache, and then attends over all four cached pairs. Without a cache, we would recompute keys and values for all four tokens. Two counters are running now: 4 pairs computed with the cache, 7 without.

@2
Decode step 2. The new token, the, computes one pair and attends over five. With the cache, 5 pairs computed in total. Without it, 12, because every step recomputes the whole sequence.

@3
Decode step 3. The new token, mat, computes one pair and attends over six. With the cache, 6. Without it, 18. Notice what the cache does not remove: each step still attends over every cached token, so the attention span grows by one every step, and decode gets slower as the context gets longer.

@4
So the cache makes key and value work grow linearly instead of with the square of the length, and it pays in memory. Every token stores a key and a value in every layer: about half a megabyte per token for a 7-billion-class model in 16-bit, so a 4,000-token sequence holds about 2 gigabytes. That memory, not arithmetic, limits how many sequences one GPU can serve at once. Grouped-query attention shrinks it, and paged attention, popularised by vLLM, manages it in fixed-size blocks, like virtual memory.
