@0
The prompt is three tokens: The cat sat. Prefill runs one parallel forward pass over all three, and in every layer it computes each token's key and value vectors and stores them: three key and value pairs in the cache. Causal attention inside the prompt costs 1 plus 2 plus 3, 6 scores, and the last position predicts the first output token, on. Here is the fact the whole cache rests on. Because of the causal mask, a token's keys and values never change once computed, since they depend only on the tokens at or before it. So compute them once, and keep them.

@1
Decode step 1, the table's second row. Only the new token, on, runs through the layers. It computes one new key and value pair, appends it, and attends over all four cached pairs to emit the. Without a cache we would recompute keys and values for all four tokens. Two counters are running now: 4 pairs computed with the cache, 7 without.

@2
Decode step 2. The token the computes one pair and attends over five, emitting mat. With the cache, 5 pairs in total. Without it, 12, because every step recomputes the whole sequence. Those are the table's totals: 12 against 5.

@3
And the column people miss: 15 attention scores either way, 6 in prefill, then 4, then 5. The cache removes recomputation, not attention; each step still attends over every cached token, so decode gets slower as the context grows. What the cache costs is memory. Every token stores a key and a value in every layer: about half a megabyte per token for a 7-billion-class model in 16-bit, so a 4,000-token sequence holds about 2 gigabytes. That memory, not arithmetic, limits how many sequences one GPU can serve at once.
