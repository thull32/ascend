@0
An agent is a language model in a loop. It reads the task and the history so far, decides on either a tool call or a final answer, a harness runs the tool, the result is appended, and round it goes. Two tools are available: list PRs, and today. The task: how many open pull requests are older than 7 days?

@1
Iteration 1. The model reads the transcript and decides it needs the list first. It emits a structured tool call: list PRs, with state open. The prompt so far is about 340 tokens.

@2
Your code, the harness, not the model, executes that call. Tool results are the agent's only contact with reality, so this is where you validate arguments and sandbox side effects.

@3
The observation is appended to the transcript: 12 pull requests, each with its creation date. Everything in the transcript is context for every later decision, so a verbose tool result is paid for again on every iteration.

@4
Iteration 2. Older than 7 days needs today's date, and the model has no clock. It calls the today tool. The prompt is now about 750 tokens.

@5
The harness executes today.

@6
The observation is appended: 26 September 2026.

@7
Iteration 3. With the 12 dates and today's date in context, the model works out the answer itself and stops: 4 open pull requests are older than 7 days, numbers 412, 418, 421 and 430. No tool call means the loop ends. Notice that this last step, comparing dates and counting, was the model's own work. The lookups were delegated to tools; the arithmetic was not. That is exactly the kind of step the lesson says to hand to a code tool or check, because counting and date maths degrade as the list grows.

@8
The loop needs guards: an iteration cap, here 6, a token budget, timeouts on tools, and human confirmation for anything irreversible. The run took 3 model calls and 2 tool calls. By the last call the prompt is about 1,210 tokens, and since every call resends the whole transcript, the three calls processed about 2,300 input tokens between them: cost grows roughly with the square of the loop length. And each iteration is a step whose error rate compounds: at 95 percent per step, twenty unchecked steps succeed only about a third of the time.
