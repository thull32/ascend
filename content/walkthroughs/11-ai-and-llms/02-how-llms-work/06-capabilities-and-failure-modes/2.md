@0
An agent is a language model in a loop. It reads the task and the history so far, decides on either a tool call or a final answer, a harness runs the tool, the result is appended, and round it goes. Two tools are available: today, and list PRs, which can filter by state and creation date. The task: how many open pull requests are older than 7 days?

@1
Iteration 1. The harness sends the system prompt, the tool definitions and the task, about 340 input tokens, and the model decides. Older than 7 days needs today's date, and the model has no clock, so it emits a structured call to the today tool.

@2
Your code, the harness, not the model, decides what runs. Today is a read-only tool, so it runs on the harness side. This is where you validate arguments and sandbox side effects.

@3
The observation is appended to the transcript: 26 September 2026. Everything in the transcript is resent on every later call, so a verbose tool result is paid for again on every iteration.

@4
Iteration 2. The harness resends the whole transcript, now about 390 tokens, and about 730 across the two calls so far. Seven days before 26 September is 19 September, so the model asks the tracker to do the work: list PRs, state open, created before 19 September.

@5
The harness checks it, a read-only tool again, and executes it.

@6
The observation is appended: a count of 4, pull requests 412, 418, 421 and 430. The tracker did the filtering and the counting, not the model.

@7
Iteration 3. The harness resends the transcript, about 480 tokens. The count is already in the last tool result, so the model answers without a tool call and the loop ends: 4 open pull requests are older than 7 days. The model never counted anything. It decided what to look up and read the answer back, which is the division of labour this lesson recommends: lookups and counting go to tools, because counting and date maths degrade as the list grows.

@8
Three model calls and two tool calls. The last call sent only about 480 tokens, but every call resends the whole transcript, so the run processed about 1,210 input tokens in total, and that total grows roughly with the square of the loop length. The loop needs guards: an iteration cap, here 6, a token budget, timeouts on tools, and human confirmation for anything irreversible. And each iteration is a step whose error rate compounds: at 95 percent per step, twenty unchecked steps succeed only about a third of the time.
