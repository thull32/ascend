@0
This is step 5 of the lesson's trace. The model is generating JSON and has written an open brace, the verdict key, a colon and an opening quote, so the next token must start the verdict's value. On screen are six candidate tokens with the model's raw scores: maybe 2.0, hire 1.5, no 1.0, strong 0.5, a newline at minus 1, and Sure at minus 2. Nothing in the model knows the schema. These are its own preferences.

@1
The softmax turns the scores into probabilities: maybe 0.441, hire 0.268, no 0.162, strong 0.098, and almost nothing for the last two. Left alone, the model's favourite is maybe.

@2
Now the mask. The grammar allows only tokens that keep the text a prefix of some valid output, and the enum has two values, hire and no hire. So hire and no survive, and every other token, maybe included, gets probability zero. The 0.430 that remains is renormalised in proportion to the model's own preference between the survivors: hire 0.622, no 0.378. Top-p does exactly this with a different rule for which tokens survive. A schema grammar is just another mask.

@3
The draw is 0.811. Walking the legal tokens, hire covers up to 0.622 and no the rest, so the draw lands on no, the token the lesson's trace samples. It is appended, the grammar's automaton advances, and the next step gets a new mask that allows only the rest of no hire.

@4
The guarantee and the blind spot both come from this mask. The output is guaranteed to parse, so the retry-on-parse-error loop can go. But the model put 0.441 on maybe, and the mask threw it away: whatever came out, hire or no, looks confident in a perfect shape. If the honest answer is not representable, the schema forces a guess, so give the enum an honest escape value such as insufficient evidence.
