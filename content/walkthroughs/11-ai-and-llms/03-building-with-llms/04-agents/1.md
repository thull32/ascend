@0
An agent is a language model in a loop that chooses its own next action. It reads the task and everything that has happened so far, then either calls a tool or declares it is done. The model, not your code, decides the control flow, and that is the source of both the power and every problem. This is the lesson's traced run: eight tools, five of them used here, and one task. A customer says they were charged twice for invoice 2291.

@1
Iteration 1. The harness sends the system prompt, the tool definitions and the task, 4,500 input tokens, and the model decides to start from the dispute record: get dispute, for dispute 881.

@2
The harness, not the model, decides what runs. It is a read tool, so it runs.

@3
The result is appended: customer 42 says invoice 2291 was charged twice. Nothing ever leaves the transcript, so this rides along on every later call.

@4
Iteration 2. The harness resends the whole transcript, now 5,350 tokens, which makes 9,850 across the two calls so far. The model needs the amount and calls get invoice.

@5-6
The read runs, and the result is appended: 49 euros, customer 42.

@7
Iteration 3, at 6,450 tokens. The model looks for payments against the invoice with list payments, for customer 42, since 1 August.

@8-9
It runs, and here is the expensive moment: the result is 2,400 tokens of raw provider JSON, with the two 49-euro payments somewhere inside it. Every one of those tokens is resent on calls 4, 5 and 6.

@10
Iteration 4, at 9,070 tokens, the jump that result caused. The model checks both payments at once: two get payment calls in one turn, which costs one model call instead of two.

@11-12
Both reads run, and the result is appended: both payments were captured, so it is a real double charge.

@13
Iteration 5, at 10,330 tokens. The model decides to refund the duplicate: issue credit, 49 euros, against dispute 881.

@14
This one is different. It is a write that moves money, so the loop pauses for a person to approve it, and only then does the harness run it. The approval check sits on the harness side, before the call executes.

@15
The result is appended: a credit of 49 euros issued.

@16
Iteration 6, at 10,770 tokens. The model answers without a tool call, so the loop ends: it confirmed the duplicate charge and issued the credit.

@17
Six model calls and six tool calls. The last call sent 10,770 tokens, but every call is a fresh request that resends the whole transcript, so the run processed 46,470 input tokens in total, the table's figure. That is why agent cost grows faster than the step count, roughly with its square. A production loop needs guards on every exit: an iteration cap, here 12, a token budget, timeouts on tools, and human approval before anything irreversible, like the credit you just watched.
