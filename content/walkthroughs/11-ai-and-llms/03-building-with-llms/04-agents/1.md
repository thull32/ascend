@0
An agent is a language model in a loop that chooses its own next action. It reads the task and everything that has happened so far, then either calls a tool or declares it is done. The defining property is that the model, not your code, decides the control flow, and that is the source of both the power and every problem. Two tools here, list PRs and today, and one task: how many open pull requests are older than 7 days?

@1
Iteration 1. The model reads the transcript and decides it needs the list first: a structured call to list PRs, with state open. The prompt is about 340 tokens.

@2
The harness runs the call, not the model. This is where your code validates arguments, sandboxes side effects, and enforces timeouts.

@3
The result is appended: 12 pull requests with their creation dates. Nothing ever leaves the transcript, so this result rides along on every later call. A verbose result is a cost you pay again and again.

@4
Iteration 2. The model needs today's date and calls today. The prompt is now about 750 tokens: everything before, plus the new result.

@5
The harness executes today.

@6
The result, 26 September 2026, is appended.

@7
Iteration 3. With the dates and today in context, the model computes the answer itself and stops: 4 open pull requests are older than 7 days, numbers 412, 418, 421 and 430. No tool call, so the loop ends.

@8
Three model calls and two tool calls. By the last call the prompt is about 1,210 tokens, and because every call is a fresh request that resends the whole transcript, the three calls processed about 2,300 input tokens between them. That is why agent cost grows faster than the step count, roughly with its square. A production loop needs guards on every exit: an iteration cap, here 6, a token budget, timeouts on tools, a check for repeated identical calls, and human approval before anything irreversible, such as issuing a credit.
