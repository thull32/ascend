@0
Two requests, the second one appending to the first, which is exactly how consecutive agent calls look. Request 1 is three tokens, The cat sat. Prefill runs them through every layer in one pass and computes a key and a value for each: three pairs, stored. The last position predicts the first output token, on.

@1
Decode step 1. Only on runs through the layers; its key and value are appended, four cached, and it attends over all of them to emit the. Inside one request, this cache is what saves recomputing earlier tokens.

@2
Decode step 2 does the same for the: five cached, and it emits mat.

@3
Request 1 ends with the reply, on the mat. Its working cache would normally be freed now. With prompt caching, the provider keeps the prompt's three key and value pairs as a cache entry for that exact prefix, for about five minutes.

@4
Request 2 resends everything, because every call is stateless: the three-token prompt, the reply, and the new message, nine tokens. Its first three are byte-identical to the cached prefix, so the lookup hits, and those three pairs are read from the cache instead of computed. For an agent, the prefix is the tool definitions, the system prompt and the whole transcript of the previous call.

@5
Prefill runs only over the six new tokens, appending their pairs after the three it read: six computed instead of nine. That is the sentence from the lesson: each agent call pays full price only for what was appended since the last one. Less prefill also means a shorter wait for the first token.

@6
In this toy the saving is 3 of 9 tokens. In an agent it is the system prompt, the tools and every earlier step, so most of each call is a cache read at a tenth of the input price, while the new tail is a cache write at 1.25 times. In the lesson's 20-step example, 345,000 input tokens bill as about 70,700, about a fifth. Caching changes the price, not the shape: the cost still grows with the square of the step count. And the match is exact and in order, so anything that rewrites earlier content, such as editing a past tool result, reordering tools or switching models mid-task, breaks the prefix and turns the next call into a full cache write.
