@0
Prefill: the model runs the input, here three tokens, The cat sat, through every layer in one pass and computes a key and a value for every token. Three pairs, stored. For an agent, the input on each call is the system prompt, the tool definitions and the whole transcript so far, thousands of tokens, and this prefill is where most of that work goes.

@1
Decode step 1. Only the new token, on, is computed; it appends one key and value pair and attends over all four. Inside one request, the cache means old tokens are never recomputed: 4 pairs, against 7 without it.

@2
Decode step 2 appends the: 5 pairs, against 12.

@3
Decode step 3 appends mat: 6 pairs, against 18. These frames show the cache within a single request. A prompt cache stretches the same idea across an agent's calls. Consecutive calls share a byte-identical prefix, because the tools and system prompt never change and the transcript only appends, so the provider can reuse the stored keys and values for that prefix.

@4
The price follows. Each agent call pays full price only for what was appended since the last one, written to the cache at 1.25 times the input price, and reads the rest at a tenth. In the lesson's 20-step example, 345,000 input tokens bill as about 70,700: about a fifth. Caching changes the price, not the shape: the cost still grows with the square of the step count. And anything that rewrites earlier content, such as editing a past tool result, reordering tools or switching models mid-task, breaks the prefix and turns the next call into a full cache write.
