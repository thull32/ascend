@0
This is the agent loop at its smallest: a task, the model deciding, a tool running, an observation, and an answer. The task is a simple question, how many open pull requests are older than 7 days, rather than a bug fix, and the loop runs only three times. But the cost curve the title promises is already visible. Watch the token count: it is the size of the prompt the model reads on each decision.

@1-3
Iteration 1. The prompt is about 340 tokens, just the task. The model calls the tool that lists open pull requests, the harness runs it, and 12 pull requests come back and are appended to the transcript.

@4-6
Iteration 2. The prompt is now about 750 tokens, because the list of 12 is in it. The model calls the date tool, and today's date is appended as well.

@7
Iteration 3, about 1,210 tokens. The model answers, 4 pull requests, and the loop ends.

@8
Every observation stays in the transcript and is resent on the next decision, so each iteration reads everything before it: 340, then 750, then 1,210. Now picture a fix loop instead: every file read and every test log appended, iteration after iteration. Iteration 30 reads all 29 before it, so it is far more expensive than iteration 3, and less focused. That is why the harness has an iteration cap and a budget, here a cap of 6. Your equivalent is noticing the third failed attempt and resetting with a fresh session and a sharper spec.
