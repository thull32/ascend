@0
The agent loop: a task, the model deciding, a tool running, an observation, and an answer. The task here is a harmless question, how many open pull requests are older than 7 days, and the tools are a pull request lister and a clock. Watch where each step happens, because that decides where the guardrails can go. The model only proposes. The harness executes.

@1
The model reads the transcript and emits a structured tool call: list the open pull requests. That call is a proposal, nothing more. Nothing has run yet.

@2
The harness executes it. Everything that keeps an agent safe sits here, on the harness side: validating the arguments, checking the permission rule, running hooks, and sandboxing the side effects. The model cannot skip a check it never gets to run.

@3
The result, 12 pull requests, is appended to the transcript. Think about what that means with an integration: whatever the tool returns, including text an attacker wrote into an issue or a document, becomes input to the next decision. Nothing on this screen marks it as data rather than instructions.

@4-6
The loop goes round again. The model asks for today's date, the harness runs the clock, and the date is appended.

@7
With both results in context, the model answers, 4 pull requests, and makes no further call, so the loop ends.

@8
The guards on screen are all harness features: an iteration cap of 6, a token budget, timeouts on tools, and human confirmation for irreversible actions. That is the shape to aim for with integrations. The human decides at the confirmation, and a scoped token and limited network egress bound the worst a wrong decision can do.
