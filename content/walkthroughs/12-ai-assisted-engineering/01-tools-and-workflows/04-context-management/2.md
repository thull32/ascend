@0
Two rows: the sequence of tokens, and below it the key and value cache. The prompt is three tokens, The cat sat. The expensive part of any model call is prefill: one pass over the prompt that computes a key and a value for every token, in every layer, and stores them. Three tokens, three key and value pairs. Every later token has to attend to the keys and values of every earlier one, so the point of storing them is to compute each one only once.

@1
Decode, step 1. The model generates on. Only that one new token runs through the layers; its pair is appended, and it attends over all four stored pairs. Without the cache, the model would recompute all four: 7 pairs computed so far, against 4 with the cache.

@2-3
Step 2 generates the, step 3 generates mat. Each time, one new pair is appended. Without the cache the work keeps piling up: 12 pairs, then 18, against 5, then 6.

@4
So generation does work proportional to the length, not its square, at the price of memory: for a 7 billion parameter model at 16-bit precision, about half a megabyte per token, roughly 2 gigabytes for a 4,000-token sequence. Now connect it to your bill. Prompt caching stores exactly this prefill result for a prefix, and serves it to the next request that starts with the same bytes. That is why a cache read is billed at about a tenth of the input rate on most models, why the stable part of a prompt must come first, and why changing one byte early in the prefix makes everything after it miss.
