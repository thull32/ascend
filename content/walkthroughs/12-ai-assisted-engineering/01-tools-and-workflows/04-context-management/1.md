@0
The agent loop, small enough to watch: a task, the model deciding, a tool running, an observation, an answer. The task is a question, how many open pull requests are older than 7 days, and the loop runs three times rather than thirty. The number to watch is the token counter. It is the same quantity as the input-tokens column in the lesson's table: how much the model reads on each call.

@1-3
Call 1 reads about 340 tokens, the task alone. The model asks for the list of open pull requests; the harness fetches it, and 12 of them, with their dates, are appended to the transcript.

@4-6
Call 2 reads about 750 tokens, because the list is now part of the prompt. The model asks for today's date, and that is appended too.

@7
Call 3 reads about 1,210 tokens, and the model answers: 4 pull requests are older than 7 days.

@8
Nothing in this loop ever removes anything. The transcript only grows, and each call reads all of it, so the sum of the input column grows roughly with the square of the number of iterations. In the lesson's eight-step fix loop, the final transcript was 44,300 tokens, but the model processed 199,900 input tokens to get there. Prompt caching cuts the bill, because a repeated prefix is billed as a cheap cache read, but it does not shrink the window. The only ways down are compaction, a fresh session, or handing work to a subagent.
