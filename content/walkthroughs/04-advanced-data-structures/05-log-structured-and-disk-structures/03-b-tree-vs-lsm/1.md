@0
Two engines, three currencies: read cost, update cost and space. This is the B-tree side. Each box is a fixed-size page. The root holds two separators, 20 and 40, and three leaves hold the keys: 5, 10, 15; 20, 25, 30; and 40, 45, 50. As you watch, count two things: how many pages a read touches, and how many bytes a small write rewrites.

@1-2
Look up 45. Read the root, binary-search its separators, and since 45 is at least 40, follow the third pointer. Read leaf 3, and 45 is there. Two page reads, and the root is always in memory, so one disk read. That is the B-tree's strength: read amplification of about one.

@3
A range scan from 25 to 45 descends once, to leaf 2, then follows a sibling pointer straight to leaf 3. Leaves are linked, so scans read consecutive pages with no merging. Range scans are what B-trees are best at.

@4
Insert 42. It is routed to leaf 3, which has room, and slides into place, filling the page to four keys. But notice what that costs on disk. The change is a few bytes, and eventually the whole page is written back. For a 100-byte row in an 8 kilobyte page that is about 82 times the bytes the application asked to write, and it is a random write, wherever that page happens to live.

@5-6
Insert 47, and leaf 3 would hold five keys, one over its capacity. It splits: 40, 42 and 45 stay, 47 and 50 move to a new leaf 4, and 47 goes up into the root as a separator. Now several pages change for one insert.

@7
Insert 12 lands in leaf 1, which has room. Another single page rewritten, in place.

@8
The failure modes. A split is a multi-page write, so a crash halfway through needs the write-ahead log. Random keys leave pages about 70 percent full, which is space amplification. And ever-increasing keys pile every insert onto the rightmost leaf.

@9
So the B-tree minimises read cost and keeps one copy of each row, and pays in update cost: a whole page per change, written at random. If updates cluster on a hot set of pages, a page absorbs many changes before it is flushed and that cost shrinks. A uniformly random write stream over terabytes is where it hurts, and that is where the LSM tree makes the opposite bet.
