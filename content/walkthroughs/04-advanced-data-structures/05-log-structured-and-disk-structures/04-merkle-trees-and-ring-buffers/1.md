@0
One producer thread, one consumer thread, and a ring of four slots between them. There are two indices, head and tail, and they only ever grow; the slot is the index masked down to the ring's size. Hold onto one rule, because it is the whole design: the producer is the only thread that writes tail, and the consumer is the only thread that writes head. Each reads the other's index, but never changes it. So there is no lock here, and no compare-and-swap.

@1
The producer pushes A. It loads its own tail, 0, and reads head, also 0. Tail minus head is 0, so there is room, and it writes A into slot 0. At the same moment the consumer tries to pop. It reads tail, sees 0, the same as head, and returns empty straight away. Empty is an answer, not a wait. And the consumer cannot see A yet, because tail still says 0.

@2
Now the producer publishes: it stores tail equals 1, with release ordering. Release means that everything the producer wrote before this store, the bytes of A, is visible to any thread that reads the new tail with acquire ordering. Slot 0 turns from written to published.

@3
Both threads work at once. The producer writes B into slot 1. The consumer reads tail with acquire ordering, sees 1, which is not equal to head, 0, and reads slot 0. Because its acquire load saw the producer's release store, A's bytes are guaranteed to be there.

@4
The producer publishes tail equals 2. The consumer publishes head equals 1, with its own release store, handing slot 0 back. Two stores to two different indices, each with exactly one writer: there is nothing to race on.

@5-8
The consumer is busy with A, and the producer keeps going. Push C: tail 2 minus head 1 is 1, so there is room; write slot 2, then publish tail equals 3. Push D into slot 3, then publish tail equals 4. The ring now holds B, C and D, and slot 0 is free again, because head moved past it.

@9
Push E. Tail 4 minus head 1 is 3, still room. The slot is 4 masked by 3, which is 0, so the producer wraps around and reuses A's old slot. The indices keep growing; only the mask wraps.

@10
Publish: tail equals 5. Tail minus head is now 4, the capacity. The ring is full.

@11
The producer tries to push F, finds tail minus head equal to 4, and gets full back immediately. It does not sleep: the caller decides whether to spin, back off or drop. Meanwhile the consumer reads B from slot 1.

@12
The consumer publishes head equals 2, freeing slot 1. The producer retries: tail 5 minus head 2 is 3, so there is room, and F goes into slot 1.

@13
Publish: tail equals 6.

@14
Six pushes, two pops, no lock and no compare-and-swap. Each index has one writer, and every operation finishes in a bounded number of steps, which makes the queue wait-free for both sides. What it does need is ordering: write the slot, then release-store the index; acquire-load the index, then read the slot. Get that wrong on a weakly ordered processor and the consumer can read a slot before its bytes arrive. And one more cost hides in the layout: if head and tail share a cache line, every publish drags that line between the two cores, which is the next visualisation.
