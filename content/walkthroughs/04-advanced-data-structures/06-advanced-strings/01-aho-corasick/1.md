@0
Aho-Corasick starts from a trie of the patterns: he, she, his and hers. A trie stores strings one character per edge, so patterns with a common prefix share the nodes of that prefix. A double ring marks a node where a pattern ends.

@1-3
Insert he. There is no edge for h under the root, so a node is created, then a node for e under it, and that node is marked: a pattern ends here.

@4-7
Insert she. Nothing under the root starts with s, so this is a fresh branch: s, then h, then e, marked as the end of she.

@8-11
Insert his. The h edge already exists, so we follow it, with no new node. That is the shared prefix paying off. Then new nodes for i and s, and the s is marked.

@12-16
Insert hers. Follow h, follow e, both already there, then create r and s, and mark the s. Ten nodes, counting the root, for twelve pattern characters.

@17-20
Now some lookups. Search for she: follow s, h, e. Every character matched and the node is marked, so she is stored.

@21-24
Search for her: h, e, r all exist, but the r node is not marked. Her is only a prefix of hers, so the search says no. That is what the marker is for.

@25-27
A prefix check for he just needs the path to exist, and it does, so it says yes.

@28
Four patterns in ten nodes, and insert, search and prefix all cost the length of the key, however many keys are stored. But notice the limitation: this trie matches patterns starting at one fixed position. To scan a text, you would restart from the root at every position, and after matching she you would throw away the h and e you just read, even though he is itself a pattern. Aho-Corasick adds failure links that jump straight to the longest suffix still in the trie, so the text is read once.
