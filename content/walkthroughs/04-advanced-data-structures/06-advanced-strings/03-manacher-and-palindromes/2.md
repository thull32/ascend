@0
The other classic tool: an interval table. The string is abaab, and cell i, j answers one question: is the piece from position i to position j a palindrome? The rule is that a piece is a palindrome when its two ends match and the piece inside them is a palindrome. Each cell needs a strictly shorter piece, so the table fills by increasing length.

@1
Length 1: every single character is a palindrome, so the whole diagonal is true. Five palindromes already.

@2-5
Length 2: a pair is a palindrome only if both characters are equal. a b, no. b a, no. a a, yes. a b, no.

@6-8
Length 3. a b a: the ends match, and the inside, b, is a palindrome, so yes. b a a: the ends differ, so no, without even looking inside. a a b: no, for the same reason.

@9-10
Length 4. a b a a: the ends match, but the inside, b a, is not a palindrome, so no. b a a b: the ends match and the inside, a a, is a palindrome, so yes.

@11
Length 5. The whole string, abaab, begins with a and ends with b, so no.

@12
Eight palindromic substrings, and the longest is baab. The table answers every question about every interval, but it costs n squared time and n squared memory, using only the upper triangle. Manacher answers the same questions, the longest, the count, and whether any range is a palindrome, with an array of 2n plus 1 integers built in linear time. Keep the table for the problems that really need it, such as palindromic subsequences and partitioning.
