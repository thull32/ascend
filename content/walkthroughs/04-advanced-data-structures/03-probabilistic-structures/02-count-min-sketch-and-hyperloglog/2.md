@0
HyperLogLog counts distinct items by looking at bit patterns. A good hash turns each distinct key into a random string of bits, and in a random string, half start with a 1, a quarter start with zero then 1, and one in 2 to the power r starts with r minus 1 zeros followed by a 1. The animation itself counts set bits with Brian Kernighan's trick: x AND x minus 1 clears the lowest set bit. As each eight-bit value goes by, read its row from the left too, because the zeros before the first 1 are what HyperLogLog cares about.

@1-4
The first value is 1: seven zeros, then a single 1 at the far right. For HyperLogLog that is a rare pattern, a 1 in 256 event. The animation subtracts 1, which borrows through the trailing zeros, ANDs the two rows, and the only set bit disappears. One step, so 1 has one set bit.

@5-10
Next, 6: five zeros, then 1, 1, 0. A 1 in 64 pattern. It takes two clearing steps, first down to 4, then to 0, so 6 has two set bits.

@11-14
8 is four zeros, then a 1, then three zeros: a 1 in 32 pattern. One clearing step.

@15-18
32 is two zeros, then a 1. A 1 in 8 pattern, and again a single set bit.

@19-24
96 is one zero, then two 1s. A 1 in 4 pattern. Two clearing steps, through 64 down to 0.

@25
The animation's own lesson is that counting set bits costs one step per set bit, and many processors do it in a single instruction. HyperLogLog's lesson is in the left edge of those rows. The longest run of leading zeros here is seven, and if you only ever kept that one maximum, a single unlucky hash would wildly inflate your estimate. So HyperLogLog splits the hashes across many registers, keeps a maximum in each, and combines them with a harmonic mean, which shrugs off one outlier.
