@0
This is what red-black trees exist to prevent. We insert 1 through 7, in sorted order, into a plain binary search tree with no balancing at all. The only rule is the search-tree rule: smaller keys to the left, larger keys to the right.

@1-4
1 becomes the root. 2 is bigger, so it hangs off 1's right. 3 is bigger than 1 and bigger than 2, so it goes right twice and attaches at depth 2. Already you can see the shape: nothing ever goes left.

@5-11
4 compares against 1, 2 and 3, and lands at depth 3. 5 makes four comparisons and lands at depth 4. Each insert walks the entire chain before it finds an empty slot.

@12-22
6 walks five nodes, and 7 walks six, attaching at depth 6. Every comparison says go right, because sorted input always lands beyond the largest key so far.

@23
The result is a linked list wearing a tree's clothes: seven keys stacked in seven levels. Each insert costs time proportional to the height, which is logarithmic when the tree is balanced and linear for a chain like this, and the insertion order alone decided which one we got. A red-black tree fed the same seven keys rotates its way to a height of 4, and an AVL tree to 3. The colour rules forbid this shape outright: no two reds in a row, and the same number of blacks on every path, so the longest path is at most twice the shortest.
