@0
Ten points on a plane and a query, the red ring at 5.5, 7.5: the same points and the same query as the k-d tree trace. The animation is a nearest-neighbour classifier, so it calls the two colours classes. Here they simply mark the two sides of the k-d tree's root split, the vertical line at x equals 6: blue on or to the right of it, amber to the left. We want the one nearest point.

@1
Brute force has no index and no cleverness. It measures the distance from the query to all ten points, so every query costs time proportional to the number of points. The nearest is the point at 6, 8, which the k-d tree trace calls G, at 0.71. The runner-up is 4, 7, at 1.58.

@2-3
So the answer is G, at a distance of 0.71. With only one neighbour asked for, it decides the vote on its own, and the prediction is G's colour, blue.

@4
Compare the cost. Brute force computed ten distances. The k-d tree reached the same answer, G at 0.707, after five, because at each split it asked whether the splitting line was closer to the query than the best distance so far, and when it was not, it skipped the whole far side. Brute force stays linear in the number of points for every query; a k-d tree is the tool at low dimension, and a graph index such as HNSW at high dimension.
