@0
Eight values: 5, 2, 4, 7, 1, 3, 6 and 8. Underneath them is an empty prefix row. Each prefix entry will hold the sum of every value from the start up to and including its position. Build it once, and any range sum becomes a single subtraction. Watch how each entry is made, because that is also why this structure breaks.

@1-4
The first prefix is just 5. Then each entry is the previous prefix plus the value above it: 5 plus 2 is 7, 7 plus 4 is 11, 11 plus 7 is 18.

@5-8
The run continues: 19, 22, 28, and finally 36, the sum of everything. One pass, linear time.

@9
Now ask for the sum from position 2 to position 5: 4, 7, 1 and 3. Take the prefix at 5, which is 22, and subtract the prefix just before the range, at position 1, which is 7. The answer is 15, with one subtraction, however long the range.

But look at what each entry depends on: every value before it. Change the value at position 2 from 4 to 9, and six of the eight prefixes are now wrong, and rebuilding them costs linear time again. Prefix sums are perfect when the data never changes, and that long chain of dependencies is exactly what a segment tree replaces with short ones, so that each element feeds only about log n summaries, and both a point update and a range query cost logarithmic time.
