@0
The top row is not data. It is a difference array, a list of instructions: 0, 5, 0, 0, minus 5, 0, 3, 0. It encodes two range updates. Add 5 to positions 1 through 3, written as plus 5 where the range starts and minus 5 just after it ends. And add 3 to positions 6 and 7, written as plus 3 at position 6, with nothing to cancel because the range runs off the end. The idea to hold: an update is recorded only at its boundaries, and the elements in between are never touched.

@1-4
Now run prefix sums over the instructions, and the real values appear. Position 0 is 0. At position 1 the plus 5 kicks in: 5. Positions 2 and 3 add nothing, so they stay at 5. The add has flowed across its whole range without anyone writing to those positions.

@5-6
At position 4 the minus 5 cancels it: back to 0. Position 5 stays 0. The first update stopped exactly where it was told to.

@7-8
At position 6 the plus 3 starts the second update: 3, and position 7 carries it to the end: 3. The real array is 0, 5, 5, 5, 0, 0, 3, 3.

@9
The last frame subtracts two prefixes, 3 minus 0, which here means the differences between positions 1 and 6 add up to 3: the value at position 6 is 3 more than the value at position 0. So the trade is this: a range add costs two point writes, and reading a value costs a prefix sum, which a Fenwick tree brings down to logarithmic time. Lazy propagation generalises the same idea to a segment tree. It records an update on the few nodes at the edges of the region it affects, as a pending tag, and lets it flow inward only when a later operation needs to look inside.
