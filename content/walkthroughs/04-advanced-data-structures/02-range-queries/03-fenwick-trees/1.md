@0
A Fenwick tree runs on one small trick: low bit of i, the value of the lowest set bit of i. It decides which block of elements each cell of the tree is responsible for. Here i is 12, which at 8 bits is 0 0 0 0 1 1 0 0. Its lowest set bit is bit 2, worth 4.

@1
To see why 12 AND minus 12 finds it, build minus 12 the way two's complement does: flip every bit, then add 1. Flipped, 12 becomes 1 1 1 1 0 0 1 1. The trailing zeros of 12 have become trailing ones, and the lowest set bit has become a 0.

@2
Now add 1. The carry runs through the trailing ones, turning them back to zeros, and stops at the lowest set bit, which becomes 1 again. Minus 12 is 1 1 1 1 0 1 0 0. Below that bit it matches 12; at that bit it matches 12; above it, it is still the exact opposite of 12.

@3-11
AND keeps a bit only when both rows have it. Working from the right: bits 0 and 1 are 0 in both, so 0. Bit 2 is 1 in both, so 1. From bit 3 up, every column has a 1 in one row and a 0 in the other, so every one of them comes out 0.

@12
12 AND minus 12 is 0 0 0 0 0 1 0 0, which is 4. Everything above the lowest set bit cancels, because minus 12 is the inverse of 12 there, and only the lowest set bit survives. Low bit of 12 is 4, so tree cell 12 covers the four elements ending at position 12: positions 9 to 12.

@13
One negation and one AND, constant time, no loop over the bits. A query walks down by subtracting low bit of i, and an update climbs by adding it, so both touch about log n cells.
