@0
An app, a cache, and a database behind it. This cache holds two keys, and the table lists them most recently used first. The rule, which is the whole policy: every access moves a key to the front, and when the cache is full, the key at the back, the one untouched for longest, is evicted. The keys accessed will be 1, 2, 1, 3, 4, 3, 4, the same order as the trace in the lesson.

@1-2
Key 1 is not cached, a miss, so it is loaded from the database and placed at the front. Then key 2, also a miss, goes in front of it. The cache is full: 2, then 1, with 1 at the back.

@3
Now key 1 again, and this time it is a hit. It jumps from the back to the front. Reads update recency, not just writes, so the order is now 1, 2, and key 2 is the least recently used.

@4
Key 3 is a miss, and the cache is full. The key at the back is 2, last used at step 2, so 2 is evicted and 3 is loaded and placed at the front. Notice what saved key 1: one read at step 3. Without it, 1 would have been the victim.

@5
Key 4 misses. Now the back of the list is key 1, last used at step 3, so 1 is evicted. The cache holds 4 and 3.

@6-7
Key 3 hits and moves to the front; then key 4 hits and moves back to the front. Each hit is just an unlink and a push to the front, and nothing is evicted. The cache ends with 4, then 3.

@8
Here is where recency alone fails. A one-off scan, a report or a crawler reading a handful of keys once each, marches every key through the front of the list and pushes every genuinely hot key out the back, so the next real requests all miss. Variants like LRU-K, ARC, or a small probationary segment as in W-TinyLFU admit a key to the main cache only on its second touch.

@9
The trade: with a hash map and a doubly linked list, every operation is constant time, and LRU adapts instantly when the working set shifts, which is why it is the default almost everywhere. But it tracks recency only, so it cannot tell a key read a thousand times from one read once a moment ago. And the exact list costs memory per entry, which is why Redis approximates LRU by sampling five keys and evicting the oldest of those.
