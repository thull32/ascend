@0
This is autocomplete with a trie, and it has two phases. First walk down to the node for the prefix, which costs one step per character. Then enumerate the subtree below it, emitting a suggestion at every terminal node, because every key down there starts with the prefix.

@1-3
Five words go in. Net creates 3 new nodes. Netflix shares those 3 and adds 4 more, and network shares the same 3 and adds its own 4.

@4-5
Nest shares only n and e, and adds 2 nodes. New shares n and e as well, and adds 1.

@6-9
Now the user types net. The walk follows n, then e, then t, and reaches the node for net. Every key in the subtree below it starts with net, so we enumerate it depth first, visiting children in sorted order.

@10
Net itself is terminal, so it is emitted as suggestion number 1. The walk does not stop there, because longer keys may follow below it.

@11-14
Next, the f branch. Netf, netfl and netfli are not terminal, just internal prefixes, each with a single child, so the walk descends through them. At netflix it finds a terminal node and emits suggestion number 2.

@15-18
Then the w branch. Netw, netwo and networ are internal prefixes again, and network is terminal: suggestion number 3. Notice the chains of one-child nodes. Most trie nodes look like this, and it is where the memory goes.

@19
The suggestions for net are net, netflix and network, already in lexicographic order with no sorting step, because children were visited in sorted order. The cost is the length of the prefix plus the size of the subtree.

@20
That second term is the catch. An empty prefix makes the subtree the whole trie. That is why production autocomplete does not walk at all: it precomputes the top few completions at each node, so a keystroke costs the prefix length plus those few.
