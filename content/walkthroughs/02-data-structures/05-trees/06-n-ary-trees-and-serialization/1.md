@0
Six nodes: 8 at the root, 3 and 10 below it, then 1 and 6 under 3, and 14 under 10. We want a string from which this exact tree can be rebuilt. A plain preorder listing is not enough, because two different shapes can share one. The fix is to write down the absence of a child too: a marker, the hash sign, for every empty slot.

@1-3
Preorder writes the node first, then its left subtree, then its right. So we emit 8, go left and emit 3, go left again and emit 1.

@4-5
Node 1 has no children, so it emits two markers, one for each empty side. Those markers are the whole trick: they record where the subtree under 1 ends.

@6-8
Back up to 3's right child: emit 6, and it is a leaf, so two more markers.

@9-10
Now the root's right side. Emit 10. Its left child is missing, so a single marker.

@11-13
Then 10's right child, 14, a leaf, with its two markers.

@14
The encoding is 8, 3, 1, marker, marker, 6, marker, marker, 10, marker, 14, marker, marker. Thirteen tokens for six nodes. That count is always the same: a binary tree with n nodes has n plus one empty child pointers, so the encoding is always two n plus one tokens. Now we decode it, reading the tokens in the same preorder.

@15-17
The first token, 8, becomes the root, and decoding immediately asks for its left subtree. The next token, 3, is attached as that left child, and it asks for its own left: 1, attached under 3. Each node joins the tree the moment its token is read. The build stack holds 8, 3 and 1, the chain of nodes still waiting for their children.

@18-19
Two markers: node 1's left and right are both empty, so node 1 is complete.

@20-22
Node 1 comes off the stack. The next token, 6, must be 3's right child, because 3's left is already finished, and the stack now holds 8, 3 and 6. Two markers close 6.

@23-24
Now 10 is read and attached as the root's right child, with only 8 and 10 on the stack. One marker says its left is empty.

@25-27
Then 14 becomes 10's right child, and its two markers are the last tokens.

@28
The stack unwinds back to empty, and the decoded tree is identical to the original. Every token was consumed exactly once, with no searching and no index map, so both directions are linear, and the recursion depth is the height. The markers are what make it unique: preorder plus explicit absences fixes the shape. One more trick from the lesson: you can validate such a string without building anything. Start with one open slot; each value fills one and opens two, each marker fills one, and the string is valid when the count never goes negative and ends at zero.
