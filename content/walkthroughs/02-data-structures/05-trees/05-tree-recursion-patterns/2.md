@0
We want the lowest common ancestor of 3 and 5, both highlighted: the deepest node that has both of them below it. In a general tree that takes a bottom-up search. This tree is a binary search tree, with 6 at the root, so the values tell us which way to go, and a single walk down from the root is enough. The rule: if both targets are smaller than the node, go left; if both are larger, go right; otherwise this node splits them, and it is the answer.

@1
At the root, 6. Both 3 and 5 are smaller than 6, so both are in the left subtree. Go left.

@2
At 2. Both 3 and 5 are larger than 2, so both are in its right subtree. Go right.

@3
At 4. Three is smaller and 5 is larger, so they sit on different sides of 4, and 4 is the lowest common ancestor. That took three comparisons and no recursion: the cost is the height. On a tree without the ordering, you fall back to the bottom-up version, where a node that hears back a hit from both children is the split point. Watch one trap there: if one target is missing from the tree, the bottom-up function still returns the other, and the caller cannot tell the difference unless it also returns flags saying which targets were found.
