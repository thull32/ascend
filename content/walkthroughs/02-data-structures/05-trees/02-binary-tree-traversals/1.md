@0
This is a binary search tree of nine keys, with 8 at the root. Inorder has one rule: finish the left subtree, then visit the node, then do the right subtree. You cannot visit a node when you first reach it. Because this is a search tree, everything left of a node is smaller and everything right is larger, so that rule should print the keys in sorted order. Watch the call stack on the side; it holds the path back up.

@1-3
We enter 8 and, before visiting anything, go left to 3, then left again to 1. The stack now holds 8, 3 and 1.

@4
Node 1 has no left child, so its left subtree is trivially finished. Visit it: the output starts with 1. Its right side is empty too.

@5-6
We return from 1 and pop it off the stack. Back at 3, its left subtree is now done, so 3 is visited. The output reads 1, 3. Now 3 turns to its right child, 6.

@7-9
Enter 6, and dive left again, to 4. Node 4 has no left child, so it is visited at once. Output: 1, 3, 4. The stack is four deep here, 8, 3, 6 and 4, the deepest it gets.

@10-11
Pop 4. Node 6 has finished its left side, so 6 is visited, then we go right to 7.

@12-14
Node 7 is a leaf: enter, visit, pop. The output is 1, 3, 4, 6, 7.

@15-17
Now the unwinding pays off. We return from 6, then from 3, and land back at the root. Its entire left subtree is finished, so 8 is finally visited, sixth, after every key smaller than it.

@18-19
The root's right side starts at 10. It has no left child, so 10 is visited straight away, and we head right to 14.

@20-22
At 14 we go left first, to 13. It is a leaf, so it is visited: 1, 3, 4, 6, 7, 8, 10, 13.

@23-24
Pop 13. Node 14's left is done, so 14 is visited last of all.

@25-27
Nothing remains on any right side. The stack unwinds through 14, 10 and 8 until it is empty.

@28
The output is 1, 3, 4, 6, 7, 8, 10, 13, 14: sorted, because the search tree invariant makes left, node, right ascending. Every node was entered and left once, so the walk is linear in the number of nodes, and the stack holds at most one node per level. On a tree that is not a search tree, inorder is not sorted; the sortedness belongs to the invariant, not to the traversal. This is the order you reach for whenever you need sorted output from a search tree, the k-th smallest key, or a validity check.
