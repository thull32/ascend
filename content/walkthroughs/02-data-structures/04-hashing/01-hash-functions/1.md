@0
Four empty buckets, each the head of a chain. A key's bucket is its hash modulo 4, and the hash here is Java's string hash: multiply by 31, add the next character, repeat. Keys that land in the same bucket simply share its chain. We are about to insert six keys that differ only in their last digit, user 1000 through user 1005, which is exactly the kind of input a weak hash handles badly.

@1-2
User 1000 hashes to 337,474,643. Modulo 4 that is 3, so it goes into bucket 3, which is empty. One entry, load factor a quarter.

@3-4
User 1001 hashes to 337,474,644: exactly one more. The last character is multiplied by 31 to the power 0, so consecutive keys get consecutive hashes. That is the missing avalanche. Here, though, one more means the next bucket around, 0, and it lands there.

@5-8
User 1002 and user 1003 continue the pattern: one more each time, so buckets 1 and then 2. Four keys, four buckets, one entry in each, and the load factor is 1.

@9-11
User 1004 hashes to bucket 3 again, which already holds user 1000. The insert walks the chain, compares against user 1000, finds a different key, reaches the end and appends. Bucket 3's chain now has length 2. That is a collision, and with five keys in four buckets, an unavoidable one.

@12-14
User 1005 does the same in bucket 0: one comparison against user 1001, then an append. Six keys, and the chains are 2, 1, 1 and 2.

@15-17
Now a lookup for user 1003. Its hash points to bucket 2, the chain has one entry, and the first comparison matches. The value is 4, found after one comparison.

@18
Six keys in four buckets is a load factor of 1.5, which is also the expected chain length, and a lookup costs one plus the load factor. Notice what did not happen: these near-identical keys spread evenly, because in a chained table they fall into adjacent buckets, which is harmless. Put the same keys into a linear-probing table and adjacent slots become one long cluster. That is why weak avalanche is a problem for some tables and not others, and why the table, or a finaliser, must spread the bits.
