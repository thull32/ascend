@0
A binary search tree built from 30, 10, 50, 20, 40 and 60. The root is 30; 10 hangs to its left with 20 below it, and 50 to its right with 40 and 60 below. We search for 45, which is not in the tree. A hash map could only tell you that. The tree can tell you more: the nearest key below 45, called the floor, and the nearest key above it, the ceiling. Two candidates, both empty for now, ride along with the search.

@1
Start at the root, 30. Forty-five is bigger, so the target can only be in the right subtree, and the whole left side, 10 and 20, is ruled out by one comparison. Thirty is the first key we have passed that is below 45, so it gets the floor label.

@2
At 50, 45 is smaller, so go left. Sixty is ruled out. Fifty is the first key passed that is above 45, so it becomes the ceiling.

@3
At 40, 45 is bigger, so go right. Forty is below 45 and closer to it than 30, so the floor label moves from 30 to 40.

@4
The right child of 40 is empty, so 45 is not in the tree, after 3 comparisons. But the walk has already answered the two questions a hash map cannot. The last node where we turned right, 40, is the floor. The last node where we turned left, 50, is the ceiling. Both come from the same root-to-leaf walk, so they cost the height of the tree, logarithmic when it is balanced, while a hash map would have to scan every key to answer either one.
