@0
A small hash table with 4 buckets and chaining. Think of the buckets as the four cache servers from the opening story. A key's bucket is its hash modulo the bucket count, here with FNV-1a as the hash. When the entries outnumber the buckets, this table grows from 4 buckets to 5, just as the cluster gained a fifth server. So a key's place depends on two things: its hash, which never changes, and the modulus, which is about to.

@1-8
Four keys go in. User 1 hashes to about 1.83 billion, which modulo 4 is bucket 3. User 2 lands in bucket 2, user 3 in bucket 1, and user 4 in bucket 0. One key per bucket.

@9-11
User 5 also hashes to bucket 3. It is compared with user 1, a different key, and appended behind it: a collision. Five entries in four buckets is a load factor of 1.25, over the bound of 1.

@12
So the table grows to 5 buckets, and every entry has to be placed again. The hash values are unchanged; only the modulus has gone from 4 to 5.

@13-16
Watch where they go. User 4 was in bucket 0 and is now in bucket 4. User 3 goes from 1 to 0, user 2 from 2 to 1, and user 1 from 3 to 2. Every one of them moves.

@17
User 5 is the exception: its hash modulo 5 is 3, the same bucket number it had modulo 4, so it stays put. It is still copied into the new array, but it is the only key that ends up where it was.

@18
The rehash is done: five entries recomputed, and four of the five changed bucket. That is 80 percent, exactly the lesson's figure. A key keeps its bucket only when its hash gives the same remainder modulo 4 and modulo 5, and for random hashes that happens for 1 key in 5.

@19
Inside one process this is harmless: a brief pause that touches every key. Now make the buckets servers. A key's server is its hash modulo the server count, and the data does not move for free. Going from 4 servers to 5 sends 80 percent of keys to a server that has never seen them, and every one of those is a cache miss that lands on the database. The ideal is that only the new server's fair share, one fifth, moves. That is the problem consistent hashing solves.
