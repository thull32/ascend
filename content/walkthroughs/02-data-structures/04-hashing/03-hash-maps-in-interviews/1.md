@0
Six empty buckets, with a key's bucket chosen by its hash modulo 6. The keys arriving are already canonical: each word has been reduced to its sorted letters, so eat, tea and ate all become A-E-T. The value stored is how many words have joined that group so far. The point to watch is that a repeated key never creates a second entry.

@1-2
The first key, A-E-T, hashes to 96,464, which is bucket 2. The bucket is empty, so the entry goes in with count 1.

@3-4
A-N-T, from a word like tan, hashes to bucket 5, also empty. Count 1.

@5-7
A-E-T again, from a second anagram. Same key, so same hash, so same bucket, 2. The chain's first entry is compared and it is equal, so the existing entry is found and its value is overwritten in place, from 1 to 2. Nothing new was added: a map never holds two entries for one key, and that is exactly what makes grouping work.

@8-10
A-B-T, from bat, hashes to bucket 5, where A-N-T already sits. The insert compares against A-N-T, finds a different key, reaches the end of the chain and appends. That is a collision: two different groups sharing one bucket, kept apart by comparing the full keys.

@11-13
A-E-T a third time. Bucket 2, one comparison, found, and the count becomes 3.

@14-16
A-N-T a second time. Bucket 5, and this time the very first entry in the chain matches, so its count goes to 2. A-B-T, behind it, is not touched.

@17-19
Finally, look up A-E-T. Bucket 2, one comparison, and the answer is 3: three words in that anagram group.

@20
Six inserts produced only three entries in six buckets, a load factor of one half. The hashing was never the hard part. The hard part was choosing a key under which equal things become identical, here the sorted letters, and building that key costs time proportional to the word's length for every word. In the interview, say what the key is before you say hash map.
