@0
Five buckets, each the head of a chain of entries. A key's bucket is its 32-bit FNV-1a hash modulo 5, and when two keys land in the same bucket, nothing is lost: they simply share the chain. Hold onto one fact, because it is the whole cost model: a lookup costs one hash, plus one comparison for every chain entry it walks.

@1-4
Set apple. Its hash modulo 5 is 2, the bucket is empty, so apple goes in as the first entry there. Set grape: bucket 0, also empty.

@5-7
Set melon. Its hash modulo 5 is 0, the same bucket as grape. The insert walks the chain to check that melon is not already there: it compares melon with grape, finds a different key, reaches the end of the chain and appends. Bucket 0 now has a chain of two. That is a collision, handled.

@8-9
Set kiwi: bucket 1, empty. Four keys in five buckets, a load factor of 0.8.

@10-13
Now get melon. Hash to bucket 0, compare with grape: different, keep walking. Compare with melon: equal. Found after 2 comparisons, and the value is 3. A key at the back of a chain pays for every key in front of it.

@14-16
Get lemon, which was never inserted. Its hash sends it to bucket 1, where kiwi sits. One comparison, different key, and the chain is exhausted, so lemon is absent. A miss has to walk the whole chain, because the key could be anywhere in it.

@17-20
Delete apple. Hash to bucket 2, one comparison, found. Removing it is one pointer change: unlink the node from the chain. Nothing else in the table moves, and the load factor drops to 0.6.

@21-22
Get apple again. Bucket 2 is now empty, so apple is absent after one hash and zero comparisons, the cheapest possible miss.

@23
Three keys in five buckets: a load factor of 0.6, which is the expected chain length. A successful lookup costs about one plus half the load factor in comparisons, and a miss about the load factor, so keep the load factor bounded by resizing and every operation stays constant time on average. The price chaining pays is not in comparisons but in memory: every entry is a separate node, and every step along a chain is a pointer to follow, usually a cache miss.
