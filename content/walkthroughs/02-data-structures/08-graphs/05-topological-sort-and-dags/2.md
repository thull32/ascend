@0
The same six vertices and six edges, sorted a second way. A vertex in a depth-first search finishes only after everything reachable from it has finished. So if you list vertices as they finish and read that list backwards, every vertex comes before everything it leads to. The search never has to find a source first; the reversal does that work.

@1-2
The outer loop starts at 0. Vertex 0 has no outgoing edges, so it finishes at once, the first entry in the finish list.

@3-4
Next, 1. It has no outgoing edges either, and finishes immediately.

@5-8
Then 2. Its edge leads to 3, so enter 3. 3's only edge leads to 1, which is already finished, so 3 finishes, and then 2 finishes after it. That ordering is the whole point: 2 finished after 3, so in the reversed list 2 will come before 3.

@9-10
Enter 4. Both its edges lead to vertices already finished, 0 and 1, so 4 finishes straight away.

@11-12
Enter 5. Its targets, 2 and 0, are finished too, so 5 finishes last.

@13
The finish order was 0, 1, 3, 2, 4, 5. Reversed, it is 5, 4, 2, 3, 1, 0, and every edge points forward. Kahn's algorithm gave 4, 5, 2, 0, 3, 1 on the same graph. Both are valid: topological orders are rarely unique. In an interview, write Kahn's unless you specifically want the finish order: it is iterative, and it gives the order and the cycle check in one loop.
