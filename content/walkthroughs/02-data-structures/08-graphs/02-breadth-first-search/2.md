@0
A 5 by 5 grid, where 1 is a wall, and we want the shortest path from the top-left corner to the bottom-right. Every move costs the same, one step, and that is the condition for breadth-first search: the first time it reaches a cell is the fewest moves to it. Walls simply have no edges.

@1-4
Start at row 0, column 0, at distance 0. Walls block the cell below it, so the only way is right: row 0 column 1 at distance 1, then column 2 at distance 2. Column 3 is a wall, so the path turns down to row 1, column 2, at distance 3.

@5
Row 2, column 2 is expanded at distance 4. This row is open, so the search can spread in both directions from here.

@6-7
Now the wavefront splits. Row 2, column 3 and row 2, column 1 are both expanded at distance 5. Each ring of cells is one level of the search, and the queue keeps the levels in order.

@8-9
At distance 6: row 2, column 4 on the right, and row 2, column 0 on the left.

@10-12
At distance 7, three cells: row 3, column 4 heading down toward the goal, row 1, column 4 heading up, and row 3, column 0 down the left side. Expanding row 3, column 4 has already put the goal on the queue.

@13
The goal is reached at distance 8, and the path is highlighted: right twice, down twice, right twice, down twice. Each cell entered the queue once, so the cost is proportional to the number of cells. The traps in grid code: check bounds before indexing, check walls and visited together, and mark a cell visited when you enqueue it, or one cell can be enqueued up to four times.
