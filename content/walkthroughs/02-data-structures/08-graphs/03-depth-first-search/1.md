@0
Eight vertices and twelve directed edges, built to contain every kind of edge depth-first search can meet. DFS commits: it follows one edge as deep as it can, and backs up only when stuck. The call stack holds exactly the current path, and that is the idea to hold onto. A vertex on the stack is grey, still being explored. Reaching a grey vertex again means you have walked in a circle.

@1-3
Enter 0. Its first edge leads to 1, so enter 1. The only edge out of 1 leads to 3, so enter 3. Three vertices deep, and nothing has been finished yet.

@4
Now 3 examines its edge to 0. Vertex 0 is still on the stack, grey, an ancestor of 3 on the current path. That is a back edge, and a back edge means a cycle: 0, 1, 3, and back to 0.

@5-6
3's other edge leads to 4, which is new, so enter 4. Vertex 4 has no outgoing edges, so it finishes at once.

@7-8
With nothing left to explore, 3 finishes, then 1. Notice the order: 0's own edge to 3 has not been examined yet. It is examined only after 1's whole subtree is done, and by then 3 is finished, so that edge is a shortcut to a descendant, not a cycle.

@9-12
Back in 0, the edge to 2 leads somewhere new. Enter 2, and the search dives again: 5, then 6, then 7, four deep.

@13
7's edge leads back to 5, which is still on the stack. Second back edge, second cycle: 5, 6, 7, and back to 5.

@14-18
Now everything unwinds. 7 finishes, then 6, then 5, then 2, and finally 0, the first vertex in and the last one out.

@19
Each label shows a vertex's discovery and finish times, and they nest like parentheses: 1 was discovered after 0 and finished before it, because it is 0's descendant. Each vertex was entered once and each list scanned once, so the cost is V plus E. Two takeaways. A cycle exists exactly when there is a back edge, an edge to a grey vertex, and treating any visited vertex as a cycle is the classic false positive: the edge from 2 to 1 would report one. And sorting by decreasing finish time gives a topological order, when the graph has no cycles.
