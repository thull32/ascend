@0
Six nodes: 4, 8, 15, 16, 23 and 42, each holding a value and a pointer to the next. The walk starts with curr at the head. A list has no index. To reach node k you must follow k next pointers, one after another, and that "one after another" is the whole cost story.

@1-3
Visit 4: read its value, then follow its next pointer to reach 8. Visit 8, follow the pointer to 15. Visit 15, follow it to 16. Notice what the processor cannot do here: it cannot start fetching node 16 until node 15 has arrived, because the address of 16 is stored inside 15. Every load depends on the one before.

@4-6
Visit 16, then 23, then 42. At 42 the next pointer is null: the list ends here.

@7
curr is null, so the loop stops. Six nodes, one pointer load each: linear time, constant extra space, the same big O as scanning an array. The difference is in the constant. An array scan lets the hardware prefetcher run ahead, while a list walk can only ever have one miss in flight. If every node misses to main memory, a million nodes take about 100 milliseconds against roughly 0.4 milliseconds for a million-element array. Real traversals commonly land between 10 and 50 times slower, depending on how scattered the nodes are.
