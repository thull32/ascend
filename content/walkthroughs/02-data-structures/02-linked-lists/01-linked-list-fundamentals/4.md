@0
A sorted list, 2, 5, 9, 14, and we want to insert 7 so it stays sorted. Walk with two pointers, prev and curr, until curr is null or holds a value of at least 7. The new node goes between them.

@1-2
2 is less than 7: not yet, so prev takes curr's place and curr moves on. 5 is less than 7: step again. prev is now on 5.

@3
curr reaches 9, the first node not smaller than 7. The spot is found: between 5 and 9. That walk was the linear part.

@4
Now the splice, in a deliberate order. First, point the new node at 9. Set the new node's link first, and the rest of the list is never unreachable, even for a moment.

@5
Then point 5 at the new node. The list reads 2, 5, 7, 9, 14, and the splice is complete. Two pointer writes, constant time.

@6
Inserted at position 2. Finding the spot cost linear time; the splice itself cost constant time, and no element moved, which an array cannot offer for an insert in the middle. But that is the honest rule for linked lists: they win only when you already hold a pointer to the position. If you are going to search for the position anyway, as we did here, use an array.
