@0
The array is 1, 3, 4, 2, 2: five integers, each between 1 and 4. Read it as a function. Each index points to the index named by its value, so index 0 points to 1, index 1 points to 3, 3 points to 2, 2 points to 4, and 4 points back to 2. Every node has exactly one outgoing edge, which makes this a linked list in disguise, and the "next" pointer is just an array lookup. So Floyd's two pointers work here unchanged. Slow and fast both start at index 0.

@1-2
Each iteration, slow takes one step and fast takes two. After the first, slow is at 1 and fast at 3. After the second, slow is at 3 and fast at 4. No value is 0, so nothing ever points back at index 0: it is always in the tail, never in the cycle.

@3
After the third iteration slow has entered the cycle at 2, while fast has gone round from 4 to 2 and back to 4.

@4
After the fourth, slow steps to 4, and fast goes round once more and lands on 4 too. They meet, so there is a cycle. Four is the smallest multiple of the cycle length, 2, that is at least the tail length, 3.

@5
Phase 2 finds where the cycle starts. A new pointer, p, goes back to index 0, while slow stays at the meeting point, 4. Now both move one step at a time.

@6-7
p moves to 1 while slow moves to 2; then p moves to 3 while slow goes round to 4.

@8
On the third step p moves to 2, and slow moves to 2 as well. They meet at the entry of the cycle.

@9
The cycle is 2 to 4 and back to 2, and its entry, 2, is the node with two incoming edges: one from index 3 and one from index 4, because both of those slots hold the value 2. Five indices but only four possible targets means some target must have two incoming edges, and that node is both the entry of the cycle and the duplicated value. Floyd found it in linear time and constant space, without modifying the array. One constraint is load-bearing: the values must be between 1 and n. A 0 would put index 0 on a cycle, and phase 2 could return the wrong node.
