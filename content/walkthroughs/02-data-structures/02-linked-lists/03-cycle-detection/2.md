@0
The array is 1, 3, 4, 2, 2: five integers, each between 1 and 4. Read it as a function. Each index points to the index named by its value, so index 0 points to 1, index 1 points to 3, and so on. Every node has exactly one outgoing edge, which makes this a linked list in disguise, and the "next" pointer is just an array lookup.

@1-3
Follow the edges from index 0. Enter 0, then 1, then 3. No value is 0, so nothing ever points back at index 0: it is always in the tail, never in a cycle.

@4-5
From 3 the edge leads to 2, and from 2 to 4.

@6
And from 4 the edge leads back to 2, a node already on the current path. That is the cycle: 2, 4, 2. Look at node 2. It has two incoming edges, one from index 3 and one from index 4, because both of those slots hold the value 2. Five indices but only four possible targets means some target must have two incoming edges, and that node is both the entry of the cycle and the duplicated value. Floyd's two pointers find it in linear time and constant space, without modifying the array. One constraint is load-bearing: the values must be between 1 and n. A 0 would put index 0 on a cycle, and phase 2 could return the wrong node.
