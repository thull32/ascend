@0
The list is 1, 2, 3, 4, 5, and we will reverse it in place with three pointers. prev is the part already reversed, empty so far. curr is the node being flipped, starting at 1. And next will save the rest of the list before we cut the link to it. Each node gets the same three moves: save, flip, advance.

@1
Save first. next holds 2, so the rest of the list stays reachable once we touch the pointer of node 1.

@2
Flip. Node 1 now points at prev, which is null, so 1 becomes the new tail.

@3
Advance. prev moves to 1, and curr moves to 2, the node we saved. The reversed part is just 1.

@4-6
Node 2: save 3, point 2 back at 1, advance. The reversed part reads 2, 1.

@7-12
The same three moves for node 3, then for node 4. Each flip turns one arrow around, and the reversed part grows from the front: 3, 2, 1, then 4, 3, 2, 1.

@13-15
Node 5 is the last. Saving its next gives null. Flip it back to 4, and advance: prev is now 5, and curr is null.

@16
curr is null, so the loop stops, and the new head is prev: 5, 4, 3, 2, 1. One pass, linear time, constant extra space, and every next pointer rewritten exactly once. The line people get wrong is the save. Flip before you save, and the rest of the list becomes unreachable after one iteration, with no error raised. Say "save next" out loud before you touch the pointer.
