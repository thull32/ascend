@0
A min-heap is an array read as a tree. The children of position i sit at two i plus one and two i plus two, so there are no pointers at all. Two rules hold at all times. The shape rule: the array has no gaps, so the tree is complete. The order rule: every parent is no larger than its children. Nothing is promised about siblings or cousins; that weak order is just enough to keep the minimum at position 0. We will push 5, 3, 8, 1, 9 and 2, then pop six times.

@1
Push 5. Every push appends at the end, the next free slot, which keeps the shape rule. Here that is position 0, the root.

@2-3
Push 3. It lands at position 1, whose parent is position 0, holding 5. Three is smaller than its parent, so they swap. Sifting up stops at the root: the heap is 3, 5.

@4-5
Push 8 at position 2. Its parent is 3, and 8 is not smaller, so it stays. No swaps at all.

@6-8
Push 1 at position 3. Its parent is 5 at position 1: smaller, swap. Now at position 1, its parent is 3 at the root: smaller again, swap. One has climbed all the way to the top. The array is 1, 3, 8, 5.

@9-10
Push 9 at position 4. Its parent is 3, and 9 is larger, so it stays where it landed.

@11-13
Push 2 at position 5. Its parent is 8: swap. Its new parent is 1, and 2 is not smaller, so it stops halfway up. Six pushes, four swaps. Each swap climbs one level, so a push is at most the height, logarithmic, and on random input most pushes stop after zero or one swap.

@14
Now pop. The minimum, 1, is at the root, but removing it directly would leave a hole. Instead, the last element, 8, moves into the root, which keeps the array gap-free, and then it sifts down.

@15-16
The root's children are 3 and 2. Swap with the smaller one, 2. It has to be the smaller, because the child that moves up becomes the parent of the other. Eight is now a leaf, so it stops. The heap is 2, 3, 8, 5, 9.

@17-20
Pop again: 2 leaves, and the last element, 9, moves to the root. Its children are 3 and 8, so it swaps with 3. Then its only child is 5, so it swaps again, and stops at a leaf. Notice that pop goes nearly all the way down, because the element moved to the root came from the bottom, where the large values live.

@21-23
Pop 3. Nine moves to the root again, swaps with the smaller child, 5, and lands on a leaf.

@24-25
Pop 5. Eight moves up; its only child is 9, which is larger, so nothing moves.

@26-28
Pop 8, leaving 9 alone at the root. Then pop 9, and the heap is empty.

@29
The pops came out 1, 2, 3, 5, 8, 9: sorted, because each pop takes the current minimum. Every push and every pop touches one path from root to leaf, so both are logarithmic, with a plain array and no pointers.
