@0
The array holds only 0s, 1s and 2s: 2, 0, 2, 1, 1, 0. We sort it in one pass with three pointers, low, mid and high, which split it into four regions. Before low, all 0s. From low up to mid, all 1s. After high, all 2s. And from mid to high, the elements nobody has looked at yet. Each step looks at the element under mid.

@1
The element under mid is a 2. Swap it with the element under high, the last 0, and shrink high by one. The array becomes 0, 0, 2, 1, 1, 2. Mid does not move, because the value that just arrived came from the unknown region and has not been examined yet.

@2-3
And indeed it is a 0. A 0 swaps with the element under low and both pointers advance. Here low and mid are on the same cell, so the swap changes nothing. The next element is also a 0, with the same result. The 0s region now holds two elements.

@4
Mid reaches a 2 at position 2. Swap it with position 4, which holds a 1, and shrink high. The array reads 0, 0, 1, 1, 2, 2. Once again mid stays put, so the 1 that arrived will be checked.

@5-6
It is a 1, already in the middle region, so mid simply advances. The next element is a 1 as well. Mid advances again and passes high, and there is nothing unknown left.

@7
Sorted, in one pass, with constant extra space. The trap is in the 2 case: advancing mid after swapping with high skips an element nobody examined. In the first step it would have skipped the 0 that arrived at position 0. That bug only shows up on some inputs, which is why you trace this one by hand. This three-way split is also how quicksort copes with many equal keys.
