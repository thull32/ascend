@0
Two stacks side by side: the main stack, and a min stack beside it. The idea is that the top of the min stack is always the minimum of everything currently in the main stack, so asking for the minimum is a single read, with no scan.

@1
Push 5. The min stack is empty, so 5 is also the minimum, and it goes onto both.

@2
Push 3. Three is at most the current minimum of 5, so it goes onto the min stack too. The minimum is now 3.

@3
Push 7. Seven is bigger than 3, so this version leaves the min stack alone, which saves space. The minimum is still 3.

@4
Push another 3. It equals the current minimum, and this is the subtle part: ties are pushed onto the min stack as well. The min stack now holds 5, 3, 3.

@5
Get min reads the top of the min stack: 3.

@6
Pop. Out comes the second 3, and because it equals the top of the min stack, that is popped too. The minimum is still 3, because the first 3 is still in the main stack and still on the min stack. If the tie had not been pushed, this pop would have removed the only 3 from the min stack and lost the minimum while a 3 remained.

@7
Get min: 3.

@8
Pop 7. It is not the current minimum, so the min stack is unchanged.

@9-10
Pop the first 3. It equals the min stack's top, so both pop, and the minimum reverts to 5. Get min confirms it: 5.

@11
Push, pop, top and get min were all constant time. The price is extra space: up to one min stack entry per element when pushes keep decreasing. This was the space-saving version, which pushes only on a new minimum or a tie. The simpler version, and the one to write on a whiteboard, pushes the running minimum onto the second stack on every push and pops both together, so there is no equality rule to get wrong.
