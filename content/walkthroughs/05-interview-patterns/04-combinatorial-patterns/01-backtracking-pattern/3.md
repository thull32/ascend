@0
Place 4 queens on a 4 by 4 board so that none attacks another. One queen per row, so the search only chooses a column for each row. A column is safe if no earlier queen shares it, or shares a diagonal, where row minus column is equal, or an anti-diagonal, where row plus column is equal. Keeping those three in sets makes each test constant time.

@1-2
Row 0: column 0 is safe, so place a queen at the top-left corner and move to row 1.

@3-6
Row 1: column 0 shares the column, and column 1 shares the diagonal. Column 2 is safe: place it.

@7-12
Row 2 is where it goes wrong. Column 0 is the first queen's column. Column 1 is on the anti-diagonal of the queen at row 1, column 2. Column 2 is on the first queen's diagonal, and column 3 is on the diagonal of the queen in row 1. No column works: a dead end, so return false to row 1.

@13-14
Backtrack: remove the queen at row 1, column 2, and try the next column. Column 3 is safe.

@15-17
Row 2 again: column 0 is still the first queen's column, but column 1 is safe. Three queens are down.

@18-23
Row 3: column 0 is attacked through its column, column 1 through the anti-diagonal of the queen at row 1, column 2 through the diagonal of the queen at row 2, and column 3 through the first queen's diagonal. Another dead end.

@24-27
Back in row 2, remove the queen at column 1 and try the rest: column 2 is on the first queen's diagonal, and column 3 shares the column of the queen in row 1. Row 2 is exhausted too.

@28-30
So row 1 has also run out of columns. The failure unwinds all the way to row 0: with a queen in the corner, no solution exists. Remove it and try column 1.

@31-36
Row 0, column 1. In row 1, column 0 is on its anti-diagonal, column 1 is its column, and column 2 is its diagonal. Column 3 is safe.

@37-38
Row 2: column 0 is safe immediately.

@39-42
Row 3: columns 0 and 1 are taken by earlier queens. Column 2 is safe.

@43-44
All four queens are placed: columns 1, 3, 0 and 2. That took 8 placements and 9 calls, against 4 to the power 4, which is 256, boards by brute force. Every rejection was a constant-time set lookup, and every dead row cut off its whole subtree, which is the whole point: backtracking prunes as soon as a partial answer cannot be completed.
