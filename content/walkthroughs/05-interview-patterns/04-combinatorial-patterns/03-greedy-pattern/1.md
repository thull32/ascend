@0
The array is minus 2, 1, minus 3, 4, minus 1, 2, 1, minus 5 and 4, and we want the largest sum of any contiguous run. Kadane's scan keeps two numbers: the current running sum, and the best seen so far. At each element there is one decision: extend the running subarray, or start fresh here. And the rule is greedy: a running sum that has gone negative is a burden, because anything that extends it would do better without it.

@1
The first element starts the run. Current is minus 2, and so is best.

@2
Next is 1. Minus 2 plus 1 is less than 1 on its own, so the old run is dropped and a new one starts at index 1. Current and best are both 1.

@3
Minus 3 extends the run: current falls to minus 2. Best stays 1.

@4
Now 4. Minus 2 plus 4 is only 2, less than 4 alone, so the negative running sum is dropped again, and the run restarts at index 3. Current and best are 4.

@5-7
From here the run keeps extending. Minus 1 takes current to 3, but it is still positive, so it is worth keeping. Then 2 makes it 5, a new best, and 1 makes it 6, another new best.

@8-9
Minus 5 drops current to 1. That hurts, but 1 is still positive, so the run is not abandoned. The final 4 lifts it to 5, which does not beat 6.

@10
The maximum subarray sum is 6, from index 3 to index 6: 4, minus 1, 2 and 1. One pass, constant space. Notice the greedy choice never looks ahead: the reset argument says a negative prefix can never help any later subarray, so dropping it the moment it goes negative is always safe. That proof is what separates a correct greedy from a plausible one.
