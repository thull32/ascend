@0
A stack that can also report its minimum in constant time. A second stack, the min stack, holds the running minimum, and its top is always the minimum of everything currently in the main stack. Watch the comparison used when pushing, because one character decides whether this works.

@1
Push 5. The min stack is empty, so 5 is the minimum and goes there too.

@2
Push 3. Three is less than or equal to the current minimum, 5, so it goes onto the min stack as well.

@3
Push 7. Seven is larger than the minimum, 3, so the min stack is left alone.

@4
Push another 3. It is equal to the current minimum, and equal counts, so this second 3 is pushed onto the min stack too. That is the line that matters.

@5
Get the minimum: read the top of the min stack, 3, with no scan of the main stack.

@6-7
Pop. The 3 comes off, and it equals the min stack's top, so that comes off too. But the min stack still holds the first 3 underneath, so the minimum is still 3, which is right: a 3 is still on the main stack.

@8-9
Pop again: 7 is not the minimum, so the min stack is untouched. Pop once more: the first 3 comes off, matches the min stack's top, and that comes off as well. The minimum reverts to 5.

@10
Get the minimum: 5.

@11
Push, pop, top and get minimum are all constant time, at the cost of up to n extra entries when the pushes keep decreasing. The trap is the comparison. With strictly less than, the second 3 would never have been recorded, the first pop would have removed the min stack's only 3, and get minimum would have answered 5 while a 3 was still on the stack.
