@0
Brian Kernighan's trick: n AND n minus 1 clears the lowest set bit of n. So the number of times you can apply it before reaching 0 is the number of set bits. We will run it on 12, 7 and 8.

@1
12 is 1 1 0 0 in binary. The count starts at 0.

@2
Subtracting 1 borrows through the trailing zeros. The lowest set bit, bit 2, flips to 0, every bit below it flips to 1, and the bits above are untouched. 11 is 1 0 1 1.

@3
AND the two together. Below bit 2, 12 has only zeros, so those columns give 0. Bit 2 is now 0 in 11, so it gives 0 too, and bit 3 is untouched. Exactly the lowest set bit disappears. That leaves 8, and the count is 1.

@4-5
Again on 8. The lowest set bit is bit 3. Subtract 1, AND, and it vanishes, leaving 0. The count is 2.

@6
12 has 2 set bits, found in 2 steps. The loop costs one step per set bit, not one per bit of the word.

@7-14
Now 7, which is 0 1 1 1. Its lowest set bit is bit 0. Clear it to get 6, then bit 1 to get 4, then bit 2 to get 0. Three steps, three set bits.

@15-18
And 8, which is 1 0 0 0. The borrow runs through three trailing zeros, flipping them all to 1, and the AND clears the single set bit. One step.

@19
One step per set bit is the whole point. It is why the popcount loop costs the number of set bits, and why counting bits has a second recurrence: the count for i is the count for i AND i minus 1, plus one, since that smaller number is already filled. Popcount itself underpins Hamming distance, bitset sizes and the iteration order of subset dynamic programming, and many CPUs expose it as a single instruction.
