@0
Two numbers in binary, at four bits: 5 is 0 1 0 1, and 3 is 0 0 1 1. Hold onto one sentence: a bitwise operator works on each column on its own, and never looks at its neighbours. No carries, no borrows.

@1
First, AND. A result bit is 1 only when both bits are 1. We go from the rightmost column, bit 0, to the left.

@2-5
Bit 0 is 1 and 1, which gives 1. Bit 1 is 0 and 1, bit 2 is 1 and 0, and bit 3 is 0 and 0, all of which give 0.

@6
5 AND 3 is 0 0 0 1, which is 1. AND is a mask: it keeps only the bits set in both, which is how you extract a field.

@7-11
Next, OR, where a result bit is 1 when either bit is 1. The first three columns each have at least one 1, so they give 1. Only bit 3, 0 and 0, gives 0.

@12
5 OR 3 is 0 1 1 1, which is 7. OR sets bits without disturbing the others.

@13-17
Last, XOR, where a result bit is 1 when the bits differ. Bit 0 is 1 and 1, the same, so 0. Bits 1 and 2 differ, so 1. Bit 3 is 0 and 0, so 0.

@18
5 XOR 3 is 0 1 1 0, which is 6. XOR toggles: apply the same mask twice and you are back where you started, and anything XOR itself is 0.

@19
So 5 AND 3 is 1, 5 OR 3 is 7, and 5 XOR 3 is 6, each in constant time, because the hardware evaluates every column at once. Now put two of them together. XOR is addition with the carries thrown away, and AND marks exactly the columns that would carry. Shift the AND left by one and you get the carry, 2, and 6 plus 2 is 8, the real sum. The add-without-plus loop repeats that split until the carry is 0.
