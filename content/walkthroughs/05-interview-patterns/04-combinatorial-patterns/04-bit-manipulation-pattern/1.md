@0
Two numbers in binary, at four bits: 5 is 0 1 0 1, and 3 is 0 0 1 1. Hold onto one sentence: in every column, XOR gives the sum digit and AND gives the carry out. So a plus b equals a XOR b, plus twice a AND b, and adding without a plus sign is just that split, repeated.

@1-5
First, XOR: a result bit is 1 when the two bits differ. From the right: bit 0 is 1 and 1, which gives 0. Bit 1 is 0 and 1, which gives 1. Bit 2 is 1 and 0, which gives 1. Bit 3 is 0 and 0, which gives 0.

@6
5 XOR 3 is 0 1 1 0, which is 6. That is the sum of each column with the carries left out. In bit 0, 1 plus 1 should be 0 carry 1, and XOR wrote the 0 and dropped the carry.

@7-11
Now AND: a result bit is 1 only when both bits are 1. Bit 0 is 1 and 1, so 1. Every other column has at least one 0, so 0.

@12
5 AND 3 is 0 0 0 1, which is 1. The one set bit is exactly the column that carried: bit 0.

@13
A carry belongs one column to the left, so shift the AND left by one: 0 0 1 0, which is 2. Now 5 plus 3 has become 6 plus 2, and 6 plus 2 is 8, the sum. But adding 6 and 2 can carry too, so the loop repeats the split, with a equal to 6 and b equal to 2.

@14-16
6 XOR 2 is 4, and the carry, 6 AND 2 shifted left, is 4. Then 4 XOR 4 is 0, and the carry is 8. Then 0 XOR 8 is 8, and the carry is finally 0. At every step the sum of the pair stays 8; only the split changes, with the carry's lowest set bit climbing at least one column each round.

@17
The carry is 0, so a alone is the sum: 5 plus 3 is 8, after four rounds. Because the carry climbs at least one column per round, the loop leaves a 32-bit word within 32 iterations. In JavaScript it works as written; in Python, with unbounded integers, you mask every iteration and reinterpret the result at the end.
