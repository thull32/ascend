@0
Repeated squaring halves the exponent on every iteration, and the tempting way to halve is a right shift. A right shift moves every bit one place toward the low end, and the lowest bit falls off the 8-bit word: that is floor division by 2.

@1
13 in 8-bit two's complement is 0 0 0 0 1 1 0 1.

@2
Shift right by one and it becomes 0 0 0 0 0 1 1 0, which is 6. The low bit, the one the loop has just consumed, falls off the end: floor division by 2, which is exactly what the exponent loop needs.

@3
Now minus 13, which is 1 1 1 1 0 0 1 1. In two's complement, the top bit set marks a negative number.

@4
Right shifts come in two kinds, and here they part ways. An arithmetic right shift copies the sign bit into the top, giving 1 1 1 1 1 0 0 1, which is minus 7. That is floor of minus 13 over 2, rounded down, not toward zero.

@5
A logical right shift fills the top with 0 instead, giving 0 1 1 1 1 0 0 1, which is 121: a large positive number from a negative input. Languages differ on which one the shift operator means for signed values.

@6
Shifts are constant time, and they are how multiplying and dividing by powers of two, bit masks and packed fields are built. The JavaScript template avoids the shift for a different reason. Every bitwise operator first converts its operand to a 32-bit signed integer, so 2 to the 31, shifted right by one, comes out negative and the loop stops at once. That is why it halves the exponent with a floor division instead.
