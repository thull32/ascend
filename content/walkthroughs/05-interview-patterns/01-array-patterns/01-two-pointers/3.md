@0
Here is a sorted array with duplicates: 1, 1, 2, 2, 2, 3, 4 and 4. The job is to compact it in place so each value is kept once, using two pointers that both walk to the right. Read visits every element. Write marks the next free slot in the kept prefix. The rule is one sentence: copy the value under read only when it differs from the last value you kept.

@1
Read and write both start at position 0. Nothing has been kept yet, so the 1 is new, and it is written at slot 0. Write moves on to slot 1.

@2
Read moves to position 1, another 1. It equals the last kept value, the 1 at slot 0, so it is skipped. Write stays where it is.

@3
Read reaches position 2, which holds a 2. That differs from the last kept 1, so it is copied into slot 1, and the prefix now reads 1, 2. Write moves to slot 2.

@4-5
The next two elements, at positions 3 and 4, are both 2. Each equals the last kept value, so both are skipped, and write waits at slot 2 while read pulls ahead.

@6
Read reaches the 3 at position 5. It is new, so it is written into slot 2, overwriting a 2 that read has already passed. The prefix is 1, 2, 3.

@7
The 4 at position 6 is new too. It goes into slot 3, and write moves to slot 4.

@8
The last element, another 4, equals the last kept value and is skipped.

@9
The first four slots hold the unique values, 1, 2, 3 and 4, and write is 4, which is both the count of kept elements and the index of the next free slot. That is why the function returns write, and why returning one more or one less is a bug you can rule out by that sentence alone. Notice the guarantee that makes the overwrites safe: write never overtakes read, so every write lands on a slot that has already been read. One pass, linear time, constant extra space. To keep at most k copies instead of one, compare against the value k slots behind write rather than the one just behind it.
