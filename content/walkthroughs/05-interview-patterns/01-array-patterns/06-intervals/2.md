@0
Four intervals, 1 to 4, 2 to 4, 3 to 6 and 4 to 4, and four queries, 2, 3, 4 and 5, each asking for the length of the shortest interval that contains it. The queries are answered in increasing order. Each one first pushes every interval that has started by then, and then pops, from the top, intervals that have already ended. The heap's root is then the answer. In the code each entry is a length paired with its end; here only the lengths are drawn.

@1-3
Query 2. Two intervals have started: 1 to 4, length 4, and 2 to 4, length 3. Push 4, then push 3, which is smaller and climbs to the root. Neither has ended, so the answer to query 2 is the root: 3.

@4-5
Query 3. The interval from 3 to 6 starts, length 4. Push it; it is not smaller than the root, so it stays at the bottom. Nothing has ended, and the root is still 3: the answer is 3 again.

@6-8
Query 4. The interval from 4 to 4 starts, length 1, the shortest yet. It climbs past a 4 and then past the 3 to reach the root. An interval that ends at 4 still contains the query 4, so nothing is popped, and the answer is 1.

@9-11
Query 5. No new intervals, but three have now ended before 5, and each one in turn reaches the root. Pop the 1, the interval from 4 to 4. The last leaf moves up and sinks below the 3.

@12-13
Pop the 3, the interval from 2 to 4. Two 4s are left, and in the code the tie is broken by the end time, so the one that ends first, 1 to 4, is on top and goes next.

@14-15
Pop it. One 4 remains, the interval from 3 to 6, which still contains 5. It stays at the root, and the answer to query 5 is 4.

@16
The answers are 3, 3, 1 and 4. The expiry is lazy: an interval that has ended is removed only when it reaches the root, which is safe because queries only increase, so an interval useless for one query is useless for every later one. Every interval is pushed once and popped at most once, so with the two sorts the cost is n plus q, times log of n plus q.
