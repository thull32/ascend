@0
On screen is the array 3, 1, 4, 1 and 2, and below it a count array with one slot for every value from 0 to 4, all zero. This is counting sort, and it rests on the idea that cyclic sort borrows: when the values are small and bounded, a value can name a position. No comparisons needed.

@1-5
The first pass reads each value and bumps the count in the slot that value names. The 3 goes to slot 3, the 1 to slot 1, the 4 to slot 4. The second 1 lands in slot 1 again, which now reads 2, and the final 2 goes to slot 2. The counts read 0, 2, 1, 1 and 1.

@6-10
The second pass walks the count array in order and writes values back. Slot 1 says two copies of 1, so the array gets 1 at index 0 and 1 at index 1. Then a 2 at index 2, a 3 at index 3 and a 4 at index 4.

@11
The array is sorted, 1, 1, 2, 3 and 4, in time proportional to n plus the five buckets, without a single comparison. Now the step that turns this into cyclic sort. Counting sort needs a separate array indexed by value. If every value lies in 1 to n, the input itself can play that role: value v belongs at index v minus 1, and you swap each value into its home slot instead of counting it. Afterwards, any index that does not hold its own value names the answer, a missing or a duplicated number. This animation shows only the mapping from value to slot, not those in-place swaps.
