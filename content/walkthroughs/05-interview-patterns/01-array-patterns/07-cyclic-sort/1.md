@0
On screen is the array 3, 1, 4, 1 and 2, and below it a count array with one slot for every value from 0 to 4, all zero. This is counting sort, and it rests on the idea that cyclic sort borrows: when the values are small and bounded, a value can name a position. No comparisons needed.

@1-5
The first pass reads each value and bumps the count in the slot that value names. The 3 goes to slot 3, the 1 to slot 1, the 4 to slot 4. The second 1 lands in slot 1 again, which now reads 2, and the final 2 goes to slot 2. The counts read 0, 2, 1, 1 and 1.

@6-10
The second pass turns each count into a starting position: the number of values smaller than that key. No 0s, so key 1 starts at position 0. Two 1s come before any 2, so key 2 starts at 2. Then key 3 starts at 3, and key 4 at 4. A value's slot is now computed from the values themselves.

@11-15
The third pass walks the input in order and drops each value into a separate output array at its starting position. The 3 goes to position 3. The first 1 goes to position 0, and the start for key 1 moves on, so the second 1 lands in position 1. The 4 goes to position 4, and the 2 to position 2.

@16
The output is sorted, 1, 1, 2, 3 and 4, in time proportional to n plus the five keys, without a single comparison. Now the step that turns this into cyclic sort. Counting sort needs a count array and an output array, both indexed by value. If every value lies in 1 to n, the input itself can play that role: value v belongs at index v minus 1, and you swap each value into its home slot instead of counting it. Afterwards, any index that does not hold its own value names the answer, a missing or a duplicated number. This animation shows only the mapping from value to slot, not those in-place swaps.
