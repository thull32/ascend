@0
Find the Duplicate Number on 1, 3, 4, 2 and 2, without modifying the array. Read the array as a function from an index to the value stored there, and follow it from index 0. That walk visits indices 0, 1, 3, 2 and 4, which are the nodes on screen, and from 4 it jumps back to index 2. A plain traversal would loop forever. The key fact: the node where the loop begins has two arrows coming into it, which means two indices hold the same value, and that value is the duplicate.

@1-3
Floyd's tortoise and hare uses two speeds instead of a visited set. Slow moves one node per step, fast moves two. After step 1, slow is on 1 and fast on 3. After step 2, slow is on 3 and fast on 4. After step 3, slow is on 2, and fast has gone round the small loop and is back on 4. Once both are inside the loop, the gap between them shrinks by one each step, so they must meet.

@4
Step 4: both land on 4. They can only meet if fast has lapped slow inside a loop, so a cycle exists. But 4 is just where they happened to meet, not where the loop begins.

@5
Phase two. Slow goes back to the start, index 0, and now both move one node per step. The distance from the start to the loop's entry equals the distance from the meeting point to the entry, measured around the loop, so they must arrive there together.

@6-7
Slow moves to 1 while fast moves to 2. Then slow moves to 3 while fast moves round to 4. Still apart.

@8
On the next step both reach 2: the entry of the loop, and the duplicated value. Linear time, constant space, and the array is never touched. If mutation were allowed, cyclic sort would answer this too, but the problem forbids it, which is why this view exists.
