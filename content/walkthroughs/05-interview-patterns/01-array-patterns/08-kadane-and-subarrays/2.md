@0
The same algorithm, now as a table. The values are 5, minus 3, 5, minus 7, 4 and 2. Below them, each cell of the second row will hold the best sum of a subarray ending exactly at that position. The recurrence is one sentence: a subarray ending here either is just this value, or extends the best one ending at the previous position, so the cell is this value plus the previous cell, if the previous cell is positive.

@1
The base case is the first cell. The only subarray ending at position 0 is the 5 itself, so the cell is 5.

@2
Position 1 holds minus 3. The previous cell, 5, is positive, so it helps: minus 3 plus 5 is 2.

@3
Position 2 holds 5, and the previous cell, 2, still helps: the cell is 7, the best so far.

@4
Position 3 holds minus 7. Seven plus minus 7 is 0, while minus 7 on its own is worse, so the cell is 0. The prefix is kept even though it has been dragged all the way to zero.

@5
Position 4 holds 4. The previous cell is 0, which adds nothing either way: extending gives 4, and starting fresh also gives 4. The cell is 4.

@6
Position 5 holds 2, and the previous 4 helps, so the last cell is 6.

@7
The row reads 5, 2, 7, 0, 4 and 6. The answer is the largest cell, 7, at position 2, from the subarray 5, minus 3 and 5. Not the last cell, which is 6: that is the trap in this view. And since each cell needs only the one before it, the whole table compresses into the single running variable of Kadane's loop. Linear time, constant space. The table view matters because it extends: products and deletions each add a state to the same recurrence.
