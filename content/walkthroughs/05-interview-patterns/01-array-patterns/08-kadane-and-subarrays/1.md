@0
This is the classic Maximum Subarray input: minus 2, 1, minus 3, 4, minus 1, 2, 1, minus 5 and 4. Kadane keeps two numbers. Cur is the best sum of a subarray ending right here, and best is the best seen anywhere so far. At every index there is one decision: extend the running subarray, or start fresh here. The rule is short. If the running sum is negative, it can only hurt, so drop it.

@1
At index 0 there is nothing to decide. Cur and best both start at minus 2.

@2
At index 1 the value is 1. The running sum is negative, minus 2, and carrying it would turn the 1 into minus 1. So cur restarts at 1, and best becomes 1.

@3
At index 2 comes minus 3. The running sum, 1, is not negative, so we extend, and cur drops to minus 2. Best stays 1.

@4
At index 3 the value is 4, and the running sum has gone negative again. Restart: cur is 4, starting at index 3, and best becomes 4.

@5
Here is the step to watch. Index 4 holds minus 1. A window rule would want to throw it out, but the run before it, 4, is still positive and worth keeping. So we extend, and cur is 3. Best stays 4.

@6-7
That patience pays. Adding 2 makes cur 5, a new best, and adding 1 makes it 6, a new best again.

@8-9
Minus 5 drags cur down to 1, but 1 is still not negative, so the run survives, and the final 4 lifts cur to 5. Neither beats 6.

@10
The answer is 6, from indices 3 to 6: 4, minus 1, 2 and 1. One pass, linear time, constant space. The rule is safe because no best subarray ever starts with a prefix whose sum is negative: dropping that prefix would leave a larger sum. And notice that best was seeded with the first element, not with 0. On an input that is all negative, a seed of 0 would wrongly return the empty subarray.
