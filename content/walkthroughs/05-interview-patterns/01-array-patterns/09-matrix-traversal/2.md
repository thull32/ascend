@0
A four by four maze, where 1 is a wall. The rows read 0, 0, 0, 1; then 1, 1, 0, 1; then 0, 0, 0, 0; then 0, 1, 1, 0. We want the shortest path from the top-left corner to the bottom-right. Every move costs the same, one step, so breadth-first search is the right tool: it reaches cells in order of distance, and the first time it reaches the goal is the shortest way there. Each cell's neighbours are the four in-bounds cells reached by the direction vectors, and walls are skipped.

@1-4
Expand the start, row 0 column 0, at distance 0. The cell below it is a wall, so the only open neighbour is to the right. The search is forced along a corridor: row 0 column 1 at distance 1, row 0 column 2 at distance 2, then down through the gap to row 1 column 2 at distance 3. Each expansion adds exactly one cell to the queue.

@5
At row 2, column 2, distance 4, the maze opens up. Below is a wall, but left and right are both open, so two cells join the queue: row 2 column 3, and row 2 column 1.

@6
Expanding row 2 column 3 at distance 5 adds the cell below it, row 3 column 3, which is the goal, at distance 6.

@7
The other cell at distance 5, row 2 column 1, is expanded too, and adds row 2 column 0. The queue now holds two cells, both at distance 6, and one of them is the goal.

@8
The goal is reached at distance 6, and the path lights up: right, right, down, down, right, down. The total work is bounded by the number of cells, because each one is enqueued at most once. Flood fill, rotting oranges and maze shortest paths are all this same search with a different start set.
