@0
The matrix has three rows of four: 1, 3, 5, 7; then 10, 11, 16, 20; then 23, 30, 34, 60. Every row is sorted, and each row starts after the previous one ends, so reading it row by row gives one sorted array of 12 values, which is what is on screen. We are looking for 16. Flat position k maps back to row k divided by 4, rounded down, and column k modulo 4. The usual invariant applies: if 16 is here, it lies between low, position 0, and high, position 11.

@1
The middle is position 5, which is row 1, column 1, and holds 11. Eleven is less than 16, so the target can only be to the right, and low moves to position 6.

@2
Now the middle is position 8, row 2, column 0, holding 23. Twenty-three is more than 16, so high moves to position 7.

@3
The middle of 6 and 7 is position 6: row 6 divided by 4, which is 1, and column 6 modulo 4, which is 2. It holds 16. Found after 3 comparisons; for 12 elements the worst case is 4. The whole search costs the logarithm of rows times columns. The trap is the other kind of sorted matrix, where rows and columns are sorted but rows do not chain. There the flat sequence is not sorted and this search is wrong; start at the top-right corner and walk a staircase instead.
