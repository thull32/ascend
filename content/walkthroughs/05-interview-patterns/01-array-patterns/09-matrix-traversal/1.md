@0
Here is a grid of three rows and four columns, where 1 is land and 0 is water. The top row reads 1, 1, 0, 0; the middle row 1, 0, 0, 1; the bottom row 0, 0, 1, 1. Counting islands means counting connected groups of land. The idea that makes it easy: the grid is already a graph. Each cell is a node, and its edges are the land cells you reach with the four direction vectors, up, down, left and right, that pass the bounds check. No adjacency list is ever built.

@1
Scan the cells in order. The first one, row 0, column 0, is land that nobody has visited yet, so it starts island 1.

@2-4
A flood fill now marks everything connected to it. It covers row 0 column 0, then its neighbour to the right, row 0 column 1, then the one below the start, row 1 column 0. No other land touches these three, so the fill stops. All three are marked, and the scan will never count them again.

@5
The scan moves on past water and marked cells until it reaches row 1, column 3: land, not yet visited. That is island 2.

@6-8
The fill spreads from there down to row 2, column 3, and then left to row 2, column 2. Those three cells form the second island.

@9
Two islands. Every cell is scanned once and filled at most once, so the cost is rows times columns. Counting islands is just counting the connected components of this implicit graph: each unvisited land cell the scan finds starts one more. One detail the lesson stresses: mark a cell as seen when you push it, not when you pop it, so no cell is ever queued twice.
