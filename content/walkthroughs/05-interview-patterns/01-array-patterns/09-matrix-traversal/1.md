@0
Here is a grid of three rows and four columns, where 1 is land and 0 is water. The top row reads 1, 1, 0, 0; the middle row 1, 0, 0, 1; the bottom row 0, 0, 1, 1. Counting islands means counting connected groups of land. The idea that makes it easy: the grid is already a graph. Each cell is a node, and its edges are the land cells you reach with the four direction vectors, right, down, left and up, that pass the bounds check. No adjacency list is ever built. Each island is filled with a breadth-first search, and a cell is marked as seen the moment it is pushed.

@1
Scan the cells in order. The first one, row 0, column 0, is land that nobody has seen yet, so it starts island 1. Mark it and push it onto the queue.

@2
Pop row 0, column 0. Its right neighbour, row 0 column 1, and the cell below it, row 1 column 0, are both unseen land, so both are marked and pushed.

@3-4
Pop row 0, column 1: its only land neighbour is the start, already seen, so nothing is pushed. Pop row 1, column 0: nothing new either. The queue is empty, and the first island is three cells.

@5
The scan moves on past water and marked cells until it reaches row 1, column 3: land, not yet seen. That is island 2, and it is pushed.

@6-8
Pop it, and push the cell below, row 2 column 3. Pop that, and push its left neighbour, row 2 column 2. Pop that one, and nothing new is left. Those three cells form the second island.

@9
Two islands. Every cell is scanned once and enqueued at most once, so the cost is rows times columns. Counting islands is just counting the connected components of this implicit graph: each unseen land cell the scan finds starts one more. Marking on push is what guarantees that "at most once": mark a cell only when you pop it, and it can sit in the queue once for every neighbour that saw it first.
