@0
Five nodes, A to E, and six weighted edges. A minimum spanning tree connects every node with the smallest total weight. Kruskal's rule is greedy: take edges cheapest first, and keep an edge only if it joins two different components. Union-find answers that question in near-constant time.

@1-2
The cheapest edge is A to C, weight 1. A and C are in different sets, so union them and keep the edge. The tree weighs 1.

@3-4
Next is B to C, weight 2. B is alone, and C is in A's set, so again two different roots. Keep it. The tree weighs 3.

@5-6
D to E, weight 3, joins two more singletons into a second group. The tree weighs 6, spread across two components: A, B and C on one side, D and E on the other.

@7-8
A to B, weight 4. Find gives A for both ends: they are already connected, through C. Adding this edge would close a cycle, so it is skipped. That failed union is the same event Redundant Connection returns.

@9-10
B to D, weight 5. Their roots differ, so this edge bridges the two groups. Keep it, and the tree weighs 11.

@11
Four edges are kept for five nodes, which is all a spanning tree can hold, so the loop stops before the edge from C to D, weight 8, is even looked at. The minimum spanning tree weighs 11. Each edge costs two finds, so sorting dominates, and the total is E log E.
