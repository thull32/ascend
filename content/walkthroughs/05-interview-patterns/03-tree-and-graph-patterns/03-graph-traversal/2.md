@0
This is a five by five maze, where 1 is a wall, and we want the shortest path from the top-left corner to the bottom-right. Every move costs 1, and that is exactly when breadth-first search gives shortest paths. Hold onto one sentence: every cell at distance d is dequeued before any cell at distance d plus 1.

@1-3
The start, row 0, column 0, is expanded at distance 0. The cell below it is a wall, so the only way is right: row 0, column 1 at distance 1, then row 0, column 2 at distance 2. Each cell is marked the moment it is enqueued, so no cell ever enters the queue twice.

@4-5
A wall blocks column 3 of the top row, so the path turns down: row 1, column 2 at distance 3, then row 2, column 2 at distance 4. Row 2 is fully open, and the frontier is about to split both ways.

@6-7
Two cells sit at distance 5, one on each side: row 2, column 3 to the right and row 2, column 1 to the left. Both are dequeued before anything at distance 6.

@8-9
Distance 6: row 2, column 4 on the right, and row 2, column 0 on the left.

@10-12
Distance 7: on the right the frontier goes both down and up column 4, to row 3 and row 1; on the left it goes down into row 3, column 0. The left side is a dead end for reaching the goal, but breadth-first search cannot know that, so it explores it at the same pace.

@13
The goal is reached at distance 8, and the path is recovered from parent pointers: right twice, down twice, right twice, down twice. Because distances only grow as the queue drains, the first time the goal comes out of the queue its distance is final. The cost is rows times columns. If moves had different costs, plain breadth-first search would be wrong, and you would need Dijkstra, or a double-ended queue when the costs are only 0 and 1.
