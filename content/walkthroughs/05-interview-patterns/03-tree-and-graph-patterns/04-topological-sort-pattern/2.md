@0
The same idea, by depth-first search, on a diamond: 0 points to 1 and 2, and both of those point to 3. Every node is white, unvisited; grey, entered but not finished; or black, finished. A node is appended to a list when it finishes, after everything it points to has finished, and the reversed list is the order.

@1-3
Enter 0, then follow its first edge into 1, then 1's edge into 3. All three are grey, on the current path.

@4
3 points nowhere, so it finishes first and turns black. It will go last in the final order, after everything already placed before it.

@5
1 has no other edges, so it finishes too. The finish list reads 3, then 1.

@6
Back at 0, its second edge leads to 2, which is entered and turns grey. 2 has an edge to 3, but 3 is black, already finished. That is not a cycle: it is just a second route into a finished node, so the search skips it. Only an edge to a grey node, one still on the current path, means a cycle.

@7-8
2 finishes, and then 0 finishes. The finish list is 3, 1, 2, 0.

@9
Reverse it: 0, 2, 1, 3. Every edge points forward, and the cost is vertices plus edges. The trap is using two colours instead of three. With only a visited flag, the edge from 2 to the finished 3 looks exactly like a cycle, and the diamond, which is perfectly valid, gets rejected.
