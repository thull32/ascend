@0
Six tasks, A to F, with arrows meaning must come before. A comes before B and C. B and C both come before D. C also comes before F, and both D and F come before E. Each node is labelled with its in-degree, the number of prerequisites it is still waiting for. Kahn's algorithm has one rule: a node may be emitted once its in-degree is zero. Only A starts at zero, so the queue holds just A.

@1
Take A as position 1. Removing it deletes its outgoing arrows.

@2-3
That drops B from 1 to 0, so B is enqueued. Then C drops from 1 to 0, and it joins too. The queue holds B and C, and this is exactly the moment the order stops being unique: either could go next.

@4
Take B as position 2. Its arrow to D is removed, but D was waiting on two prerequisites, so it only drops to 1. Nothing new enters the queue.

@5-7
Take C as position 3. D drops to 0 and is enqueued, and F drops to 0 and is enqueued behind it.

@8
Take D as position 4. E was waiting on D and F, so it drops to 1 and still has to wait.

@9-10
Take F as position 5. E finally reaches 0 and is enqueued.

@11
Take E as position 6, and the queue is empty.

@12
The order is A, B, C, D, F, E, and every arrow points forward in it. Each node enters the queue once and each edge is decremented once, so the cost is vertices plus edges. The cycle check comes free: if fewer nodes are emitted than exist, the rest are on a cycle or downstream of one, and no valid order exists.
