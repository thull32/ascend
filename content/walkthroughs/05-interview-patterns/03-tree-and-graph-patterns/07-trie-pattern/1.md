@0
A trie stores strings one character per edge, along paths from the root, so keys that share a prefix share the nodes of that prefix. A node with a double ring is terminal: a key ends there. We will insert car, card, care and cat, then run four queries.

@1-3
The trie is empty, so inserting car creates three new nodes, one each for c, a and r.

@4
At the end of car, the node is marked terminal. Without that marker, car would only be a prefix of longer keys, never a key in its own right.

@5-9
Now card. The edges for c, a and r already exist, so the walk follows them without creating anything. Only the d is new, and its node is marked terminal.

@10-14
Care is the same story: follow c, a and r, then create one node for e and mark it terminal. Car, card and care now share three nodes.

@15-18
Cat shares only c and a. Under ca there is no edge for t, so one new node is created and marked terminal.

@19-22
First query: search for car. Follow c, a and r. Every character matched and the node is terminal, so the answer is true.

@23-25
Search for ca. Both characters match, but the node for ca is not terminal. Ca is only a prefix of stored keys, so search returns false. Forget the terminal check, and every prefix counts as a word.

@26-28
Now starts with ca, the prefix query. The same walk reaches the same node, and this time that is enough: a prefix check needs only the path to exist, not the terminal flag. True.

@29-33
Last, search for cart. Follow c, a and r, then look for a t under car. There is none, so the walk falls off the trie after 4 steps, and no stored key starts with cart. False.

@34
Four keys in 7 nodes, counting the root. Insert, search and prefix each cost the length of the key, no matter how many keys are stored. Say that independence out loud: it is the property a hash set cannot give prefixes.
