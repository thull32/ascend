@0
Five nodes, 1 through 5, to be reversed in place with three pointers. Prev heads the part that is already reversed, empty so far. Curr is the node being flipped. And next will save the rest of the list before its link is cut. The invariant to say aloud: at the top of each iteration, prev heads a fully reversed list of the nodes already visited, curr heads the untouched remainder, and no node is reachable from both.

@1
First, save next: curr is 1, so next is 2. Without this, flipping 1's link would leave 2 to 5 unreachable.

@2
Flip: 1's next becomes prev, which is null. Node 1 is now the tail of the reversed part.

@3
Advance: prev moves to 1, curr to 2. One node has crossed from the remainder to the reversed side, and the invariant holds again.

@4-6
The same three moves for node 2. Save next, which is 3. Flip 2's link back to 1. Advance: prev is 2, curr is 3. The reversed part reads 2 then 1.

@7-12
Node 3, then node 4, exactly the same: save, flip, advance. Each iteration rewrites one link and moves one node across. After them, prev is on 4, the reversed part reads 4, 3, 2, 1, and curr is on 5.

@13-15
The last node. Saving next gives null: 5 is the end of the list. Flip 5's link back to 4, and advance: prev is 5, and curr is null, so nothing is left to flip.

@16
Curr is null, so the loop ends and the new head is prev, 5. The list now reads 5, 4, 3, 2, 1. One pass, linear time, constant extra space, and every next pointer rewritten exactly once. The order of the three moves is the whole trick: save before you flip, or the rest of the list is lost. Return prev, not curr, which is null by the time the loop ends.
