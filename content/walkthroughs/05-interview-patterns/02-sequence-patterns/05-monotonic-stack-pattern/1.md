@0
Seven values: 2, 1, 2, 4, 3, 1 and 5. For each one we want the nearest greater value to its right. Below the array sits a stack of indices, and the invariant is the whole algorithm: the values at the stacked indices never increase from bottom to top, and every index on the stack is still waiting for its answer.

@1-2
Index 0, value 2, is pushed. Index 1, value 1, is smaller, so nothing is resolved and it is pushed too. The stack holds 2 and 1.

@3
Index 2 holds 2, which is greater than the 1 on top. So the 1 has found its answer: pop index 1, and its next greater is 2.

@4
Now the top is the first 2, which is equal, not smaller. An equal value does not pop, because it is not greater. Push index 2: the stack holds 2 and 2, which still never increases upwards.

@5-6
Index 3 holds 4. It is greater than the 2 on top, so pop index 2: its answer is 4. It is also greater than the 2 below, so pop index 0: its answer is 4 too. One arrival resolved two waiting indices.

@7-9
Push index 3, value 4. Then 3 and 1 arrive, each smaller than the top, so they are pushed. The stack holds 4, 3, 1: three indices waiting.

@10-12
The 5 arrives, and it is greater than everything on the stack. Pop the 1, the 3 and the 4, one after another, and each gets 5 as its answer.

@13
Push index 6. The stack holds just 5.

@14
The scan is over. Index 6 is still on the stack, so nothing to its right is greater: its answer is minus 1. The answers read 4, 2, 4, 5, 5, 5 and minus 1. Each index was pushed once and popped at most once, so the nested loop does at most about 2n comparisons in total: linear, with a constant you can state.
