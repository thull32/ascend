@0
Three sorted lists: A is 2, 7, 9. B is 1, 5. C is 3, 4, 8. The heap holds exactly one entry per list that still has elements: that list's smallest unmerged value. Hold onto that sentence. Because each list is sorted and the root is the heap's minimum, the root is always the smallest unmerged value overall, so emitting it keeps the output sorted.

@1-5
Seeding: the head of each list goes in. A's 2 becomes the root, B's 1 is smaller and sifts up past it, and C's 3 settles below. The root is 1.

@6-8
Pop the root: 1 from B is emitted. The last leaf, 3, moves to the root and sinks below 2.

@9-10
1 came from B, so B's next element, 5, is pushed. There are three entries again, one per list.

@11-13
Pop: 2 from A is emitted. 5 moves to the root and sinks below 3.

@14-15
A's next element, 7, is pushed.

@16-18
Pop: 3 from C. 7 moves up and sinks below 5.

@19-20
C's next element is 4. It lands below 5, is smaller, and sifts up to the root. So C supplies the minimum twice in a row, and the heap does not care which input the minimum comes from.

@21-22
Pop: 4 from C. 5 moves to the root and is already no larger than 7.

@23-24
C's next element, 8, is pushed below 5.

@25-27
Pop: 5 from B. That was B's last element, so nothing is pushed for B. The list is exhausted, and the heap shrinks to two entries.

@28-29
Pop: 7 from A. Only 8 is left in the heap for a moment.

@30-31
A's next element, 9, is pushed below 8.

@32-33
Pop: 8 from C, C's last element. Nothing is pushed.

@34
Pop: 9 from A, the last element of all. The heap is empty, and the merge is done.

@35
The output is 1, 2, 3, 4, 5, 7, 8 and 9. The heap never held more than 3 entries, one per list, so every operation is log k, not log n. Each of the N elements is pushed and popped once, so the whole merge is N log k time with only k entries of extra space. And the proof leans on one fact, that each input is sorted. Feed it an unsorted list and the output is silently wrong, because nothing checks.
