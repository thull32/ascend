@0
A router and three shards. This picture shows the plain way to hash-partition: hash the key and take it modulo the shard count, 3. Watch closely what happens when the count changes, because that is the problem fixed partitions solve.

@1
Alice hashes to a large number, and that number mod 3 is 2, so alice goes to shard 3. Any router computes the same answer, with no shared table.

@2-3
Bob and hank also come out at 2 mod 3, so they land on shard 3 too.

@4
Judy comes out at 0, so she goes to shard 1.

@5
After four keys the shards hold 1, none, and 3. Four keys is far too few to look even. The point here is a different one: sequential keys, like order 3001 then 3002, would scatter exactly the same way, because nearby keys hash to unrelated shards. There is no hot tail.

@6
The first failure mode. A range query cannot be routed. The router has to scatter it to every shard and merge the results, so the cost grows with the number of shards, and the latency is the slowest shard's.

@7
The second, and the one that matters most here. Add a fourth shard and the modulus changes from 3 to 4, so all four keys now hash to a different shard, and must be migrated while serving traffic. The fix the lesson describes is to hash to a fixed number of partitions, far more than you have nodes, and keep a table from partitions to nodes. Growing the cluster then moves whole partitions and rewrites table entries. No key ever changes partition. Kafka, Elasticsearch and Redis Cluster, with its 16,384 hash slots, work that way.

@8
The third failure mode: hashing spreads keys, not load. One celebrity key still lands on one shard. Handle it by splitting the hot key with a suffix and reading from all its copies.

@9
The trade-off. Hash partitioning gives uniform load and simple routing, at the price of scatter-gather range queries, and of painful resharding unless the partition count is fixed up front. Range partitioning is the mirror image, and many systems, Cassandra and DynamoDB among them, hash the partition key and keep rows sorted within each partition.
