@0
Three proposers, P, Q and a third, R, waiting in reserve, and three acceptors, A1, A2 and A3. The table shows each acceptor's state as two things: the highest proposal number it has promised, and the proposal it has accepted, if any. P wants the value X, Q wants Y. Hold onto one sentence: any two majorities of three share at least one acceptor, and that shared acceptor is the memory that carries a decision from one proposer to the next.

@1
P sends prepare 1. It reaches A1 and A2; the copy to A3 is delayed. Both promise to ignore any proposal numbered below 1, and neither has accepted anything yet.

@2
P now holds promises from a majority, two of three, and none of them reports a value. So P is free to propose its own: X.

@3
P's accept, proposal 1 with value X, reaches A1 only. One acceptor of three has accepted X. That is not a majority, so X is not chosen.

@4
Now Q sends prepare 2 to all three acceptors, and all three promise 2. Look at the overlap: Q's majority and P's majority both contain A1.

@5
A1's promise does not come back empty. It reports what A1 already accepted: proposal 1, value X.

@6
Meanwhile P's delayed accept for proposal 1 finally reaches A2. But A2 has promised 2, and a promise is a commitment to reject anything older, so A2 rejects it.

@7
Q picks its value, and here is the rule that makes Paxos safe: if any promise reported an accepted proposal, use the value of the highest numbered one. That is proposal 1, value X, so Q must propose X, not its own Y. Q cannot know whether some majority it did not hear from already accepted X, so it assumes one might have.

@8
Q sends accept, proposal 2 with value X, and all three acceptors accept it. A majority has accepted the same proposal, so X is chosen.

@9
Suppose Q crashes before telling anyone. The third proposer, R, starts a new round, prepare 3, which only needs to reach any majority, in this case A2 and A3. They promise 3, and both report that they accepted proposal 2 with value X, because any majority overlaps the one that chose X. So R must propose X again. The decision survives the crash.

@10
That is why acceptors write their promise and their accepted proposal to disk before replying: the overlap only works if the shared acceptor remembers. Majorities overlap, the overlap remembers, and only one value is ever chosen. Raft's elections and commits rest on exactly the same arithmetic.
