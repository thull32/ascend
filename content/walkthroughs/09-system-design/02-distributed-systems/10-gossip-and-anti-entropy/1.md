@0
Eight nodes, N1 to N8, all holding version 1, and no coordinator. This run uses the simplest form of gossip: push, with a fanout of one. Every round, each node that knows the news sends it to one peer chosen at random. Watch two things: how fast the informed count grows at the start, and how slowly the last nodes are reached.

@1
N1 learns something new, version 2. It might be a configuration change, a membership update, or a peer's heartbeat counter. It has no list of who needs it.

@2-3
Round 1: N1 tells one peer, so 2 of 8 know. Round 2: two nodes push, but one push lands on a node that already knew, drawn dashed and wasted, so only 3 know.

@4
Round 3: three nodes push, and two new nodes learn. Now 5 of 8 know. This is the early phase, where the count roughly doubles each round.

@5
Round 4: five nodes push, two new nodes learn, and two pushes are wasted. Now 7 of 8.

@6
Round 5: seven nodes push, just one new node learns, and five pushes are wasted. Everyone knows at last. This is push's weakness: near the end, almost every push lands on a node that already knows, and the stragglers wait on luck. Pull fixes the finish, because an uninformed node stays uninformed only if the peer it asks is also uninformed. That is why push-pull, both halves in one exchange, is the standard choice, usually with a fanout of a few peers.

@7
Everyone has version 2 after 5 rounds and 18 messages, and no node sent more than one message per round. Spread time grows with the logarithm of the cluster size, so doubling the cluster adds about one round.

@8
Two flavours. Rumour mongering pushes a specific new update and retires it after a few rounds: cheap, but a rare node can miss it. Anti-entropy periodically compares full state, or a digest of it, with a peer, for example using Merkle trees: heavier, but it never stops, and it repairs any difference however old. It is the safety net under rumour mongering, and Cassandra and Riak run both.

@9
The failure modes. During a partition, each side converges to its own view. A node with a slow or broken link can be declared dead by everyone. And stale news lingers: a removed node can be re-added by a peer that never heard it left, unless you gossip tombstones.

@10
The trade-off. No coordinator, no single point of failure, and load spread evenly. In exchange, delivery is only eventual, messages are redundant, like the wasted ones you saw, and each node keeps membership state that grows with the cluster. Cassandra, Consul and Redis Cluster all gossip for membership and failure detection.
