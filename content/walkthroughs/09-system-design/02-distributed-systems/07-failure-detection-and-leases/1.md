@0
Six nodes, N1 to N6, all holding version 1 of some piece of cluster state. There is no coordinator. The rule is a rumour's rule: every round, each node that knows the news tells one peer chosen at random. Nobody keeps a list of who still needs to hear it.

@1
N1 learns something new, version 2. It might be a configuration change, a membership update, or a peer's heartbeat counter, which is how gossip-based failure detectors learn who is still alive.

@2-3
Round 1: N1 picks one random peer, and now 2 of the 6 know. Round 2: both informed nodes pick a peer, but only one new node learns, so 3 of 6 know.

@4-6
Round 3: three nodes send, one new node learns, and two messages land on nodes that already knew. Those dashed arrows are wasted. Round 4: four messages, one new node, three wasted. Round 5: five messages, and the last node finally hears. As more nodes know, more of the random picks hit nodes that already knew.

@7
Everyone has version 2 after 5 rounds and 15 messages, and no node ever sent more than one message per round. This run was slow, one new node per round. In expectation the informed group grows much faster early on, which is why spread time grows with the logarithm of the cluster size: doubling the cluster adds about one round.

@8
Two flavours. Rumour mongering pushes new updates and stops after a few rounds: cheap, but it can miss nodes. Anti-entropy periodically compares full state with a peer, for example with Merkle trees: heavier, but it guarantees convergence. Cassandra and Riak run both.

@9
The failure modes. During a partition, each side converges to its own view. A node with a slow or broken link can be declared dead by everyone. And gossip carries stale news for a while: a removed node can be re-added by a peer that never heard it left, unless you gossip tombstones. This is why a detector should only suspect. Conviction is slower and separate: SWIM has other members probe before suspecting, and lets the suspect refute it, so one bad link does not eject a healthy node.

@10
The trade-off. No coordinator, no single point of failure, and load spread evenly. In exchange, delivery is only eventual, messages are redundant, like the wasted ones you saw, and each node keeps membership state that grows with the cluster. Cassandra, Consul and Redis Cluster all use gossip for membership and failure detection.
