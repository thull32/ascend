@0
Three processes, P1, P2 and P3, each with a counter at 0. No physical clock is involved anywhere. A Lamport clock makes one promise: if event a could have caused event b, either earlier in the same process or through a message, then a gets a smaller number than b. The rules fit in a sentence. Every event adds one. A send attaches the counter to the message. A receive takes the larger of its own counter and the message's, then adds one.

@1
A local event on P1. Its counter goes to 1, and nothing else changes.

@2
P1 sends a message to P2. Sending is an event too, so P1 ticks to 2 and stamps the message with 2.

@3
P2 receives it. Its own counter is 0, the message says 2, the larger is 2, plus one makes 3. That max is the whole trick: whatever P2's counter was, the receive is now numbered after the send.

@4
Meanwhile P3 has a local event and ticks to 1. P3 has heard from nobody.

@5
P2 sends a message back to P1, ticking to 4 and stamping it 4.

@6
P1 receives it. Its own counter is 2, the message says 4, so P1 jumps to 5. The clock moved forward by three in one step, because P1 just learned that the world had moved on.

@7
P3 has another local event and ticks to 2.

@8
P3 sends a message to P1, ticking to 3 and stamping it 3.

@9
P1 receives it. This time P1's own counter, 5, is already larger than the message's 3, so it keeps 5 and adds one, landing on 6. Follow any causal chain on this screen and the numbers rise strictly, exactly as promised.

@10
Now the limit. P3's first local event is stamped 1. P2's receive of the first message is stamped 3. One is smaller than three, yet neither event could have influenced the other: no message connects them. They are concurrent. A Lamport clock cannot tell happened before from happened to be numbered lower. A smaller number rules out the reverse order, and says nothing else.

@11
So here is the trade. One integer per message buys a total order, ties broken by process id, that every node computes identically and that never puts an effect before its cause. That is enough for a replicated state machine, and it is the idea behind Raft's term and index. What it cannot do is detect that two writes conflicted. For that you need vector clocks.
