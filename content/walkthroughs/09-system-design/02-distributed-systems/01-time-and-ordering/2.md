@0
The same three processes, but now each keeps a vector: one counter per process, all starting at 0, 0, 0. The rule: on every event, add one to your own slot. A message carries the sender's whole vector, and on receipt you take the larger value slot by slot, then add one to your own slot. The other slots record what you have heard about everyone else.

@1
A local event on P1. It bumps its own slot, the first, and reads 1, 0, 0.

@2
P1 sends a message to P2. It ticks to 2, 0, 0 and sends that whole vector along.

@3
P2 merges. Its own vector is all zeros, the message carries 2, 0, 0; the slot by slot maximum is 2, 0, 0, then P2 bumps its own slot to get 2, 1, 0. P2 now knows everything P1 knew when it sent.

@4
P3 has a local event and reads 0, 0, 1. It has heard from nobody.

@5
P2 sends a message to P1, ticking its own slot to 2, 2, 0.

@6
P1 merges its 2, 0, 0 with the incoming 2, 2, 0, and bumps its own slot: 3, 2, 0.

@7
P3 has another local event: 0, 0, 2.

@8
P3 sends a message to P1, carrying 0, 0, 3.

@9
P1 merges 3, 2, 0 with 0, 0, 3, takes the maximum of each slot, and bumps its own: 4, 2, 3. Every slot of P1's vector now reflects something it actually heard.

@10
Now compare. Event a happened before event b exactly when every slot of a is less than or equal to the matching slot of b, and they differ. P1's first local event, 1, 0, 0, against its send, 2, 0, 0: every slot is smaller or equal, so the first causally precedes the second.

@11
And here is what a Lamport clock could not do. P1's first event is 1, 0, 0. P3's first event is 0, 0, 1. Each is bigger in some slot, so neither happened before the other: they are concurrent, and the vectors prove it. A store like Dynamo keeps both versions as siblings and hands them to the application to merge, instead of silently picking one.

@12
The trade-off. You get exact causality and conflict detection, but the vector grows with the number of writers. Key it by client and it explodes, which is why Riak moved to dotted version vectors and why production stores key entries by replica. And detecting a conflict is only half the job: you still need a merge rule once you find one.
