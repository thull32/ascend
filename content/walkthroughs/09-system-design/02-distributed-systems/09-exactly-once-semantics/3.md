@0
A client, a payments API, an idempotency store whose entries live 24 hours, and a ledger. The rule: the caller attaches a unique key to each intent, and the server guarantees that one key produces one effect, however many times it arrives. At-least-once delivery plus an idempotent receiver equals an exactly-once effect.

@1
The client generates key k1 for this charge and sends it with the request.

@2
The API checks the store, finds nothing, and claims k1 atomically, with a set-if-not-exists, so a concurrent duplicate cannot also start processing.

@3
The real work happens once: the ledger records a 20 dollar charge.

@4
The response is saved under k1 before it is returned, so a retry can be answered without redoing the work.

@5
The reply is sent, and lost: a timeout, a dropped connection, a crashed pod. The client cannot tell whether the charge happened.

@6
So it retries, with the same key. Without the key, this would be a second 20 dollar charge.

@7-8
The store has k1, with its saved response, and the API replays that response without touching the ledger. Charges: still one.

@9
Now a concurrent duplicate, arriving while the first copy is still in progress. Its set-if-not-exists fails, so the API answers 409 Conflict, or waits for the first to finish, instead of charging twice.

@10
Different keys are different intents. Keys k2 and k3 each charge once, and the ledger shows three charges in total. The key identifies the attempt, not the endpoint.

@11
The details that bite. Scope keys per account so clients cannot collide. Store a hash of the request body, and reject a reused key with a different payload. Expire keys, but not before the client's retry window ends.

@12
The trade-off is one extra store round trip per request, and a keyspace to expire, in exchange for safe retries. Notice, though, that the claim and the effect here are separate steps. When you own the sink, the lesson's preferred version needs no store at all: make the event id a unique key in the ledger itself, so a replay's insert hits the constraint and does nothing, atomically with the effect, with no window and no clock.
