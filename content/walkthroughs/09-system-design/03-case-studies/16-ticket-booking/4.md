@0
An app, a Postgres database, a change data capture connector, and a downstream index. Instead of the app writing to the database and then to the index, a dual write, the connector tails the database's write-ahead log and turns every committed change into an event. The database's own commit order becomes the event stream.

@1
Setup: the connector creates a replication slot, so Postgres keeps the log from that point, and takes a consistent snapshot of the existing rows. From then on it needs only the log.

@2-3
The app inserts a user, Ada, and commits. Postgres writes it to the log at position 1 before acknowledging; the app knows nothing about the index. The connector decodes position 1 into an event with the row before and after, and the index applies it. The gap between commit and apply is the staleness a reader can see.

@4-7
An update renames Ada at position 2, and an order is inserted at position 3. Each one is decoded and applied in commit order, and the connector's confirmed position follows along.

@8-9
Then a delete at position 4, which the index applies by primary key. Polling a table would never have seen it.

@10
The first failure mode: the connector crashes after emitting position 4 but before confirming it. On restart it resumes from 3 and emits 4 again. Delivery is at-least-once, so the consumer must apply events idempotently, by key or by log position.

@11
The second: the slot pins the log. If the connector is down for three days, Postgres keeps every segment since the confirmed position, and the primary's disk fills toward 95 percent. Monitor slot lag and cap retention.

@12-13
Why not a dual write? A crash between the two writes loses an update, and two concurrent writers can apply updates in opposite orders. Tailing one log makes the database the single arbiter of order. In the booking system, the seat-map publisher reads seat changes this way and flips one bit per seat in a small bitmap, published every second. So every path that changes a seat, including support tools and the expiry sweeper, reaches the map, with no second write anyone could forget.
