@0
Four nodes hashed onto a circle. The rule: hash each key onto the same circle, and the key belongs to the first node clockwise from it. Compare hash mod N: with 48 nodes, adding a 49th keeps a key in place only about 1 time in 49, so 98 percent of the data moves.

@1
The key cart 9912 hashes to 270 degrees. Walking clockwise, the first node is N3 at 342 degrees, so N3 owns it.

@2-6
The rest follow the same rule. User 42 at 122 degrees walks to N4 at 159. Session 7f at 218 goes to N3. Cart 1180 at 1 degree and prefs 42 at 71 both walk to N4. User 77 at 214 goes to N3. No lookup table and no coordinator: any node, or a token-aware driver, can compute the owner.

@7
Now add N5 at 340 degrees. Only the keys on the arc it takes over change owner: cart 9912, session 7f and user 77, 3 of the 6, because N5 lands just in front of N3. The keys owned by N4 never move. With hash mod N, nearly all of them would.

@8
Look at the ring and you can see the problem with one position per node: four random positions are badly spread, and N1 and N2 own nothing. So real systems give each machine several positions, virtual nodes, and the arcs even out. A dead node's load spreads over many peers, and a replacement streams from many in parallel. But more is not free: with 256 tokens per node, any two failures in different zones leave some keys below quorum. That is why Cassandra 4 lowered its default to 16.
