@0
Six nodes, all holding version 1 of the cluster's view, and no coordinator. The rule of gossip: every round, each node that knows the news tells one random peer. Like a rumour, it reaches everyone in a number of rounds that grows with the logarithm of the cluster size.

@1
N1 learns something new: a membership change, or a peer's heartbeat counter. It has no list of who needs to hear it.

@2-3
Round 1: N1 tells N5, so 2 of 6 know. Round 2: both tell someone, and both happen to pick N4. Now 3 of 6 know.

@4-5
Round 3: three nodes send, N2 learns, and two messages go to nodes that already knew. Those dashed messages are wasted. Round 4: four messages, one new node, N6, and three wasted. 5 of 6 know.

@6-7
Round 5: N5 reaches N3, the last one. Everyone knows after 5 rounds and 15 messages in total, and no node ever sent more than one message per round. Doubling the cluster adds about one round. In the lesson's 48 node cluster, each node gossips with a random peer every second, so news reaches everyone in seconds.

@8
Two flavours. Rumour mongering pushes new updates for a few rounds; it is cheap but can miss a node. Anti-entropy periodically compares full state with a peer, using Merkle trees; it is heavier but guarantees convergence. This store runs both: gossip for membership, Merkle trees for repairing data.

@9
The failure modes. During a partition, each side converges to its own view. A node with a slow link can be declared dead by everyone. And stale news lingers, so a removed node can be re-added by a peer that never heard it left. That is why, in this design, a silent node is only temporarily unavailable: hints accumulate and nothing moves. Removal is an explicit operator action, because a gossip-driven removal would turn a 30 second garbage collection pause into a terabyte of data movement.

@10
The trade-off: no coordinator, no single point of failure, and load spread evenly, at the price of eventual delivery, redundant messages, and membership state on every node.
