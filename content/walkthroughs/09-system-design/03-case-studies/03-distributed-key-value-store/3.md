@0
Three replicas, R1, R2 and R3, all holding x equals version 1. The rule: a write waits for W acknowledgements, a read for R replies, out of N copies. Here N is 3 and both W and R are 2. Two plus two is more than three, so every read set overlaps every write set in at least one replica. Hold onto that overlap; it is the whole guarantee.

@1-2
A client sends a write, x equals version 2, to a coordinator. Any node can coordinate. It sends the write to all three replicas in parallel, with a timestamp.

@3-4
R1 and R2 acknowledge. R3 is slow: a garbage collection pause, a disk stall. Two acknowledgements meet W, so the coordinator replies success without waiting, even though R3 still holds version 1. A quorum tolerates one slow or dead replica on the write path, and that is why quorums cut tail latency.

@5-6
A read arrives. The coordinator asks all three replicas and waits for the first two replies.

@7-8
R3 answers first, with the stale version 1. Then R2 answers with version 2. Because R plus W is more than N, at least one of the two repliers was in the write quorum, so the newest version is guaranteed to be among the replies.

@9-10
The coordinator returns the value with the highest timestamp, version 2. And it noticed R3 was behind, so it writes version 2 back to it: read repair. Every replica now holds version 2. Anti-entropy sweeps fix replicas nobody reads.

@11
Break the rule and the guarantee goes. With W of 1 and R of 1, a read may consult only a replica that missed the write, and the client sees version 1 after version 2 was acknowledged.

@12
There are subtleties. With a sloppy quorum, a substitute node accepts the write while a home replica is down, and the overlap guarantee no longer holds. Two concurrent writes need a tiebreak. And even a strict quorum is not a compare-and-set.

@13
The trade-off: no leader, no election, writes that keep working through partial failures, and consistency you can tune per request. The cost is that every operation sends N messages, and the guarantees are weaker than they look. For this store, which must always be writable, that is the right bet; for balances or inventory, the lesson picks consensus instead.
