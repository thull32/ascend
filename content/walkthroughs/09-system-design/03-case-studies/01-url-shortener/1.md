@0
Three boxes: a mobile app, the links API, and the Postgres database that holds both the links and a table of idempotency keys. Mobile clients retry on timeout, so the Idempotency-Key header is mandatory. Hold onto one rule: the app mints one key per create, k1 here, and sends that same key on every retry. One key produces the effect at most once, however many times the request arrives.

@1
The first delivery: POST to create a link, carrying k1 in the header.

@2
The API claims the key by inserting a row for k1, in progress, with a hash of the request body. The key is the table's primary key, scoped to the owner, so only one insert can ever succeed, and only that delivery goes on to do the work.

@3
The work happens once: the API mints the short key x7Kq. The new link and the key's saved response, 201 with x7Kq, commit in one transaction. If the process died before the commit, neither would exist, and a retry would simply run again.

@4
The reply is sent, and lost. A timeout, a dropped connection, a crashed load balancer. The app cannot tell whether its create worked.

@5
So it retries, with the same key. Without the key, this is how one tap on shorten becomes two links.

@6
The key exists, it is done, and the body hash matches: this is the same request again.

@7
The API replays the saved response byte for byte, and mints nothing. Links: still one. The user gets back the same short link, x7Kq. At-least-once delivery plus an idempotent server gives an exactly-once effect.

@8
One more case: a client bug sends the same key with a different long URL. The stored hash does not match, so the server answers 422 and does nothing. The key names a different request.

@9
The details that bite. Scope keys per caller, which is why the shortener's table is keyed by owner and key, so one client can never replay another's response. Keep keys longer than any client retries; the shortener keeps them for 24 hours, because a retry after the key expires is treated as new and mints a second link. And decide what a failed attempt leaves behind.

@10
The price is one extra write per create and a table of keys to expire, and it removes a whole failure mode: duplicate links seconds apart for the same owner and URL. The key belongs to the operation, not to the attempt; a fresh key per retry would deduplicate nothing.
