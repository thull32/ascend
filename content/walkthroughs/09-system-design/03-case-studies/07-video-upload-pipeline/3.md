@0
A queue, two workers, and a dead-letter queue. Each message is one encode task: one chunk of the video at one rung of the ladder. The producer enqueues and moves on, and workers pull when they have capacity.

@1
A burst of 10 tasks arrives. The broker persists each one and acknowledges at once, so the orchestrator never waits for encoding.

@2-3
Worker 1 receives m1. The broker does not delete it; it hides it for a visibility timeout of 30 seconds while the worker encodes. Worker 2 takes m2. Each task goes to exactly one worker.

@4
Worker 1 finishes and acknowledges, and only now is m1 deleted. In the pipeline, the orchestrator marks a task done only after its output exists.

@5-6
Worker 2 crashes halfway through m2. Encode workers are preemptible, so this is routine. No acknowledgement was sent, so the task is still there, merely invisible. When the timeout expires it reappears, and worker 1 picks it up: attempt 2.

@7
The frame's example is a card charged twice. For an encode, a second run is harmless, by design. Each task is a pure function of the source's hash, the chunk index, the rendition and the encoder version, and its output key is derived from exactly those values. A retry overwrites the same object with the same bytes.

@8
Worker 2 restarts, and the two workers drain the backlog, m3 to m9. Throughput scales with workers, and tasks complete in any order. That is fine here, because the workflow engine turns the fan-in into a counter and packages a rung only when its chunks are in.

@9-11
m10 is a poison message: a file that crashes the decoder every time. The worker fails it, and the broker makes it visible again and counts the attempt. After 3 attempts it goes to the dead-letter queue instead of looping forever. The lesson adds what happens next: the video is marked failed with a reason the creator can act on, such as an unsupported codec, and an engineer can replay it after a fix.

@12
The trade-off: decoupling and elastic workers, at the price of at-least-once delivery, no end-to-end ordering, and a backlog that can grow silently. So the pipeline autoscales each queue on the age of its oldest message, not on CPU, which is always near 100 percent on an encoding fleet. And priority is separate queues, not a field: a priority field does not help when 500,000 backfill tasks are already ahead.
