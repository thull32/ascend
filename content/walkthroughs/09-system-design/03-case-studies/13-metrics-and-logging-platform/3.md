@0
A client, a write-ahead log, an in-memory sorted table called the memtable, which flushes at 4 entries, and two levels of files on disk. This is a log-structured merge tree. Writes go to memory and are flushed as immutable sorted files that are merged later. Every disk write is sequential; the price is that a read may have to look in several places.

@1-2
The client puts a equals 1 and b equals 2. Each put is appended to the log for crash safety and inserted into the memtable, with no disk seek. Then c equals 3, and a equals 4: overwriting a just replaces the value in memory, while the log keeps both records.

@3-4
d equals 5 fills the memtable. It is flushed in one sequential write as SST-1, a sorted, immutable file with a sparse index and a Bloom filter. The log segment can now be dropped, and a fresh memtable takes new writes.

@5
SST-1 is never touched again. b becomes 9 in the new memtable, and deleting c writes a tombstone, a marker that says deleted. The real removal happens later.

@6
Read c. The memtable is checked first and holds the tombstone, so the answer is not found, even though SST-1 still contains c equals 3. The newest level wins.

@7
Read a. It is not in the memtable, SST-1's Bloom filter says maybe, its index points to the block, and one disk read returns 4.

@8
Two more puts, e and f, fill the memtable, and it flushes as SST-2. The two files overlap in key range, both holding b and c, so a read for b must check SST-2 before SST-1. Read cost grows with every flush.

@9-10
Compaction fixes that in the background: a merge sort of the two files into one non-overlapping file at the next level. The newer b equals 9 wins, and the tombstone removes both c and itself, since nothing older remains. Now reading b touches a single file. Compaction pays a write cost now to make every later read cheaper.

@11
The failure modes: compaction competes with foreground disk work and can fall behind, and then writes stall as files pile up; and tombstones must survive until they reach the bottom level, or deleted keys come back.

@12
A time-series store is this same shape, specialised by time. Samples land in memory backed by a log, each flush is a two-hour block in object storage, compaction merges adjacent time ranges into day-long blocks, and retention deletes whole files instead of writing tombstones.
