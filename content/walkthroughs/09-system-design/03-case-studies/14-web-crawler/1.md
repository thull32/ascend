@0
Six pages, A to F, and the arrows are links. A crawler is breadth-first search over a graph it cannot see in advance: a first-in, first-out queue of pages to fetch, and a set of everything already discovered. We start with A in the queue, at distance 0.

@1-3
Fetch A. It links to B and C, both new, so both are marked discovered at distance 1 and join the queue.

@4-5
Fetch B. It links to D, which is new: distance 2, and onto the queue behind C.

@6-7
Fetch C. C links to D as well, but D is already discovered, so nothing happens; only E is new, at distance 2. Without the visited set, D would have been queued twice.

@8-9
Fetch D, which links to F: distance 3.

@10
Fetch E. Its only link points back to A, which was crawled first. The visited set turns that into a no-op too. On the real web this is what stops a crawler from going round in circles forever.

@11-12
Fetch F, and the queue is empty. Every page was fetched once and every link examined once, so the work is proportional to pages plus links, and each label is the page's distance in clicks from the seed. A real frontier is not a plain queue: priority and per-host politeness reorder it, and the visited set has ten billion entries. But the invariant is the same: every URL is discovered once.
