@0
Three hosts: a user typing in English in the US, an edge cache, and a suggest server behind it. The rule: the first request for a prefix in a region misses and goes to a suggest server, and later requests for the same prefix are served by the edge until the time to live runs out.

@1-2
User A types n, e, t, f, and the request for suggestions reaches the nearest edge, which has nothing for netf in English in the US: a miss. The edge forwards it to a suggest server, which walks the trie and returns the top suggestions.

@3-4
The suggest server responds with a Cache-Control header of 300 seconds: short, because a suggestion list must change when a query starts trending. User A gets the answer after about 60 milliseconds, and the edge now holds a copy.

@5-6
User B, in the same region, types the same prefix and is served from the edge in about 10 milliseconds. The suggest servers never see it.

@7
The cache key is the normalised prefix, language and region, and the time to live is 300 seconds, so a hot prefix reaches the suggest servers about once per edge every five minutes. There are only 18,278 prefixes of up to three letters per language, so a small key set carries most of the traffic, and the edge answers about 60 percent of requests. The time to live has a cost too: a 5 minute edge time to live, on top of 6 minutes of origin freshness, makes a trending query take up to 11 minutes to appear, one minute over target. And the kill list cannot wait for a time to live at all: removing a harmful suggestion purges every prefix of it from the edge.
