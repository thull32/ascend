@0
Two document owners that both want document d7, a lock service, and the op log they append to, which holds the document up to version 41. Because an owner can die while holding the document, ownership is a lease that expires after 10 seconds. That expiry is where the trouble starts.

@1-2
Owner A asks for the lease and gets it. It must finish or renew within 10 seconds.

@3-4
Owner B asks too, and is denied while A holds it. So far there is one owner.

@5
Now A stops for 15 seconds: a stop-the-world garbage collection, a page fault, a VM migration. A is not dead, only late, and it cannot tell.

@6
The lease expires. The lock service cannot tell a paused owner from a dead one, and releasing is the only way not to block forever.

@7-8
B acquires the lease and appends version 42. That write is legitimate: B is the owner now.

@9-10
A wakes up. From its point of view nothing happened: it still owns the document and is about to write. With no check at the op log, its own version 42 lands on top of B's. Two owners wrote one version, and the document has diverged. No lease length fixes this, because a pause can always be longer.

@11
The fix is a check the op log can already make. Every append is conditional: append version 42 only if no version 42 exists yet. That condition is a fencing token the log keeps for free.

@12-13
Replay A's late write with the condition. B has already written version 42, so A's condition no longer holds and its append changes nothing. A learns it has lost ownership and steps down, and B's work is safe.

@14
So the lease is only an efficiency measure: it keeps two owners from doing the same work most of the time. Correctness comes from the conditional append, with no second system to keep consistent. The log position is the fencing token.
