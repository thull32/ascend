@0
A CDN edge sits between users and the origin. The first request for an object is served from the origin and cached at the edge; every later request from nearby users is answered in a few milliseconds without the origin hearing about it. Hold onto that, because it is the whole capacity argument: the origin only sees the misses.

@1
User A asks for a video segment. DNS or anycast has already sent them to the nearest point of presence.

@2
The edge does not have it yet. That miss goes all the way to the origin, across the Pacific, at roughly 150 milliseconds of round trip. Distance is physics, and no protocol removes it.

@3-4
The origin responds, and its cache control header tells the edge it may keep the object for a day. User A gets the bytes after about 160 milliseconds.

@5-6
Now user B, in Tokyo, asks for the same segment. It is served from the edge in about 5 milliseconds, and the origin never sees the request.

@7
The frame's last note takes the idea further: some providers place appliances inside internet providers' networks and fill them with the catalogue during quiet hours, so even the first request is local. Now scale it to the photo service in the lesson. At peak, 17,000 image views a second at 200 kilobytes each is about 3.5 gigabytes a second at the edge. With a 95 percent hit ratio, the origin sees only the 5 percent that miss: about 870 requests a second. The origin's size is set by the miss rate, not by the user count. That is also the trap: drop the hit ratio to 70 percent and the misses go from 5 percent to 30, so the origin fleet grows about six times.
