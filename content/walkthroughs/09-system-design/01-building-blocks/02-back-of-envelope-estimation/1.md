@0
A typical read path, as six boxes: a browser, a CDN edge, a load balancer, a stateless API service, Redis, and Postgres. As you watch the request travel, put a cost on every arrow. The one fact to hold onto: the round trip dominates almost every request, and the database is rarely the slowest hop. The geography is.

@1
First, a static file. The nearest CDN edge serves it from its own cache, and the origin is never touched. That is the hop that saves the most, because it removes a long-distance round trip entirely.

@2-3
Now a dynamic request. It lands on the load balancer, where TLS terminates, and the balancer picks a healthy API instance by least connections. The instances are stateless, so any one will do. Inside one availability zone, a round trip costs a tenth of a millisecond to half a millisecond, so budget about half a millisecond for this hop.

@4-5
The service checks the cache first, and misses: the key is not there yet. A Redis lookup costs about the same half millisecond. Redis spends around a microsecond executing it; the rest is the network round trip.

@6-7
So the service falls through to Postgres, and the database answers. The lesson measured a primary-key lookup at 0.13 milliseconds on a warm buffer pool; add a network hop and budget about a millisecond.

@8
The service writes the result into the cache with a time to live, so the next minute of reads for this key never reaches Postgres.

@9
And it responds. Add it up: about half a millisecond, another half, about a millisecond for the miss, plus serialisation. A couple of milliseconds inside the data centre. Now put the client on top: its own round trip is 20 to 200 milliseconds, depending on where it is. Five sequential same-zone calls cost 1 to 2 milliseconds; one call across an ocean costs as much as a hundred of them.

@10
Two questions to ask of this path in any design review: what happens when Redis is down, and what happens when the database is slow. Degrade to the database behind a circuit breaker, and protect it with timeouts and load shedding. And when you budget the path, use each hop's 99th percentile, not its mean: five calls that are each slow 1 percent of the time make about 5 percent of requests slow.
