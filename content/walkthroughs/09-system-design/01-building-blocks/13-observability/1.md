@0
On screen is a typical read path: a browser, a CDN edge for static files, a load balancer, a stateless API service, Redis as a cache, and Postgres behind it. A trace exists to answer one question about a path like this: for one request, where did the time go? Metrics cannot answer it, because they have already thrown away which request was which. So follow one request and notice every hop it makes, because each hop is a place a trace must be carried across or it breaks.

@1
First, a side trip. The browser fetches app dot js, and the nearest CDN edge serves it from its own cache. The origin is never touched, so nothing behind the edge has anything to record.

@2
Now the dynamic request, a GET for the lessons list, reaches the load balancer, where TLS terminates.

@3
The balancer picks a healthy API instance by least connections. The instances are stateless, so any one will do.

@4
The API checks the cache first, the cache-aside pattern, asking Redis for the key lessons v3.

@5
Miss. The key is not there yet.

@6
So the API falls through to Postgres, which costs about 5 milliseconds.

@7
The database answers with 42 rows.

@8
The API puts the result in the cache with a 60 second time to live, so the next minute of reads never touches Postgres.

@9
And it responds. The total is roughly 1 millisecond at the balancer, 1 for the cache miss, 5 at the database, plus serialisation. That breakdown is exactly what a trace hands you: a tree with one span per hop, so a slow request reads as 700 of its 900 milliseconds in one query, not as a vague number on a dashboard. For that, the trace ID has to travel in a header, the W3C traceparent, on every one of these calls, and a hop that drops it cuts the tree in two.

@10
The questions to ask of this path in a design review: what happens when Redis is down, where the answer is to degrade to the database behind a circuit breaker; and what happens when the database is slow, where the answer is timeouts and load shedding. Both are questions a trace answers in seconds, as long as every hop propagated its context.
