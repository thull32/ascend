@0
An app server, Redis, and Postgres. In cache-aside the application owns both stores: it reads the cache first, falls back to the database on a miss, and writes the result back itself. The cache never talks to the database. Postgres holds user 42 at version 1, and the cache holds nothing.

@1-2
The app asks Redis for user 42, and misses. Nothing has been loaded for this key yet: the cache is cold, or the entry expired.

@3-4
So the app falls through to the database, the source of truth, and gets the row back at version 1.

@5
It sets the value in Redis with a time to live of 300 seconds. Only keys that are actually read get cached, so the memory goes to hot data.

@6
The second read is a hit, about half a millisecond, and the database never hears about it. This is the arithmetic the whole lesson rests on: database load is the miss rate times traffic, so going from 95 to 99 percent hits cuts database reads five times.

@7-8
Now a write. The app updates the database to version 2 first, then deletes the cache entry rather than writing version 2 into it. Two writers setting values can interleave and leave the older one cached; two deletes cannot disagree.

@9
The next read misses, reloads version 2 and repopulates. Every write costs one extra miss on the next read.

@10
But delete does not close every hole. Here is the stale-set race. Reader A misses and reads version 1 from the database, then pauses. Writer B updates to version 2 and deletes the key, which is not even there yet. Then A's late set writes version 1 back. The cache now serves the stale value to every reader until the time to live runs out. At 15,000 reads a second, that window will be hit.

@11
Cache-aside is still the default: simple, and resilient, because a cache outage only means more database reads. The time to live bounds how long cache and database can disagree, so choose it from what the product tolerates. To shrink the race itself, use a versioned set that only writes a newer version, or leases, which let the writer's delete cancel the reader's right to set.
