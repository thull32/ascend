@0
Three replicas, R1, R2 and R3, all holding x equals v1 at timestamp 9, and no leader. A write must be acknowledged by W of them, here 2, and a read must consult R of them, also 2. Two plus two is four, which is more than three, and that inequality is the whole idea: every read set overlaps every write set, so a read always reaches at least one replica that took the latest completed write.

@1-2
The client sends a write to a coordinator, and any node can play that role. The coordinator sends x equals v2, timestamp 12, to all three replicas in parallel.

@3
R1 and R2 acknowledge. R3 is slow, a garbage collection pause or a disk stall. Two acknowledgements are all W asks for, so the coordinator does not wait for it.

@4
The client hears OK while R3 still holds v1. The write path tolerated one slow replica without anyone noticing.

@5-6
Now a read arrives. The coordinator asks all three replicas and waits for the first two replies.

@7
R3 answers first, with the stale v1 at timestamp 9.

@8
Then R2 answers with v2 at timestamp 12. This is the overlap at work: two readers out of three must include at least one of the two writers, so the newest version is guaranteed to be among the replies.

@9
The coordinator returns the value with the highest timestamp: v2.

@10
And because it noticed R3 was behind, it writes v2 back to R3. That is read repair. Replicas nobody reads are fixed by background anti-entropy sweeps instead.

@11
The failure mode. Tune for speed with W plus R at or below N, say one and one, and a read may consult only replicas that missed the write, so the client sees v1 after v2 was acknowledged. Tune per workload instead: write to all and read from one for read-heavy data, write to one only for data you can afford to lose.

@12
Now the subtleties. Sloppy quorums, where non-home nodes accept writes during a partition, break the overlap. Concurrent writes with equal timestamps need a tiebreak. And even a strict quorum is not linearizable. Overlap guarantees a read sees the last completed write, not one still in flight: while a write has reached only one replica, one reader can find the new value there and a later reader can miss it on the other two. The lesson's fix is a write-back phase before the read returns, at the cost of a second round trip.

@13
The trade-off: no leader, no election, availability through partial failures, and consistency you can tune per request. In exchange, every operation costs messages to all N replicas, and the guarantees are weaker than they look. This is the design of Dynamo, Cassandra, Riak and Voldemort.
