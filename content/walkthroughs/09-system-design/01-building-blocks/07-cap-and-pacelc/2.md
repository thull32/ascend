@0
Two regions, each with its own leader, a user in each, and one document whose title is at version 1. Each leader accepts writes locally and ships them to the other asynchronously. Users get local write latency; watch for the price.

@1-2
The EU user sets the title to Draft A. The EU leader applies it on top of version 1 and acknowledges in about 2 milliseconds: no round trip across the ocean, and the write survives even if the link to the US is down.

@3-4
At the same moment the US user sets the same title to Draft B. The US leader also applies it on top of version 1, because it has not heard of Draft A, and also acknowledges locally. Two different version 2s now exist.

@5-6
The replication streams cross in flight. Each leader receives a write whose parent, version 1, it has already overwritten. That is a write conflict, and there is no first write, because there was never a shared order.

@7
Both sides detect the conflict. A single leader never faces this, because it serialises writes. Multi-leader systems must resolve it the same way everywhere so that all leaders converge.

@8
Resolution one, last-writer-wins: keep the write with the higher timestamp everywhere. Both leaders now say Draft B. It converges, but Draft A was silently thrown away, a lost update, and clock skew decides who loses. That is exactly how the lesson's Cassandra user chose blue a minute later and ended up with dark.

@9
The alternatives: merge the values, with a CRDT or a text merge; keep both as siblings and let the application or the user resolve them, as Riak and Dynamo's shopping cart do; or give each record a home leader, so a given key never has two writers.

@10
With more than two leaders, topology matters too. All-to-all is fastest but can deliver writes out of causal order, a reply before its question. A star or a ring adds hops but keeps ordering simpler.

@11
The trade-off: local write latency and tolerance of inter-region outages, paid for with conflict handling, no linearizability, and subtle bugs around auto-increment keys and uniqueness. It is the honest AP design, as long as you name the merge rule. Choosing AP without one is the gap interviewers look for.
