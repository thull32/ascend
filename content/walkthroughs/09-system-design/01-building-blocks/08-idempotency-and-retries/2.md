@0
A consumer receiving millions of event IDs a second cannot afford an exact lookup for every one. A Bloom filter sits in front of the exact dedupe store: a bit array and three hash functions. It can answer definitely not seen, or probably seen, but never definitely seen. Hold onto that asymmetry; it decides when the exact lookup can be skipped.

@1-4
Four event IDs are added. Each is hashed three times and those bits are set. Event 1 sets bits 14, 13 and 12. Event 2 sets 11, 4 and 5. Event 3 sets 8, 7 and 2. Event 9 sets 6, 5 and 4, two of which were already on. Bits only ever turn on; the array never shrinks.

@5-6
Event 1 arrives again. Check bits 14, 13 and 12: all three are 1, so the answer is probably present. A key that was added can never be missed: there are no false negatives.

@7
Probably is not good enough to drop a message, so only now does the consumer pay for the exact lookup in the dedupe store, and it finds the ID. A genuine duplicate, skipped.

@8-9
Event 101, never seen before, hashes to bits 1, 2 and 15. Bit 1 is 0, so event 101 was definitely never added. The exact lookup is skipped entirely and the message is processed. This is the win: most new IDs cost no lookup at all.

@10-11
Event 100, also never added, hashes to bits 14, 5 and 12. Other keys happen to have set all three, so the filter says probably present: a false positive. The exact store is checked and has nothing, so the message is processed after all. Harmless for correctness; it only costs a lookup, and it is the rate you tune. About 10 bits per ID buys a 1 percent false positive rate.

@12
The failure modes. You cannot delete: clearing a bit might erase another key's evidence and create a false negative, so churn needs counting filters or periodic rebuilds. And the false positive rate climbs as the filter fills, so size it for the final key count.

@13
The trade-off: a few bits per key buys definitely not here for the great majority of new IDs, at the cost of a tunable false positive rate and no deletes. The filter is only a pre-check; correctness still comes from the exact store behind it, and that store's window must outlast the longest redelivery.
